# const fn 逻辑运算符与短路求值（v1.1160）

## 问题：三个叠加的缺陷

### 1. `&&` / `||` 根本没有实现

`cfn_expr` 只有两层：`cfn_term`（`* / %`）+ 加减 while + **一个**比较。
`&&` / `||` 不在任何一层里，遇到就停——左边的比较结果直接成为整个条件的值，
右边整段被丢弃：

```mo
const fn f(a: i64, b: i64) -> i64 {
    if a > 0 && b > 0 { return 1; }
    return 0;
}
```

`f(1, 0)` 返回 1（只看了 `a > 0`），`f(20)` 配 `a > 0 && a < 10` 也返回 1。
表达式本身合法、编译通过、结果错。

### 2. 比较的右值递归吞掉后面的逻辑符

```mo
if a == 0 || b == 0 { return 0; }
```

比较层求右值时调的是 `cfn_expr(0)` —— 整个表达式层。于是 `a == (0 || b) == 0`：
`||` 被右侧吞进比较的右值里，`b == 0` 又变成一个独立的比较。
`pick(7, 8)` 本应返回 15，实际返回 0（走了「任一为零」的分支）。

### 3. 没有短路就必然炸除零

```mo
if b != 0 && a / b > 1 { ... }
```

如果两侧都求值，`b == 0` 时 `a / b` 在**编译期**执行除法 —— 折叠器直接除零。

## 方案：四层拆分 + 跳过模式

| 层 | 负责 | 说明 |
|---|---|---|
| `cfn_arith` | `* / %`、`+ -` | 纯算术，不含比较 |
| `cfn_cmp` | `== != < <= > >=` | 右值改为 `cfn_arith`，不再递归整层 |
| `cfn_and` | `&&` | 比 `\|\|` 紧 |
| `cfn_expr` | `\|\|` | 最松 |

**右值改 `cfn_arith` 是第 2 个缺陷的根治点**：比较不再有能力吞掉逻辑运算符。

**短路用全局 `CFSK`（跳过模式）实现**，而不是「都算完再合并」：

```mo
let v: i64 = cfn_cmp(depth);
while tok_is("&&") == 1 {
    next_token();
    let old: i64 = CFSK;
    let lz: i64 = 0;
    if v == 0 { CFSK = 1; lz = 1; }     # 左值假 → 右值只吃 token
    let r: i64 = cfn_cmp(depth);
    CFSK = old;
    if lz == 1 { v = 0; } else { if r != 0 { v = 1; } else { v = 0; } }
}
```

`CFSK == 1` 时代码仍然照常**解析**右值（token 必须照样消费，否则位置错乱），
但求值路径降级：

- `cfn_term` 的 `/` `%`：不真做除法，结果直接置 0（除数可能是 0）；
- `cfn_atom` 的 const fn 调用：不执行 `cfn_eval`，返回 0（省递归，也避免被调函数内部的除零）。

`CFSK` 在每层 `&&` / `||` 处理前后**保存/恢复**，嵌套短路不会互相污染
——同 v1.1158/v1.1159 的 `CFDONE` / `CFARGD` / `CFBRK` 一样，任何跨层共享的全局状态
都必须在进入子求值前存、返回后恢复。

## 验证

`tests/339_constfn_logic.mo`（expect **168**），10 个场景，期望值全部由 Python 模型独立算出：

| 场景 | 值 | 覆盖点 |
|---|---|---|
| `inr(5,1,10)` | 1 | `&&` 双侧为真 |
| `ez(7,8)` | 0 | `\|\|` 双侧为假（缺陷 2 的回归点） |
| `po(3,4)` | 12 | `&&` 通过后进入分支体 |
| `sd(10,0)` | 255 | 短路使 `a / b` 不被求值，不除零 |
| `tri(0,0,5)` | 1 | `&&` 比 `\|\|` 结合紧 |
| `sgn2(-2,-3)` | 1 | 括号内两组 `&&` 用 `\|\|` 连接 |
| `wh(100)` | 10 | `while` 条件里用 `&&` |
| `cn(20)` | 3 | 循环体内 `i%2==0 && i%3==0` |
| `sl(0,5)` | 0 | `\|\|` 左真短路，不再看 `a > b` |
| `np(12)` | 3 | 质因数分解：`continue` + 复合赋值 + 循环 |

加权威重 1..10，总和 168（含 `sd` 的 -1 = 255 语义），`168 % 256 = 168`（main 返回值取 mod 256）。

回归：338=127、337=136、336=142、335=98；自举 md5 一致；门禁全绿。

## 踩坑记录

- **`!` 一元逻辑非仍未支持**：`if !(x == 0)` 在 const fn 里直接报语法错（主编译器的
  表达式层也不认 `!`）。这是下一步的候选，不是本次静默错误。
- **探测要挑「左右不同」的样例**：`a > 0 && b > 0` 用 `(1,1)` 测永远是 1，
  用 `(1,0)` 才能暴露右侧被丢弃；`a == 0 || b == 0` 用 `(7,0)` 也是 1，
  必须用 `(7,8)` 才能看到缺陷 2。
