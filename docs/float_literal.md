# 浮点字面量

墨语言的 f64 字面量由编译器直接解析成 IEEE754 位模式，不经过 libc 的
`strtod`。这么做的好处是精度可断言，代价是要自己把舍入做对。

## 实现契约

| 条件 | 保证 |
|---|---|
| 有效数字 ≤ 17 位 且 小数点后总位数 ≤ 26 位 | 与正确舍入值**逐位相等**（0 ulp） |
| 整数部分 | 不受影响，19 位 i64 字面量照常解析 |
| 量级 < 1e-26 | 返回 0.0（已知限制，见下） |

判据是 `fbits()` 取位模式比整数，**不是打印出来看**。打印只显示 6 位小数，
`0.69314718` 与 `0.693147180559945` 打出来一模一样，实际差 5,043,536 ulp。

## 🔴 历史 bug 一：只取 8 位小数（v1.115 之前）

```mo
0.693147180559945   →   0.69314718      差 5,043,536 ulp
0.301029995663981   →   0.30102999      差 102,033,210 ulp
π = 3.141592653589793 → 3.14159265      差  ~1.2e8 ulp
```

**不报错、不崩溃，只是静默给一个看起来合理的数。** 这正是它藏得住的原因：
打印出来完全正常，只有拿去做数学运算时才悄悄跑偏。

根因是小数位预算写死成 8。现在按**有效数字**给预算：

```mo
let sig: i64 = 18 - idn;       # 整数部分占掉的位数要扣掉
let kmax: i64 = sig;           # v != 0
if v == 0 { kmax = 26; }       # 纯小数量级可到 1e-26
```

超出预算的位不直接丢掉，而是置 `FSTICKY` 参与舍入。

### 修的时候自己引入过一个更严重的

给**整数部分**也加了 18 位上限，于是 `9223372036854775807`（19 位）被读成
`922337203685477580`。而 `0 - 9223372036854775807 - 1` 正是墨语言写
`i64::MIN` 的惯用法 —— 这会让全语言的 MIN 写法失效。

是自举校验立刻报"两套编译器产物不一致"才抓到的：汇编 seed 是另一套词法实现，
没跟着截。所以 `tests/127` 里钉了一条专门盯它的断言：

```mo
assert_eq("整数不受影响", to_i(9223372036854775807 > 9223372036854775806), 1);
```

两个 19 位整数若被截成 18 位就相等了，这条断言就会红。

## 🔴 历史 bug 二：十六进制字面量被前一个浮点记号污染

编译器在解析 `0x...` 时提前返回，没有清掉上一个记号留下的浮点状态。于是
**紧跟在小数后面的十六进制数会被当成小数解析，且沿用上一个数的数字**。

```mo
let a: i64 = fbits(0.5);
let b: i64 = 0x1234;     # 真值 4660
# 修复前：b == a（4602678819172646912）
# 修复后：b == 4660
```

最阴的地方在于测试里常用的写法恰好**看不出来**：

```mo
assert_eq("0.5 bits", fbits(0.5), 0x3fe0000000000000);
```

`0.5` 的位模式真值就是 `0x3fe0000000000000`，污染后两边仍然相等 ——
**判断恒真，什么都没验**。要暴露它必须用值与前面小数不同的十六进制常量。
本轮用 `0x1234` 做了最小验证。

这个缺陷不限于测试：任何"先用小数、再用十六进制常量"的程序都会中招。

## 三层验证

| 层 | 工具 | 内容 |
|---|---|---|
| 手挑 | `tests/127_float_literal.mo` | 20 个常量（π / e / ln2 / log10(2) / 光速…）逐位比对 |
| 随机 | `tools/floattest.sh` | 340 个随机字面量，与 Python `struct` **逐位**比对 |
| 变异 | `tools/floatlitmut.sh` | 把预算改回 8，两层都必须报红 |

为什么必须有随机层：手挑的样本只能证明"这几个对"，而精度 bug 的特征是
"大部分对、个别差得很远"。Python 是**独立实现**（它自己有正确的 `strtod`），
两边一致才说明真的对。

变异验证实测（`make floatlitmut` 同款）：

```
== 基线 ==    tests/127 通过      floattest 总数 340 不一致 0
== 变异 ==    tests/127 退出码 8  floattest 退出码 1（84 处不一致）
✓ 两层均被捕获
```

只看"全过"证明不了断言非空转 —— 必须有变异层。

## 已知限制

- **量级 < 1e-26 返回 0.0**：实现用 `N / 10^k`，需要 `2*5^k < 2^63`，
  即 `5^26 = 1.49e18` 可以、`5^27 = 7.45e18` 溢出。这条已被
  `tests/127` **显式钉住**（断言 `1e-27 → 0`），不是"碰巧通过"。
- 有效数字超过 17 位时不保证 0 ulp（超出 double 可表示的精度）。
- 尚未支持科学计数法（`1e-9`）、十六进制浮点（`0x1p-3`）。
