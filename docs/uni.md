# uni —— Unicode 字符分类与大小写转换

## 概念来源

- **通用类别**：Unicode Annex #44，把每个码点归入 Lu / Ll / Lt / Lm / Lo /
  Mn / Mc / Me / Nd / Nl / No / Pc / Pd / Ps / Pe / Pi / Pf / Po / Sm / Sc /
  Sk / So / Zs / Zl / Zp / Cc / Cf / Cs / Co / Cn 三十个细类。
- **大小写映射**：UnicodeData.txt 的 `Simple_Uppercase` / `Simple_Lowercase`；
  SpecialCasing.txt 里还有一批「一个码点变成多个码点」的映射（ß→SS、
  İ→i̇），本表无法用单个 delta 表示，所以**显式标记**而不是静默给个近似的。

为什么算「概念」而不是「工程惯例」：C/C++ 的 `<ctype.h>` 只有 ASCII 且受
locale 支配；Java / Go / Rust / Python 有字符分类，但都依赖运行时自带的完整
Unicode 表且**不可裁剪**；没有任何主流语言把它做成可嵌入的纯数据表。本实现
是**区间表 + 二分查找**，数据由 `tools/genuni2.py` 从 Python 的 `unicodedata`
导出，覆盖哪些段是可以改的。

## 数据结构：一个区间打包进一个 i64

```
bit 0..15   lo      区间下界
bit 16..31  hi      区间上界
bit 32..39  kind    类别表：粗类别 0..22
                    大小写表：0 无映射 / 1 delta 可用 / 2 特殊多字符
bit 40..63  delta   映射增量，存 delta + 8384（避开负数字面量）
```

一个区间一个 i64，三张表共 **1391** 项，查询 O(log n)。

之所以打包而不是开三个数组：墨语言没有数组字面量初始化，只能逐项赋值，
打包把赋值条数压到原来的 1/3（`var` 初始值只接受非负整数字面量，这点在
`utf8.mo` 里已经踩过一次）。

## 覆盖范围（诚实标注，不假装全 Unicode）

| 段 | 内容 |
|---|---|
| U+0000..U+04FF | Latin-1 / Latin Ext-A,B / IPA / Greek / Cyrillic |
| U+2000..U+22FF | 通用标点、上标下标、货币、字母符号、数字形式、箭头、数学运算符 |
| U+25A0..U+25FF | 几何图形 |
| U+3000..U+303F | CJK 标点 |
| U+4E00..U+9FFF | CJK 统一汉字 |
| U+FF00..U+FFEF | 全角 / 半角形式 |

共 **23440** 个码点。之外的码点一律返回「未覆盖」：`uni_cat` 返回 -1 并置
`UNI_UNK`，`uni_upper` / `uni_lower` 同样返回 -1。**不会**静默给出一个像样的
答案 —— 这是本库最重要的一条约定。

表由 Python 3.10 的 `unicodedata`（Unicode 13.0.0）导出。换 Unicode 版本
需要重跑生成器，期望值由 `tools/uniref.py` 现算，不落在仓库里，因此不会
出现「期望文件陈旧但仍全绿」。

## 实测

- 覆盖段内 23440 个码点全部命中（无缝隙、无重叠、无错位）
- 粗类别计数逐项精确：Lu 461 / Ll 547 / Lo 21110 / Nd 20 / Sm 330 /
  Zs 18 / Cc 65 / Cn 69 / Mn-Mc-Me 158 / Nl-No 92 / Pc 5
- **与 Python 的 `unicodedata` 逐码点全量比对一致**（`make unitest`）。
  比对用的 `tools/unidump.mo` 把覆盖段内每个码点的分类与大小写全部打印
  出来，`tools/uniref.py` 用 `unicodedata` 独立算期望后逐行比对 —— 期望
  现算，不落仓库，所以换 Unicode 版本不会「期望陈旧但仍全绿」
- 特殊多字符映射 6 个：U+00DF ß、U+0130 İ、U+0149 ŉ、U+01F0 ǰ、
  U+0390 ΐ、U+03B0 ΰ

### 一条被实测钉住的「反直觉」性质

**简单大小写映射不是对合**。覆盖段内：

- `lower(upper(c)) == lower(c)` 有 **12 个反例**
  （U+00B5 µ、U+0131 ı、U+017F ſ、U+0345、U+03C2 ς、U+03D0…）
- `upper(lower(c)) == upper(c)` 有 **4 个反例**
  （U+03F4 ϴ、U+2126 Ω、U+212A K、U+212B Å）

典型例子：U+03C2 ς 的大写是 Σ，而 Σ 的小写是 σ **不是** ς。这是 Unicode 的
真实性质，不是实现缺陷 —— 所以测试断言的是反例的**精确个数**，而不是「应该
为 0」。这一条同时是很好的哨兵：区间表或 delta 表错位，这个数字立刻变。

## 🔴 两个真缺陷

### 一、二分右边界写成开区间 → 区间末端码点**死循环**

```mo
if cp < h { return v; }      # 应为 cp <= h
```

`cp == h` 时既不走 `lo = mid + 1` 也不 return，`lo` / `hi` 都不变，循环条件
`lo <= hi` 永远为真。

- 症状不是「值错了」，是**程序挂住**，而且只在**区间末端**触发
- 抽查 ASCII 中间值（`'A'` = 65）永远碰不到
- 单码点区间（如 U+0020 空格，`lo == hi == 32`）**必然**触发

修法之外还补了一组末端断言（Cc 区间末端 U+001F、单点区间 U+0020、
Cc 末端 U+007F、第一段末端 U+04FF、CJK 段末端 U+9FFF、末段末端 U+FFEF），
每组末端单独钉死 —— 否则改坏之后要碰运气才复现。

### 二、变异脚本的「自愈」方向写反，把正确源码变成变异态

`tools/unimut.sh` 开工时会做一次自愈（防止上一轮被强杀后源码停在变异态）。
第一版把 pairs 写成了「干净 → 变异」：

```python
('if cp <= h { return v; }', 'if cp < h { return v; }'),
```

于是**自愈本身**把正确的 `cp <= h` 改成了变异态 `cp < h`，源码被污染，
后续每一次运行都从污染态开始。

这属于已记录过的「验证机制自身的静默失效」，新变体是：**修复动作本身的
方向写反**。修法是让 pairs 恒为「变异文本 → 干净文本」，并在收尾用
`cmp` 逐字节校验还原。

## 变异验证（`make unimut`）

| 变异 | 结果 |
|---|---|
| M1 类别掩码收窄（`& 255` → `& 15`） | 14 项变红 |
| M2 delta 偏移差一（8384 → 8383） | 9 项变红 |
| M3 不置 `UNI_UNK` | 3 项变红 |
| M4 右边界开区间 | 程序挂住，timeout 生效 |
| M5 不置 `UNI_SPEC` | 2 项变红 |

M4 若没有 timeout 会拖住整个脚本，所以 `run_test` 一律套 `timeout 10`。

## 已知限制

- 只覆盖上表六段；**emoji（U+1F600 等）完全不在表内**，返回 -1
- 不做大小写无关比较（case folding）、不做 NFC/NFD 归一化、不做字素簇切分
- 特殊多字符映射（6 个）只置 `UNI_SPEC` 并返回原码点，不展开成多字符
- `uni_title` 按 Default Case Conversion 实现：Lt 类码点保持自身，其余取
  uppercase；SpecialCasing 里的特殊 title 映射不适用
- 查询是 O(log n) 二分，热路径应自己做一层 ASCII 快表
- 表在 `uni_init()` 里逐项赋值装载，程序启动必须先调一次
