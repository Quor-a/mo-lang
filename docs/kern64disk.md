# kern64disk —— ARM64 裸机上的持久存储（virtio-blk + 跨次启动的文件系统）

版本 1.164.0

```bash
bash tools/kernel64.sh examples/kern64disk.mo /tmp/modisk64.elf
python3 tools/kern64run.py /tmp/modisk64.elf --disk /tmp/disk.img     # 第一次
python3 tools/kern64run.py /tmp/modisk64.elf --disk /tmp/disk.img     # 第二次，同一镜像

bash tools/kern64disktest.sh     # 21 项端到端断言（判据是"重启后还在"）
bash tools/kern64diskmut.sh      # 4 个变异验证
```

## 为什么需要它

`examples/kern64sys.mo`（v1.163）有 RAMFS、shell、包管理，但**掉电即失**：
一个只能活在内存里的系统，连自己刚装进去的包都留不住。

这一份补的是"**重启之后还在不在**"。判据不是"写成功"，而是
**两次独立启动之间数据仍在** —— 磁盘镜像是一个真文件，
两次运行之间它没有被重置，第二次启动必须读到第一次写的内容。

| | 第一次（空盘） | 第二次（同一镜像） |
|---|---|---|
| 输出 | `mount: no superblock -> format`<br>`format: writes=3`<br>`wrote hi -> MO-DISK-OK` | `mount: nfiles=1`<br>`read hi -> MO-DISK-OK`<br>`len=10 sum=699 match=1` |
| 落盘 | `writes=3` | `writes=0`（没有多余写） |

## 驱动是真规范，不是私有协议

按 virtio 1.0 的 MMIO 传输层实现：magic `'virt'`(0x74726976) /
version 2 / device id 2 / 描述符链 + avail / used 环 / `QueueNotify`。
模拟器（`tools/kern64run.py --disk`）实现的是**规范里的那一侧**：
寄存器布局、描述符链遍历、环语义都照规范来，backing store 是一个真文件。
所以这不是"驱动和模拟器约好的私有协议"，换到真 QEMU virt 上应当同样工作。

扇区布局（512 B/扇区）：

```
0        超级块："MOFS1" + 文件数
1        文件表：8 × 32 B（名字 16 + 长度 8 + 数据扇区 8）
16..     数据区
```

## 🔴 三个真缺陷（都不报错）

### 一、写后立即读回，用的是同一个缓冲

格式化路径里 `put_body(&SECBUF)` → `wrsec(16)` → `rdsec(16)`。
中间**没有清缓冲**，于是即使读盘完全没生效，缓冲里还留着刚写进去的内容，
"写后立即读回"照样通过。

这正是本项目第三例"**样本充分 ≠ 覆盖充分**"（前两例：SAM v1.141 的
`SA_NCL=0`、CMS v1.144 的 w=200 让碰撞从未发生）。修法是读之前 `clear_buf()`。

### 二、模拟器同步完成请求，"必须等 used 环"永远测不出来

第一版在 `QueueNotify` 的写钩子里**当场**把请求做完。于是驱动就算不等
used 环、直接返回，拿到的数据也是对的 —— 那条约束根本无法被验证。

改成：通知只登记待办，完成推迟到驱动第一次读 used 环时。
这更接近真设备（请求在通知之后才完成），也让"不等就返回"立刻读到残留。

> 期间还踩到一个：想在回调里 `hook_add` 一个只覆盖 used 环的钩子，
> 实测 `mc=0` —— **在回调里加钩子不会生效**。改为启动时挂整片 RAM，
> 回调里先做地址过滤。

### 三、模拟器不检查描述符的 WRITE 标志

真设备只往"设备可写"的缓冲里写。不建模这一点，方向位写错的驱动
照样能读到数据。现已强制：读请求的数据缓冲没标 WRITE ⇒ 一个字节都不写。

## 变异验证：4 / 4 被捕获

| 变异 | 红 | 说明 |
|---|---|---|
| M1 不认 magic | 12 | 有盘也当没盘，挂载路径整体消失 |
| M2 描述符方向位恒为 1 | 10 | 设备不写回数据，读到残留 |
| M3 不等 used 环 | 10 | 请求未完成就返回 |
| M4 超级块写错扇区 | 4 | 第二次启动挂不上，只能重新格式化 |

另有一条**判据必须带前导空格**的教训：变异脚本早先写
`grep -q "0 失败"`，而 `11 通过 / 10 失败` 里同样含 `0 失败` ——
于是四个变异明明都被抓到，脚本却全报"未被捕获"。改成 `grep -q " 0 失败"`。

## 顺带修的编译器/转译器问题

`let p: i64 = &arr;` 在 C 系后端（c / cfs / kern）原本是**硬错误**：
用 `unsigned char*` 初始化 `long long` 属指针→整数转换。
而"这块缓冲在哪"恰恰只能靠取地址表达（virtio 描述符要填缓冲地址）。
已在 `tools/mo2x.mo` 的 `emit_local` 里补显式转换 `(long long)`。

## 已知限制

- 只实现 virtio 规范子集：无 feature 协商、无中断（轮询 used 环）、单队列
- 容量 2048 扇区（1 MiB），超出返回 status=1
- 文件系统最多 8 个文件、每文件 ≤512 B，扇区号固定（16 起）
- 没有校验和与日志：**掉电窗口内的写会留下半截数据**
- 只在 CPU 模拟器里跑过，**未经真实硬件**
