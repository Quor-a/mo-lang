# qdigest —— Q-digest 分位数草图

`lib/qdigest.mo` · `tests/149_qdigest.mo` · `tools/qdigestmut.sh`

## 概念来源

Nisheeth Shrivastava, Chiranjeeb Buragohain, Divyakant Agrawal, Subhash Suri
2004，《Medians and Beyond: New Aggregation Techniques for Sensor Networks》。

结构：在值域 `[1, σ]` 上建一棵**二分区间树**（dyadic tree）。每个节点代表
形如 `[j·L+1, (j+1)·L]` 的区间，`L` 是 2 的幂。

| 操作 | 做法 |
|---|---|
| 插入 v | 给对应**叶子** `σ + v − 1` 的计数 +1 |
| 压缩 k | 自底向上：若 `cnt(节点) + cnt(左) + cnt(右) ≤ k`，把孩子并进父节点 |
| 查询 φ | 非空节点按**右端点**升序累加，第一次达到目标秩时返回该右端点 |
| 合并 | **逐节点相加** |

## 为什么算"概念"

它与既有的三个草图构成"流数据摘要"四件套，而**四个都没进任何主流语言的标准库**：

| | 回答什么 | 主流实现 |
|---|---|---|
| Bloom (v1.144) | 在不在 | datasketch / stream-lib（第三方） |
| CMS (v1.144) | 出现几次 | 同上 |
| HLL (v1.138) | 有几个不同的 | 同上 |
| **qdigest** | **排第 q 的是几** | 同上 |

## 一条必须先讲清的性质：保证的是**秩**，不是**值**

实测（N=4000，k=80）：

```
φ=0     → 返回 808，真实最小值 800
φ=1000  → 返回 4096，真实最大值 3599
```

值差得很远，但两者的**秩误差**都很小（分别 2 和 4）。原因是压缩后
最小值/最大值会被抬到所属区间的右端点。所以 `tests/149` 对端点只断言
「**不小于真值**」，精确性交给秩误差扫描。

## 🔴 实测推翻了"误差 ≤ k"的常见叙述

同一条流（双峰：60% 聚在 1000±200，40% 聚在 2000…3600），N=4000，
φ 步长 50‰ 共 21 个分位点：

| k | 压缩后节点数 | 最大秩误差 | 误差 / k |
|---|---|---|---|
| 20 | 303 | 69 | 3.45 |
| 40 | 156 | 65 | 1.62 |
| 80 | 82 | 158 | 1.97 |
| 160 | 41 | 384 | 2.40 |
| 320 | 21 | 380 | 1.19 |

误差与 k **同阶**，常数约 2（1.2k ~ 3.5k）—— **不是 ≤ k**。

分解后看，超标的是 `lo − r` 方向（答案偏高）：按右端点累加时，
**祖先节点里落在答案左边的质量没有被算进累计值**，
于是"累计值刚够 r"所对应的右端点，实际左边已经多出一份祖先质量。

这是**如实记录的限制，不是悄悄放宽判据**。`tests/149` 因此同时断言
`maxerr >= k/2`：误差必须是"真的存在、且量级与 k 对得上"的，
否则把上界放大到 4k 就成了一句空话。

## 判据设计

`tests/149_qdigest.mo`，21 项：

**① 确定性**——`qd_total == N`。压缩只是把计数从孩子搬上父节点，
一个都不能丢。这是结构保证，写成 `==` 不写"接近"。

**② 未压缩 = 精确直方图 ⇒ 21 个分位数必须逐位相等。**
这条最强：它证明查询机制本身是对的，后面所有误差只可能来自压缩那一步。

**③ 结构**——压缩后节点数严格减少、且 ≤ 600（理论量级 `O((1/ε)·log σ)`）。

**④ 非空转守卫**——
- `ndiff > 0`：确有 φ 的答案与精确值不同（否则草图退化成精确直方图，
  "误差 ≤ 4k"平凡成立）
- `maxerr >= k/2`：误差量级与 k 相当

**⑤ 合并**——逐节点相加 ⇒ 线性 ⇒ 可交换（实测 `merge(a,b)` 与
`merge(b,a)` 逐节点逐位相同）。这与 CMS 的 Conservative Update 正好相反：
CU 不线性，所以不能分布式聚合；q-digest 可以。

## 变异验证（`make qdigestmut`）

5 个全部被捕获：

| 变异 | 缺陷 | 红 |
|---|---|---|
| M1 只清零孩子、不把计数加到父节点 | 质量凭空消失 | 3 |
| M2 加到父节点但不清零孩子 | 同一份质量数两次 | 6 |
| M3 查询判据 `>=` 改 `>` | 差一 | 1 |
| M4 压缩改自顶向下 | 只有最上面几层生效 | 2 |
| M5 合并改逐节点取 max | 总量不再是 Na+Nb | 1 |

M4 的值得单独记：压缩**必须自底向上**（`i` 从 `σ−1` 递减到 1），
自顶向下时父节点先并完、孩子已清零 ⇒ 非空节点数几乎不下降。
不报错、不崩溃，只是"压缩看起来没用"——靠 `qd_size` 的上界断言才抓得到。

## 已知限制（都没静默）

- 值域固定 `[1, 4096]`；超出返回 −1 并置 `QDBAD`，**不静默截断**
- 秩误差常数约 2k（见上表），不是常见叙述的 k
- 保证的是秩误差，端点的值可能差很远
- 未提供删除（流摘要语义下删除本来就不成立）
- `qd_merge` 每次新建一个 sketch；池 50000 字，最多 6 个
- 未做 `qd_split`（max/相加的逆运算不存在，只能按计数分摊）
