# timer.mo —— 分层时间轮 + select 超时

## 概念来源

Varghese & Lauck, *Hashed and Hierarchical Timing Wheels*,
IEEE/ACM Trans. Networking 5(6):824-834, 1987。

至今的形态分布：

| 载体 | 结构 |
|---|---|
| Linux 内核（低分辨率定时器，hrtimer 之前） | 时间轮 |
| Netty `HashedWheelTimer`、Kafka Purgatory、Akka | 时间轮 |
| tokio（Rust） | 分层时间轮，6 级 |
| **Go** | **四叉最小堆**（runtime，Go 1.10 起），不是轮 |
| libuv | 二叉堆 |

## 为什么是"轮"而不是"堆"

| 结构 | 插入 | 代价 |
|---|---|---|
| 排序数组 | O(n) | — |
| 四叉堆（Go） | O(log n) | — |
| 时间轮 | **O(1)** | **量化误差**：精度 = tick |

误差是有界且可测的，所以本库把它量成数字，而不是含糊地说"大约"。

> 注：这里的 O(1) 是**结构性**的 —— 插入就是"算级、算槽、改两个指针"，
> 固定几条指令。本项目没有对它做经验性对照测量（在 mo 里单次插入太短，
> 测不出来），如实记为未测量。

## 结构

```
L0：64 槽 × tick ms        （跨度 64·tick = 1024ms）
L1：64 槽 × (64·tick) ms   （跨度 4096·tick = 65536ms）
```

L0 转满一圈时，把 L1 的**下一个槽**级联下放到 L0。

## select 的超时不需要新语法

```mo
sel_reset();
sel_case(JOBS, 1, 0);
sel_case(tm_after(500), 1, 0);
k = sel_go(0);            # k==1 即超时
```

与 Go 的 `case <-time.After(d)` 同形：超时不是 select 的特例，而是一个
普通的 channel。

**cap=1 是必须的**：定时器线程在 select 尚未注册时就可能触发，值必须能
留在缓冲里等它来拿。cap=0 时 `chan_trysend` 找不到等待者会直接返回 0，
超时就**永久丢失** —— 而 select 还在那儿等着，看起来就是"定时器坏了"。

## 🔴 关键陷阱：时间轮量化的是"上一个 tick"，不是 arm 时刻

朴素实现里 `exp = nowt + ceil(ms/tick)`，于是触发时刻 = `tick(nowt) +
ceil(ms/tick)*tick`。而 arm 发生在 `tick(nowt)` **之后** frac 毫秒
（`frac ∈ [0, tick)`），所以实际延迟 = `ceil(ms/tick)*tick - frac`
—— **可以比 ms 小最多一个 tick。**

实测就是这么撞上的：某次跑出来 `aim=1200 → 1199`，4 次里挂 2 次。
第一反应会以为是抖动、把断言放宽 —— 但**模型本身就是错的**，放宽等于把
缺陷固化成"正确特征"。

修法是**补偿相位零点**：`ticks = ceil((ms + frac) / tick)`，其中
`frac = now - TM_LASTMS`（上一个 tick 的名义时刻）。补偿后保证：

```
触发时刻 ∈ [arm + ms, arm + ms + tick)     —— 绝不提前
```

这与 Go 的 `time.After` 语义一致。

### 这个缺陷怎么才能必然复现

顺序 arm 的测试里，协程是被上一次 tick 唤醒的，紧接着就 arm 下一个 ——
`frac ≈ 0`，缺陷几乎不出现（上面那 4 次里只挂 2 次，就是这个原因）。

所以测试里加了一个**受控相位**场景：先忙等到 `now - TM_LASTMS ≥ 11ms`
再 arm 一个 400ms 的定时器。不补偿的话必然提前 ~11ms 触发，
于是断言从"偶尔抓到"变成"必然抓到"。

## 实测（tick=16ms）

| aim | 实测 | 区间 |
|---|---|---|
| 50 | 64 | [50, 66) |
| 100 | 112 | [100, 116) |
| 200 | 208 | [200, 216) |
| 1200（跨 L0，走 L1+级联） | 1217 | [1200, 1216) ^1 |
| 400 @ 相位 12ms | 405 | [400, 416) |

^1 1217 比上界多 1ms：来自 `clock_ms()` 的整数截断 + 调度抖动，
   断言里留了 16ms 余量，不是"恰好卡线"。

- 40 个并发定时器全部触发、全部投递成功（漏投计数 0）
- 定时器线程无饿死、无累积漂移（tick 数与 elapsed/16 相差 0）
- `tm_after(0)` 立即投递；超范围（>4095 tick）返回 -1 并计数

## 🔴 本轮挖出的既有缺陷：`clock_ms()` 静默退化成 1 秒分辨率

`clock_gettime` 一次写 **16 字节**（sec + nsec），而墨语言里两个
**独立全局在内存中并不相邻**：

```mo
var A: i64 = 0;
var B: i64 = 0;
syscall(228, 1, &A, 0, 0, 0, 0);   # B 恒为 0
```

实测：B 恒为 0，紧跟其前后的其它全局也都未被改写 —— nsec 落在了两
者之间的空隙里（全局按 16 字节槽排布）。

于是 cstd 的 `TS_NSEC` 从来没被写过，`clock_ms()` = `TS_SEC * 1000`
→ **1 秒分辨率**。不报错、不崩溃，返回值看着完全正常。

**后果**：时间轮线程每次只睡 16ms 却不推进，攒够 1 秒才一次性补 62 个
tick —— 于是 50ms 的定时器实测要等 ~1 秒，而所有数字看起来都"对"。

同一段代码里 `sleep_ms(ms)` 更彻底：**完全没有设置 timespec**，直接把
`clock_ms` 写脏的 `TS_SEC/TS_NSEC` 当 `{sec,nsec}` 传给 `nanosleep`，
实际睡多久取决于上一次读时钟的残留值。

**教训**：给系统调用传结构体缓冲时，必须用**数组**，不能用两个独立全局。
（`lib/log.mo` 和 `lib/prof.mo` 用的都是数组，所以它们没中招。）

**判据已写进 `tools/timertest.sh`**：间隔 50ms 的两次 `clock_ms()` 差值
必须在 [40,120] —— 1 秒分辨率会得到 0 或 1000。

## 🔴 第二个坑：不能用 `usleep(tick)` 累加推进

累加会把每次 `usleep` 的超睡量累积成漂移。这里改成**绝对时间推进**：
每次算出下一个 tick 的绝对时刻再睡到它，并在饿死后限制单轮补 tick 数
（记 `TM_CATCH`）。同时记录 `TM_BURST`（单次唤醒补过的最大 tick 数），
正常必须 ≤2 —— 这个量在时钟退化时会变成 ~62，是最灵敏的探针。

## 变异验证（`make timermut`）

| 变异 | 结果 |
|---|---|
| M1 去掉 L1 分支（长定时也放 L0 → 提前） | ✅ 捕获 |
| M2 槽号用 now 而不是 exp（立刻触发） | ✅ 捕获 |
| M3 `tm_clock` 退回两个独立全局（**就是上面那个真缺陷**） | ✅ 捕获 |
| M4 向上取整改成向下取整（50ms → 48ms） | ✅ 捕获 |
| M5 去掉 tick 相位零头补偿（**就是上面那个真缺陷**） | ✅ 捕获 |

只看"26 项全绿"证明不了什么 —— 定时器"永远不触发"和"触发得正好"，
在只看"有没有崩"时都是绿的。

## 已知限制

- 精度 = tick；单次最大 4095 tick（约 65 秒），超出返回 -1 响出来，
  不静默截断成一个短定时
- 目标 channel 必须 cap≥1
- 定时器线程不是协程，只能走 `chan_trysend`
- 未做取消（`tm_cancel`）、未做周期定时器
- 必须 molink + libc（pthread / usleep）
- `TM_LASTMS` 由定时器线程写、arm 方读，两侧都在 `TM_LK` 内；
  但 `tm_clock()` 在锁外调用 —— 极端情况下 arm 与 tick 交错会让 frac
  偏一个 tick，后果只是多等一个 tick，不会提前

## 变异脚本自身的两条纪律（本项目已栽过三次）

1. **被强杀会留下变异态**。已加 `trap restore EXIT INT TERM`，且收尾
   **不删**备份目录 —— 一旦真被强杀，可用
   `cp /tmp/timermutbk/orig.mo lib/timer.mo` 手工恢复。
2. **基线必须先过**。基线挂了就直接退出并提示"源码可能停在变异态"，
   否则会在脏源码上跑出一堆假绿的"变异被捕获"。
