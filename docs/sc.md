# 随机计算（Stochastic Computing）

## 这是什么

SC 是 1960 年代提出、近十年因 AI 硬件复兴的计算范式：**数值编码为比特流中 1 的概率**，
于是算术退化成几个逻辑门。

```
数 x ∈ [0,1]  →  一条比特流，其中 1 的比例是 x
0.6           →  1010011110（10 位里 6 个 1）
```

## 为什么算"概念"而不是"工程惯例"

论文体系是完整的：编码格式、门-函数对应定理、相关性理论、SNG 优化（Alaghi & Hayes 2013 综述、
Qian 的 UW 博士论文《The Logic of Random Pulses》给了通用定理）。

但**主流框架零实现**——PyTorch、JAX 都没有 SC 算子。现存实现只有 FPGA/ASIC 的 RTL，
以及少量 Python 仿真。属于典型的"有数学、躺在论文里"。

对比一下：本项目的点积检验、有限差分是**工程惯例**（gradcheck 就在用）；
HVP、Revolve 是**有算法无主流实现**；SC 更进一步——
连"该用什么接口表达一个 SC 张量"都还没有共识。

## 三条核心公式

| 编码 | 值域 | 乘法 | 加法 |
|---|---|---|---|
| 单极 UP | [0, 1] | `AND` | MUX + P(sel)=1/2 → (x+y)/2 |
| 双极 BP | [-1, 1] | `XNOR` | 同上 |

加法那个"被缩放 1/2"不是缺陷，是 MUX 的本质：它在每个时间步随机选一个输入，
所以输出概率是两者均值。**所有用 MUX 树求和的设计都必须处理这个缩放。**

## 实测

### 1. 位并行：103 倍

把 L 个时间步打包进 L/64 个 i64 字——**打包的是时间维度**，不是把不同的数塞进一个字。

```
打包    511 ns/次   （w 次 AND + popcount）
逐位  52669 ns/次   （L 次标量循环）
```

墨语言有 i64 位运算，这条天然合适。

### 2. 相关性：这是 SC 里最要紧的一条

门实现的函数**取决于两路流的统计相关度 C**：

```
AND :  C=0 → x·y          C=1 → min(x,y)
XNOR:  C=0 → x·y          C=1 → 1 − |x−y|
```

实测（p_a=0.6, p_b=0.7 → 乘积 0.42，min = 0.6）：

```
L=4096    独立 28000      共享 39840
L=16384   独立 27708      共享 39532
           期望 27525       ≈39321（=min）
```

**共享随机源时算出来的根本不是乘积，而且加长比特流也救不回来。**
Alaghi & Hayes 原话："cannot be corrected simply by extending N"。

所以本库把"源编号"做成显式参数，让这个陷阱**可复现**：
同一 `src` → 逐位相同的流 → C=1；不同 `src` → 独立 → C≈0。

### 3. 精度

```
L=512   误差 3333
L=1024  误差  901
L=2048  误差   59
L=8192  误差   99
```

采样误差本身有涨落，单步不保证单调；只断言整体收敛（L×16 → 误差至少 ÷2）。

### 4. 低差异序列：同长度下准 7.3 倍

```
L=1024   伪随机误差 901   低差异误差 123
```

低差异序列是**确定性**的，误差 ~1/N 而不是 ~1/√N。

## SC 神经元

标准结构：XNOR 阵列做乘法，MUX 树做求和。

### 🔴 MUX 树不是等权求和

树 `((t1+t2)/2 + t3)/2` 展开是 `(t1 + t2 + 2·t3)/4`——
**t3 只过一层 MUX，权重是 2；t1/t2 过两层，权重是 1。**

要让结果等于 `(w1x1 + w2x2 + bias)/4`，必须把 `bias/2` 塞进 t3。
漏掉这步会得到 `(w1x1 + w2x2 + 2·bias)/4`，偏置被放大一倍：
**不报错、不崩溃，只是决策边界整体平移。**

实测（AND，w=+1，bias=-1.5）：

```
输入      SC 输出    定点解析   分类
-1,-1     -57776     -57344     0
-1, 1     -24880     -24576     0
 1,-1     -24968     -24576     0
 1, 1       7928       8192     1
                              4/4 ✓
```

### 比特翻转容忍度

```
0‰   7928
1‰   7816
10‰  7712
50‰  7216    ← 5% 的位翻转，输出只掉 8.9%
```

这是 SC 相对定点的真正优势：一位错只影响一个时间步，是**平均掉**的；
定点里高位翻转一次就是灾难。

## 三个坑（按阴险程度排序）

### 1. `>> 48` 只覆盖半个值域

xorshift 输出非负且 < 2^63，所以 `x >> 48 ∈ [0, 32768)`，
而 Q16.16 的 [0,1] 是 0..65536。**任何 p > 0.5 的流都恒为全 1**。
不报错，只是所有结果都是 1.0。正确是 `>> 47`。

### 2. 多维低差异序列必须换基，不能靠 XOR 加扰

第一版用同一条 base-2 van der Corput，给两个源异或不同掩码。
表面上"两路流各不相同"，实际两维**仍然高度相关**：

```
L=1024   XOR 加扰误差 7877   伪随机误差 901
```

**低差异反而比伪随机差得多。** 症状是"低差异没效果"，根因是维度构造错了。
正解是 Halton：第 s 维用第 s 个素数做基。

### 3. popcount 的算术右移

墨语言的 `>>` 是算术右移。SWAR 写法在这里**恰好**安全——
每一步的掩码都把最高位组清掉了，符号扩展位混不进来。
但换个写法就不一定，所以测试里放了 200 组逐位对照。

## 限制

- **只做推理，没做训练**。SC 训练要靠随机积分器（论文有，未实现）。
- MUX 树缩放需手工补偿；真实设计用 APC 或 ESL，未实现。
- 值域受编码限制：BP 是 [-1,1]，超出要缩放。
- 存储池 8192 字（=524288 比特总量），超限需调大 `SCP`。
- 精度要靠长度换：8-bit 精度约需 L=256，16-bit 约需 L=65536。
