# import "x.mo" as N; —— 模块命名空间

墨语言所有 `import` 进来的文件共享**同一张**符号表。`tools/nscheck.py` 把由此
产生的风险面查清楚了（见 `docs/nscheck.md`）：文件内部调用自己的函数是安全的，
但**调用点所在文件自己没定义时，绑到最后被处理的那个文件的定义** ——
改一行 import 顺序就换了一个实现，编译器一声不响。

`import as` 把这一点变成显式的：给文件一个命名空间，之后必须写 `N.fn()` 访问。

```mo
import "ambA.mo" as A;
import "ambB.mo" as B;
fn main() -> i64 { return A.helper() + B.helper(); }
```

## 为什么不是"前缀字符串拼接"

第一反应是把函数名改写成 `"A." + name`。**没有这么做**：

拼接需要一个临时缓冲，而 `import` 可以嵌套 —— 共用缓冲会被内层冲掉。本项目
已在共享临时变量上栽过六次（HDC 的 CIM、SDM 的计数器、sq_recall 的循环变量……）。

改成给符号表加一列 `O_SPFX[sym]`（该符号所属的前缀**指针**），查找时比指针
而不是比字符串。于是**一次拼接都不需要**，嵌套天然安全。

同一个道理也用在模块表的存放上：`O_MODS[mid*32]` 每条定长 32 字节，而不是
一个共用缓冲。

## 绑定语义（实测，不是推断）

| 场景 | 结果 |
|---|---|
| A / B 内部各调自己的 `helper` | 恒正确，**与 import 顺序无关** |
| `A.helper()` / `B.helper()` | 各自的实现（1 / 2） |
| 带 as 之后裸写 `helper()` | `undefined symbol` —— 隔离生效 |
| 裸 import 的库 | 函数仍在全局，行为与 1.140 之前完全一致 |
| 库内部调用全局符号（如 `ufun`） | 先查本模块，查不到回退全局 |
| 同一文件先裸 import 再 `as` | **明确报错** `already imported` |

不带 `as` 时 `K_PFX` 恒为 0、所有符号的 `O_SPFX` 恒为 0，查找路径与改动前
**逐条等价** —— 190 项既有测试全过，自举三级产物仍字节一致。

## 实测

`tools/importastest.sh`，8 项：

| 用例 | 断言 |
|---|---|
| 143_importas | `A.calla()*100 + B.callb()*10 + (A.helper()+B.helper())` = **123** |
| 144_importas_rev | 反序 import，同样是 **123** |
| 145_importas_mix | `as` 与裸 import 混用 = **15** |
| 146_importas_global | 带 as 的库内部调全局符号 = **8** |
| 未定义模块名 | 必须报 `undefined symbol 'X'` |
| 模块内无此函数 | 必须报 `undefined symbol 'nosuch'` |
| 带 as 后裸调用 | 必须报 `undefined symbol 'helper'` |
| 重复 import as | 必须报 `already imported` |

143/144 是最关键的一对：**只差 import 顺序，结果都是 123**。
其中 `calla` 是 A 内部对自己 `helper` 的调用 —— 若内部自调用绑错（都绑到后
导入的 B），`A.calla()` 会得 2，结果变成 223。只看"两个库都能编译"完全
分不出这两种情况。

## 🔴 三个真坑

### 一、把变量版的 kind 判据用到了函数查找上

`sym_lookup`（变量）的条件是 `sym_kind(i) != 0`；`sym_lookup_func`（函数）
的条件是 `sym_kind(i) == 0 || == 3`。我第一版把两者统一成前者，于是
**所有 kind==0 的函数都被过滤掉了**。

症状离改动很远：**任何程序都报 `no main function`**。全套 190 项里 168 项
编译失败，而报错点在一万行之后的 `resolve_all`，看 `sym_lookup` 的源码
根本看不出来。

### 二、空模块 + 静默回退到全局

`import "x.mo";` 之后再 `import "x.mo" as A;`：第二次因 `imp_seen` 去重而
**一个符号都没收进模块**，但模块名照样登记。于是 `A.anything()` 在模块里
查不到 → 回退到全局 → **静默绑到一个完全无关的同名函数上**。

不报错、不崩溃，只是结果不对。现在明确拦下。

顺带拆了一个 `imp_have()`（纯查询、不登记）：原来的 `imp_seen` 查询时会
顺手登记，用它来问"导入过吗"会导致随后 `compile_file` 里的 `imp_seen`
必然返回 1 —— **文件根本不会被编译，而模块名却登记好了**，那才是真的静默。

### 三、变异锚点的 12 空格是 16 空格那一行的后缀

`tools/importasmut.sh` 第一版里 M3 的锚点是
`'            if load64(...) == pf {'`（12 空格）。而 `sym_dup` 里有一行
**16 空格**的同样内容 —— 12 空格是它的后缀，于是 `replace(..., 1)` 命中的
是 `sym_dup` 而不是 `sym_lookup_in`。

结果是：变异改到了无关函数上，测试全绿，脚本打印"未被捕获"。**看着像断言
空转，实际是变异没打中。** 修法是所有锚点都带 `\n` 前缀，按行首缩进精确匹配。

## 变异验证（5 个全部被捕获）

| 变异 | 结果 |
|---|---|
| M1 不给函数登记命名空间 | 捕获 |
| M2 模块内查不到时不回退全局 | 捕获 |
| M3 查找时忽略命名空间 | 捕获（修对锚点之后） |
| M4 import 时不设置当前前缀 | 捕获 |
| M5 去掉"重复 import as"检查 | 捕获 |

## 已知限制

- **只给 `kind 0`（本文件定义的函数）加命名空间。** 变量不加：库里的全局
  `var` 被 main 直接引用是既有用法。`extern` 不加：它是 C 的全局符号。
- **`A.x`（模块内的变量）不支持**，只有函数调用 `A.fn()`。
- **严格隔离会切断库间内部依赖。** 实测 `import "str.mo" as S;` 会报
  `vec.mo:39: undefined symbol 'memcpy'` —— `memcpy` 是 str.mo 定义的，
  进了 S 之后 vec.mo（全局）就看不见了。这是隔离的正确后果，但它意味着
  **`as` 只适合用在自包含的模块上**，不适合给互相依赖内部函数的标准库加。
- 同一文件只能 import 一次；带 `as` 重复 import 会报错。
- 模块名 ≤30 字符，模块数 ≤64。
- 变量与模块同名时**变量优先**（`sym_lookup` 先命中变量就不试探模块了）。

## 用法

```
bash tools/importastest.sh    # 8 项断言
bash tools/importasmut.sh     # 5 个变异验证
```
