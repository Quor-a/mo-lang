# fenw —— Fenwick 树（Binary Indexed Tree）

`lib/fenw.mo` · `tests/150_fenw.mo`（24 项断言）· `tools/fenwtest.sh` · `tools/fenwmut.sh`（6 变异）

## 概念来源

Peter M. Fenwick 1994，《A New Data Structure for Cumulative Frequency Tables》，
*Software: Practice and Experience* 24(3)。

核心恒等式是 `lowbit(i) = i & (-i)`：

```
T[i] = A[i - lowbit(i) + 1 .. i]
prefix(i) = Σ T[k]，k 从 i 起不断 k -= lowbit(k)
add(i, d) = 所有 k 起不断 k += lowbit(k) 的 T[k] += d
```

**为什么算"概念"：没有任何主流语言的标准库收录它。** C++ 标准库里没有，
Python / Java / Go / Rust 也全靠第三方或手写。它常被当成"十行代码片段"
而不是一个正式的数据结构 —— 但下面四种形态里有**两种不是十行能写对的**。

## 与四个概率性草图的关系（本库的真正定位）

| 库 | 回答 | 精度 |
|---|---|---|
| Bloom (v1.144) | 在不在 | 只假阳 |
| CMS (v1.144) | 出现几次 | 只高估 |
| HLL (v1.138) | 有几个不同的 | 相对误差 1.04/√m |
| qdigest (v1.147) | 排第 q 的是几 | 秩误差 ≈ 2k |
| **fenw (v1.148)** | **前缀 / 区间 / 秩** | **精确** |

前四个用**可控误差**换亚线性空间；Fenwick 走另一条路：空间 O(n)、答案精确。
它们回答同一类问题，只是精度-空间取舍相反 —— 草图答"大约是多少"，
Fenwick 答"恰好是多少"。

⇒ 因此本库的判据一律是 `==`，不是"接近"。

## 四种形态（同一句柄只能用一种，混用会给出无意义的值）

| | 操作 | 需要几只 BIT |
|---|---|---|
| ① 单点加 + 前缀和 | `fw_add` / `fw_prefix` | 1 |
| ② 单点加 + 区间和 | `fw_add` / `fw_range` | 1 |
| ③ 区间加 + 单点查 | `fw_radd` / `fw_prefix` | 2 |
| ④ 区间加 + 区间和 | `fw_radd` / `fw_rsum` | 2 |

④ 的公式（B1 存差分、B2 存加权差分）：

```
radd(l,r,d):  B1[l] += d,  B1[r+1] -= d
              B2[l] += d*(l-1),  B2[r+1] -= d*r
prefix(i)   = i * B1.pre(i) - B2.pre(i)
```

推导：任意区间 `[l,r]` 在位置 i 处的贡献是
`i>r → d*(r-l+1)`（整段）、`l<=i<=r → d*(i-l+1)`（部分）、`l>i → 0`。
代入上式三项（ `+d*i` / `-d*(l-1)` / `+d*r` ）恰好分别命中，可逐项验。

## 实测

参照一律是**暴力算法**（直接累加），不是另一个数据结构。

| 检查 | 规模 | 结果 |
|---|---|---|
| 前缀和 | 512 个 i，全部 | **0 处不一致** |
| 区间和（形态 ②） | 200 个随机区间 | **0 处不一致** |
| lower_bound | 300 个随机 target | **0 处不一致** |
| 点值（形态 ④，400 次区间加后） | 256 个 | **0 处不一致** |
| 区间和（形态 ④） | 200 个随机区间 | **0 处不一致** |
| `FWSTEP == popcount(i)` | 512 个 i | **0 处不一致** |
| `FWSTEP == floor(log2 n)+1` | n=512 | 10 ✓ |

## 结构性断言（本测试独有的价值）

`FWSTEP` 记录上一次遍历走过的步数，有两个**结构**性质的精确期望：

- `fw_prefix(i)` 走 **popcount(i)** 步（每次剥掉一个置位）
- `fw_lower()` 走 **floor(log2 n)+1** 步（二进制提升）

这两个数能在"答案碰巧对"时**仍然**抓出 lowbit 遍历被改坏。变异 M2 就是
专门为此设计的：**只把步数计数改成 +2，值一条都没错** —— 结果 24 项里
只有那一条结构断言变红。

> 只测"值对不对"的套件，会把遍历结构改坏这类缺陷判成全绿。

## 变异验证（6/6 被捕获）

| 变异 | 内容 | 结果 |
|---|---|---|
| M1 | 前缀遍历 `-= lowbit` → `-= 1` | 6 项红 |
| **M2** | **只改步数计数（值全对）** | **1 项红 ← 只有结构断言能抓** |
| M3 | `while FWI > 0` → `>= 0` | 死循环，timeout 124 |
| M4 | 单点加上升遍历 → `+= 1` | 5 项红 |
| M5 | lower_bound `<` → `<=` | 1 项红 |
| M6 | 区间加 B2 加权 `d*(l-1)` → `d*l` | 1 项红 |

`tools/fenwmut.sh` 自带 6 条防"验证机制自身失效"的措施：备份放项目目录内、
不用管道取退出码、apply 后读回校验、带 timeout、开工前预检源码是否已是变异态、
锚点带足够上下文避免命中同名函数。

## 已知限制（都没静默）

- `n ≤ 4096`，池最多 60000 字（约 14 个 n=4096 的 sketch）；越界返回 -1 并置 `FWOV`
- 下标 **1-based**；越界一律返回 -1 并置 `FWBAD`，**不静默夹紧**
- 四种形态**不能混用**同一句柄（B1/B2 语义不同），本库不检测混用
- 不支持 `fw_reset`（要清空请 `fw_new` 一个新句柄）
- 不支持删除（`fw_add` 传负 delta 可以抵消，但那是调用方的事）
- lower_bound 依赖值非负（负 delta 会让前缀和不再单调，结果无意义）
- `FWSTEP` 是全局诊断量，被 `fw_prefix` 和 `fw_lower` 共用 —— 连续调用会被覆盖
