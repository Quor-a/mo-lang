# .bss —— 占内存、不占文件

`a64as -r` / `a64ld` 现在支持 `.bss` 段。它补的是自举 aarch64 工具链的
最后半边：v1.166 只能汇编单文件，v1.167 补了链接器，v1.168 补了数据段
重定位（`.quad`），**但数据段里的东西必须是"已知的"** —— 写进去的每个
字节都要在汇编期定下来。

`.bss` 是反面：**零初始化、运行时才写**。缓冲区、计数器、栈、页表都
是这一类。没有它，"系统"只能由常量构成。

## 一句话性质

> bss 占内存、不占文件。

落到 ELF 上就是两件事，缺一不可：

| | 字段 | 含义 |
|---|---|---|
| 目标文件 | `sh_type = SHT_NOBITS(8)`，`sh_size = N` | 文件里没有这 N 个字节 |
| 可执行文件 | `p_filesz < p_memsz` | 加载器按 memsz 铺内存，多出来的部分补 0 |

**只做一半会怎样：**

- 只做"内存里有"（把 bss 当 `.data` 写出去）→ 行为完全正确，文件变大
  一圈。端到端执行、逐字节比对**全绿**，看不出错。
- 只做"文件里没有"（memsz 不加 NB）→ bss 字节压根没被分配。程序写
  bss 时要么越界、要么踩到别人的内存。

所以判据必须同时钉住 `memsz - filesz == NB` **和** `实际文件大小 ==
120 + filesz`。二者都在 `tools/a64bsstest.sh` 里。

## 段号与段头

加了 `.bss` 之后目标文件的段序号整体后移：

```
0 null · 1 .text · 2 .data · 3 .bss · 4 .rela.text · 5 .rela.data
6 .symtab · 7 .strtab · 8 .shstrtab        (e_shnum=9, e_shstrndx=8)
```

符号的 `st_shndx` 因此是：text=1 / data=2 / **bss=3** / UNDEF=0。
链接器按 `shn==3` 把符号归入 bss，地址 = `BASE + NT*4 + ND + FBW[文件] + 偏移`，
其中 `FBW` 是该输入文件 bss 在合并后 bss 区里的起点 —— 漏掉它，两个模块
的 bss 就会从同一个地址开始，互相覆盖。

## 实测

```
MO-BSS
Z OK        acc（模块 A 的 bss）初始为 0
P OK        buf[0]（模块 B 的 bss）初始为 0
SUM OK      用 bss 变量累加 1..100 = 5050
FILL OK     填充后 buf[0] == 0xA5
DATA OK     填充 12288 字节后，.data 里的字符串仍完好
ACC OK      填充后另一个模块的 bss 变量仍是 5050
```

链接产物：`filesz = 120 + 指令 + 数据`，`memsz - filesz = 12296`
（= 8 + 12288），**磁盘文件大小 == 120 + filesz**。

## 12288 这个数字不是随手写的

填充 12288 字节是判据的一部分：

- bss 地址正确 → 写在 `.data` 之后，字符串完好
- bss 地址错成 `.data` 起点 → 12288 字节足以覆盖全部 `.data`
  （4096 填充 + 全部字符串），`DATA OK` 那行必然消失

**若只填 256 字节，恰好只覆盖 `.zero 4096` 的填充区，字符串侥幸活下来，
缺陷就测不出来。** 这是本项目第三例"样本充分 ≠ 覆盖充分"（前两例：
SAM 的 `SA_NCL=0`、CMS 的 w=200）。

## 三个真缺陷

### ① 两遍汇编之间没复位 `NBB`

`assemble()` 每遍把 `NC`/`ND` 归零，我加 `NBB` 时忘了归零 —— 于是
bss 大小**翻倍**（`MEM_BSS_SIZE=16`、`BUF_BSS_SIZE=24576`）。

不报错、程序照跑（bss 只是多了一半空闲空间）。端到端执行**发现不了**，
只有"文件大小 vs memsz"这类判据能抓到。

### ② 段头表写到文件末尾之外

尾部余量原本是固定的 512 字节，只够 8 个段头。加了 `.bss` 之后段头表
是 9×64=576，超出文件末尾。

症状是链接器报 **`symtab has no strtab link`**（`SLK=0`）—— 看起来像
"文件坏了"，实际是段头表被截断。这个报错方向完全不指向真因。

### ③ `.zero` 在 bss 里仍写文件字节

`dbyte()` 原本无条件往 `DAT` 里写。`.bss` 里 `.zero 12288` 会把 12288
个 0 真的写进 `.data`，`ND` 涨到超出 16384 上限 → `data overflow`。

漏掉派发的话症状是"数据段莫名其妙变大"，而不是"bss 没生效"。

## 变异验证（`tools/a64bssmut.sh`）6/6 被捕获

| 变异 | 红几项 |
|---|---|
| M1 `.bss` 段头写成 `SHT_PROGBITS(1)` | 13 |
| M2 两遍汇编之间不复位 `NBB` | 3 |
| M3 `.zero` 在 bss 里仍写文件字节 | 6 |
| M4 bss 基址漏掉 `ND`（落在 `.data` 上） | 4 |
| M5 bss 基址漏掉 `FBW`（两模块 bss 重叠） | 3 |
| M6 `memsz` 不含 `NB` | 1 |

**M6 只红 1 项**，冗余度薄，如实记录：改动 memsz 前应先补一条
"越界写 bss 必须被模拟器拦下"的断言。现在它只被 `memsz - filesz` 这一条
盯住 —— 而这条恰好就是被测的那行算出来的，等于自己验自己。

## `.bss` 里不能初始化

`.byte` / `.asciz` / `.ascii` / `.quad` 在 `.bss` 里一律报错
`cannot initialize .bss`，不静默丢值。

`.zero` 与 `.align` 在 `.bss` 里只推进 `NBB`，不产生字节。

## 已知限制

- 没有 `.bss` 的重定位：`.quad sym` 在 bss 里报错。bss 无法被预先初始化
  成地址，需要跳转表请放在 `.data`（v1.168 已支持）。
- 链接器要求 `.bss` 段头类型必须是 `SHT_NOBITS`，否则拒绝链接并报
  `SHT_NOBITS` —— 因为按 `sh_size` 去读文件内容会把后面的段当成 bss 内容
  搬进内存。
- 只有 8 个输入文件；bss 总大小无硬上限（只推进计数器）。
- 零初始化依赖加载器按 `memsz` 补 0。裸机模拟器（Unicorn）天然满足；
  换成别的加载器时要确认这一点。
