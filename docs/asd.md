# ASD：自动稀疏微分（1.80）

## 什么是"概念"

**概念 = 有数学推导和算法、但没变成可用东西的能力。**

前几轮做的（点积检验、有限差分）属于**工程惯例**——早有人在用，
PyTorch 的 gradcheck 就是。这轮做的是另一类：论文写完了，但实现要么
没有、要么只是个演示用的参考实现，能力一直躺在 PDF 里。

ASD 就是这样的概念：

- Gebremedhin, Manne & Pothen, *What Color Is Your Jacobian? Graph
  Coloring for Computing Derivatives*, SIAM Review 2005
- Griewank & Walther, *Evaluating Derivatives* 第 8 章
- ICLR 2025 blogpost *An Illustrated Guide to Automatic Sparse Differentiation*

**它现在的状态**：ColPack 是 C++ 的、Julia 有 SparseDiffTools、Python 的
asdex 很新。**没有哪个主流框架默认做这件事**——PyTorch/JAX 都把 Jacobian
当稠密的算。

## 核心悖论

> 要判断哪些列"结构正交"（可合并成一次传播），得先知道稀疏模式；
> 可要用传统 AD 把矩阵算出来才知道模式 —— 那 ASD 就没意义了。

解法：**只传播索引集，不做数值计算**。

## 四步流水线

```
Detection → Coloring → Compressed AD → Decompression
```

墨语言能做，是因为它有 tape（AD_TOP/TA/TB/TO 记录每个算子的操作数），
稀疏模式**可以静态推出**，不需要先算数值。

### 实测（1→4 通道 3×3 卷积，8×8 输入，gmax 输出）

| 步骤 | 结果 |
|---|---|
| Detection | 非零 36 / 稠密 144（每行只有 9 个） |
| Coloring | **9 种颜色**（稠密需 36 次传播）→ 压缩 **4×** |
| 压缩 + 解压 | 与逐列稠密 JVP **逐值一致**，144 项 0 处不一致 |

全连接对照（2×4 权重）：非零 8/16，颜色数 **4**（稠密 8）→ 压缩 2×。

## 三个真坑

### 1. 🔴 运算符优先级：两次静默失效

墨语言里 `==` 的优先级**高于** `&`。于是：

| 写法 | 实际解析 | 后果 |
|---|---|---|
| `used >> c & 1 == 0` | `used >> (c & (1==0))` = `used` | 第一次判断就不成立，**所有列分不到颜色**，颜色数=0 |
| `pj * 2 + q & 1` | `(pj*2 + q) & 1` | pool 的 `q=2,3` 读到通道 0，bit 0..8 泄漏进所有通道 |

两个都**不崩、不报错**，只是结果慢慢变差。

**修法**：位测试一律写成两步，不依赖优先级——

```mo
let b: i64 = pp >> j;
b = b & 1;
if b == 1 { ... }
```

这是本项目第三次栽在优先级上（前两次碰巧结果正确才没暴露）。

### 2. 🔴 偏置索引：`b + j` 应为 `b + i`

`ad_vadd_bcast(c1, KB, 4, 36)`：nr=4 是**通道数**，nc=36 是每通道元素数，
偏置每通道**一个**（实现里是 `ad_val(b + i)`）。detect 写成了 `b + j`，
j 循环到 35，读到槽 100..135——而 104 之后正是 `c1` 的元素，
于是把通道 0 的模式混进所有通道。

表现：模式从"每行 9 个"膨胀成"每行 18 个"，**稀疏度悄悄减半**。

### 3. 🔴 解压必须按模式过滤（recovery）

`JC[c][o]` 是颜色 c 里**所有列**在输出 o 上的导数之和。只有 j 是其中
那个"唯一非零"的列时才可直接取。必须先查模式：模式说 `J[o][j]=0` 就返回 0。
这正是论文里的 recovery matrix R。

去掉这步 → 144 项里 **27 项**错（跨通道串味）。

## 变异测试（证明非空转）

| 变异 | 结果 |
|---|---|
| detect 末尾强制输出块全稠密 | 非零 144（应 36）、颜色 36（应 9）→ **抓到** |
| 解压去掉模式过滤 | 不一致 27、跨通道非零 27 → **抓到** |

## ⚠️ ASD 能预测什么、不能预测什么

这是它与前面几轮工作的**边界**，很重要：

| 现象 | ASD 能否预测 | 原因 |
|---|---|---|
| 不连通导致的结构零 | ✅ 能 | 模式就是连接性 |
| 输入恒空窗口（1.74 那 6 个"合理死亡"） | ❌ 不能 | 连通但数值恒为 0 |
| 符号一边倒 + relu（1.73 那 9 个） | ❌ 不能 | 连通，是数值与激活的后果 |

**ASD 看的是拓扑，不是数值。** 它把"结构性零"从"事后统计"变成
"训练前推导"，但那两类"数值性零"仍要靠 1.70 起的审计体系去抓。

## 已知限制

- 输入数 ≤ 64（位集用 i64）
- `pool_mc` 保守：POOLPOS 依赖数值，静态推不出，所以 4 个候选全算
  （会高估非零，压缩率偏保守，但不会算错）
- 只实现了 conv_mc / pool_mc / gmax / gavg / matmul / 逐元素算子的精确传播，
  其余回退到并集（保守，安全方向）
