# lsh —— 局部敏感哈希（MinHash / SimHash / banding）

`lib/lsh.mo`，测试 `tests/137_lsh.mo`（18 项），变异验证 `tools/lshmut.sh`（4 个）。

## 概念来源

| 部件 | 出处 | 估计的度量 |
|---|---|---|
| MinHash | Broder 1997；Broder–Charikar–Frieze–Mitzenmacher 2000 *Min-wise independent permutations* | **Jaccard** |
| SimHash | Charikar 2002 *Similarity estimation techniques from rounding algorithms* | **余弦 / 角度** |
| banding | Indyk & Motwani 1998 *Approximate nearest neighbors* | 把 Jaccard 放大成 S 曲线 |

**为什么算"概念"**：LSH 是次线性相似检索的经典理论基础，但主流框架里一个都没有
—— Python 靠 datasketch、Java 靠 stream-lib，都是第三方；Go / Rust / .NET 标准库无。
它也不是数据结构练习，核心是一句概率恒等式：

```
Pr[ min h(A) = min h(B) ] = |A ∩ B| / |A ∪ B|
```

签名不存集合，只存 k 个最小值，压缩是**有理论保证**的，不是"够用就行"。

## 与 HDC / SDM 的关系（项目内对照）

三者都用随机性，但保的东西不同：

| | 载体 | 机制 | 会不会漏 |
|---|---|---|---|
| HDC | 随机高维向量 | **代数运算**（⊕ 保相似、⊗ 保可逆） | 容量内确定 |
| SDM | 随机硬地址 | **邻接激活**（内容寻址） | 容量内确定 |
| LSH | 随机哈希 | **保序压缩**（只保相似度序） | **会漏**，且是本质的 |

最后一行是本库特意钉成数字的：`s = 0.4493` 略高于阈值 `t = 0.4204`，
实测召回率 **0.633**，理论 0.7358 —— 高于阈值仍会漏掉约三分之一。
这不是实现不精，是 banding 的定义本身。

### SimHash —— 用解析精确点验证 Charikar 定理

定理说的是 `Pr[第 i 位不同] = θ/π`，其中 `cos θ = cos(x,y)`。
**刻意不查表、不近似 arccos**，只用四个能手算的点：

| 构造 | cos | θ/π | 实测 |
|---|---|---|---|
| A = B | 1 | 0 | **0（精确）** |
| \|A\|=32 ⊂ \|B\|=64 | 1/√2 ≈ 0.7071 | 1/4 | 通过（\|Δ\|<2500） |
| \|A\|=\|B\|=100，交 50 | 0.5 | 1/3 | 通过 |
| \|A\|=\|B\|=64，不相交 | 0 | 1/2 | 通过 |

> 第一版我手写了一张 33 点的 cos 表，实测与真值差到 **0.5**
> （把"角度均分的 cos"写成了"线性递减"）。表已删除 —— 解析点不需要任何近似源。

### banding 的 S 曲线（b=32, r=4, k=128，30 次重复）

阈值 `t = (1/b)^(1/r) = 0.4204`。

| Jaccard s | 理论 `1−(1−s^r)^b` | 实测 |
|---|---|---|
| 0.2000 | 0.0500 | 0.100 |
| 0.4000 | 0.5639 | **0.567** |
| 0.4493 | 0.7358 | 0.633 |
| 0.6000 | 0.9882 | 1.000 |

- `P(0.6) − P(0.2) > 0.6`：S 曲线确实陡变 ✓
- `P(0.45) < 0.9`：高于阈值仍明显漏 ✓（本轮最该钉住的一条）
- `P(0.45) < P(0.6) − 0.1`：不是"一到阈值就饱和" ✓

s=0.2 那点偏离最大（0.100 vs 0.050）：30 次里命中 3 次，期望 1.5 次，
泊松 σ≈1.2，属 +1.2σ 的样本波动，不是系统性偏差。

## 🔴 本轮挖出的缺陷

### 1. SimHash 退化成"只加不减"（优先级陷阱，项目第二次）

```mo
if (LSW >> LSJ) & 1 == 0 { ... }      # 🔴 恒假
if ((LSW >> LSJ) & 1) == 0 { ... }    # ✅
```

`==` 优先级**高于** `&`，裸写会被解析成 `(LSW>>LSJ) & (1 == 0)` 即 `& 0`，恒假。
于是减分支从不执行，acc 恒为正、签名恒定、**所有汉明距离 = 0**。

不报错、不崩溃。而 `cos=1 时 ham=0` 那条断言**照样通过** —— 测试全绿、什么都没验。

> `lib/sdm.mo` 第 335 行早有这条警告，本库是**第二次**栽上。
> 注释没能阻止重犯；只有 M2 变异能（去掉减分支 → 3 项断言变红）。

### 2. 原始元素号上直接用 `a·x+b` 不是 min-wise 的

集合元素常常是连续整数 `{0,1,2,…}`，而 `{a·x+b mod P}` 在这种输入上是**等差数列**，
最小值位置分布严重不均（三条距离定理），`Pr[min 相等]` 不再等于 J。

四种哈希方案对照（A={0..99}、B={50..149}，J=1/3 应为 21845，n=3000）：

| 方案 | 实测 |
|---|---|
| raw `a*x+b` ← 第一版 | **18634**（偏低 15%） |
| `mix(x)` 再线性 ← **本库采用** | 21757 |
| `mix(x)` + salt | 21692 |
| `mix` 高位 + salt | 21408 |

不报错、不崩溃，估计值只是永远偏低一截。
**教训**：MinHash 的理论前提是"h 在集合上是均匀随机排列"；
`a·x+b mod P` 只满足 pairwise independence，**不够**，必须先用一个混合函数把结构化 ID 打散。

## 已知限制

- **SimHash 的 tie**：累加值是偶数项 ±1 之和，`acc == 0` 的概率约 10%（|D|=64 时）。
  本库把 tie 归为 bit 0（`> 0` 才算 1），是确定且对称的，但 Charikar 定理假设无 tie，
  所以这是**一个未量化的近似源**。要素数维或随机 tie-break 才能消除。
- MinHash：`k ≤ 512`；签名池 24576 字；`banding` 要求 `b*r == k`，否则 `lsh_bcand` 直接返回 0。
- banding 的 `bhash` 用乘法混合（wrapping），不是密码学哈希。
- 只做**成对**相似度估计与候选判定，没有做完整的索引结构（桶表 / 倒排）。
