# 后缀自动机（Suffix Automaton / DAWG）

`lib/sam.mo` · `tests/142_sam.mo`（50 项）· `tools/sammut.sh`（6 个变异）

## 1. 它是什么，为什么算「概念」

**识别一个文本全部子串的最小 DFA。**

- Blumer, Ehrenfeucht, Haussler, McConnell 1985
  *"The smallest automaton recognizing the subwords of a text"* —— 证明
  状态数 ≤ 2n−1，且这个界是紧的
- Crochemore 1986 —— O(n) 在线构造

**主流语言标准库一个都没有**：C/C++、Java、Go、Rust、Python 均无内建。
Python 有第三方 `pydivsufsort`，C++ 有 SDSL / Boost，都不是标准库。

### 与 `lib/regex.mo` 的分工

| | 预处理的 | 查询 | 复杂度 |
|---|---|---|---|
| regex（Thompson NFA + Pike VM） | **模式** | 文本 | O(n·m) |
| sam（后缀自动机） | **文本** | 模式 | 预处理 O(n)，查询 O(m) |

SAM 回答的是「文本固定、模式任意多」那一类问题：一次建好后，每次查询与
模式个数无关。两者不是替代关系。

## 2. 三条可测的性质

| 性质 | 判据 |
|---|---|
| 状态数 ≤ 2n−1，边数 ≤ 3n−4 | 12 个随机文本逐个断言 |
| 从初态沿边走 ⟺ 是子串 | 与 O(n·m) 暴力对照 200 次查询 |
| `cnt[v]` = `\|endpos(v)\|` = 出现次数 | 与暴力**逐个子串**对照（330 个） |
| 不同子串数 = Σ(len[v] − len[link[v]]) | 与「枚举+排序+去重」精确对照 |
| 最长重复子串 / 最长公共子串 | 与暴力 LCP 对照 |

**全部结论都有独立参照。** SAM 自己算出来的数字不能证明自己 ——
「状态数是 84」这句话，只有和暴力算法给出同一个答案时才成立。

## 3. 🔴 本轮最有价值的发现：被测文本从未走克隆分支

M5（克隆状态的 `cnt` 初值设成 1 而不是 0）一开始**没被任何断言抓到**。
查下去才知道原因：

```
"abacabadabacaba"  →  16 个状态，SA_NCL = 0
```

**这个文本在构造过程中一次克隆都没发生** —— 每个新字符都恰好满足
`len[p] + 1 == len[q]`。于是所有只影响克隆状态的代码路径，
在上面**一行都没有被执行过**。

这不是「测试写少了」，是测试**空转**的一种形状：
样本看着很充分（120 个子串全枚举），但覆盖不到那条分支。

修法不是放宽断言，而是：

1. 给 `lib/sam.mo` 加 `SA_NCL`（克隆计数），把「确实克隆了」本身写成断言
2. 换一个真正会克隆的文本（k=2 字母表、n=20，实测克隆 10 次）
3. 在上面再全枚举 210 个子串

改完之后 M5 立刻被抓到（1 项红）。

> **凡是「改了代码测试却全绿」，先问是不是那条分支压根没跑到。**
> 这条和 v1.137 LSH 里「SimHash 的减分支恒假」、v1.138 HLL 里
> 「哈希 bit63 恒 0 只用一半桶」是同一族。

## 4. 🔴 我自己犯的一次静默：`main` 吞掉了 `test_done()` 的返回值

第一版 142 写的是：

```mo
test_done();
return 0;        # ← 断言失败也返回 0，而 run.sh 的期望值恰好是 0
```

于是 M1/M2/M4/M5 四个变异**全部被判成「未被捕获」而实际早就失败了 9~12 项**，
同时 `make test` 照旧报「通过」。

这正是 v1.115 修过的那类系统性空转，我在新文件里又写了一遍。
好消息是 `projcheck` 第 8 项能抓到它 —— 并且这次**实测验证过守护有效**：

```
把 142 改回 `test_done(); return 0;` →
  ✗ 以下测试丢弃了 test_done 的返回值： 142_sam.mo
```

**守护不能只是「写了」，得确认它真的会响。**

## 5. 变异验证（`make sammut`）

| 变异 | 结果 |
|---|---|
| M1 克隆时不复制转移 | 13 项红 |
| M2 克隆状态的 len 取成 len[q] | 21 项红 |
| M3 cnt 按 len **升序**传播（应为降序） | 捕获 |
| M4 nsub 不减 len[link] | 9 项红 |
| **M5 克隆状态 cnt 初值 1** | **仅 1 项红**（见 §3） |
| M6 查不到转移返回初态（子串判定恒真） | 捕获 |

M5 只挂 1 项，说明这条因果链的冗余度仍然很薄 —— 改 `sam_prep` 或
克隆逻辑时应当先补断言，不要指望现有的 1 项。

另：M2 的第一版设计是「克隆条件 `==` 改成 `>=`」，结果**未被捕获**。
原因是 `len[q] ≥ len[p]+1` 恒成立，两者在数学上等价 ——
**「改了代码」不等于「改到了那条因果链」。**

## 6. 实现说明

- 转移用**稀疏链表**存：稠密表要 2n × 256，字节字母表下太浪费；
  代价是转移查询 O(出度) 而非 O(1)
- `sam_prep` 用**计数排序**按 len 升序排列状态，再**倒序**把 cnt 累加到
  后缀链接上 —— 顺序错了 it 就不是拓扑序（M3 就是打这里）
- 克隆必须复制**全部转移**（`sam_clone_tr`）。漏了之后克隆状态没有出边，
  从它出发的查询提前失败，而构造过程完全不报错（M1 打这里）

## 7. 已知限制

- 文本长度 ≤ 2100（`SA_BKT`），状态 ≤ 4200，边 ≤ 6300；超出置 `SA_ERR`
- 只处理字节，不按 UTF-8 码点切分（要码点先用 `lib/utf8.mo`）
- 未做 `sam_lcs_str`（只给了长度 `sam_lcs_len`）
- 未做后缀链接树上的 DP（最长回文、最小表示等经典应用）
- 转移查询是 O(出度)；字节字母表下出度可能不小，热路径应换稠密表
