# 内存管理：arena 与 leak

## 问题

`lib/heap.mo` 的 `malloc`/`free` 要求调用方对**每一个**对象都记得释放。
漏掉一个是**静默错误**：不报错、不崩溃、结果也对，只是内存一路涨，
等 OOM 时离真正的出错点已经有十万八千里。

两个互补的手段：

- **arena**：让"忘记 free"这件事**从根上不可能发生**
- **leak**：让已经发生的泄漏**看得见**

## arena —— 区域分配器

```mo
import "arena.mo";
let a: Arena;
Arena_init(&a, 65536);

let p: ptr = Arena_alloc(&a, 64);     # 分配 = 指针前推
let s: ptr = Arena_str(&a, "hello");  # 字符串副本

Arena_reset(&a);    # 丢弃**所有**对象，保留块供复用
Arena_free(&a);     # 连块一起还给堆
```

### 对照实验（examples/arenademo.mo）

同一个"解析 2000 条记录"的任务：

| 写法 | 未释放对象 | 未释放字节 |
|---|---|---|
| 逐个 `malloc` 忘 `free` | 2000 | 128000 |
| arena + 一次 `free` | 0 | 0 |
| arena 反复 `reset`（100 批） | 0 | 0 |

三种写法**运行结果完全一样**，差别只有 leak 能看出来。

### 代价

- 不能单独回收某个对象
- reset 之前所有对象都活着

适合"一批数据共同生死"：解析一个文件生成的所有节点、一次请求里的
所有临时串、编译器的一遍 pass。

### 两个坑

**1. 块头必须是 16 的倍数（32，不是 24）。**
数据区起点是 `块 + BLK_HDR`，24 % 16 = 8，于是每个对象都偏移 8 字节——
x86 允许非对齐访问所以"能跑"，但 `p % 16 == 0` 这类断言直接失败。

**2. `next` 必须是"旧块指向新块"。**
反过来 reset 时从 `cur` 走不到 `first`，无法把所有块的 `used` 清零，
表现为"reset 之后内存没真正回收"——程序照样能跑，极难发现。

## leak —— 分配追踪

```mo
import "leak.mo";
leak_init();
let p: i64 = lmalloc(64);   # 用 lmalloc / lfree 代替 malloc / free
lfree(p);
leak_report();              # 报告未释放的
leak_clear();               # 只清统计，用于分段测量
```

也可以只在**怀疑有泄漏的模块**里用，其余照旧。

报告示例：

```
---- 内存分配报告 ----
累计分配 : 4    累计释放 : 1    活跃条数 : 3    活跃字节 : 448
⚠ 未释放的分配（前 8 条）：
  #2  地址 514203712  大小 64
```

## 🔴 顺带修掉的 heap.mo 扩容 bug

leak.mo 一次性申请 3 × 64KB 的追踪表，把 heap.mo 一个**一直存在的
严重缺陷**逼了出来：

```mo
# 原写法：grow **之后**才遍历链表找 last
heap2_grow(...);
let q: i64 = HB;
while q < HP { last = q; q = blk_next(q); }   # ← HP 已推高
```

grow 之后 `HP` 已经被推高，遍历会走进刚申请、**内容未初始化**的区域，
把全 0 当块头读（size=0 → 每次只前进 16 字节），`last` 落到错误位置；
接着把它的 size 设成跨越 brk 边界的值，split 出一个**越界地址**。

**症状**：单次 `malloc` 超过初始空闲块（65520 字节）时返回越界指针，
一写就段错误。

因为平时都是小块分配，这个 bug 一直没被触发。

**修法**：在 grow **之前**先定位最后一个块并记住它是否空闲。

```mo
let q: i64 = HB;
while blk_next(q) < HP { q = blk_next(q); }   # ← grow 之前
last = q;
let wasfree: i64 = 0;
if blk_used(last) == 0 { wasfree = 1; }
```

## 已知限制

- 追踪表固定 8192 条，超出后不再记录新的（会提示"溢出 N 次"），
  但不影响程序正确性
- `lfree` 用"最后一条覆盖当前条"删除，不保序 —— 报告里的顺序
  不等于分配顺序
- arena 不检查越界写入（与 C 一样）
