# 墨语言（Mo）语言参考

适用版本：1.0.0

墨语言是一门静态类型、直接生成 ELF64 可执行文件的编译型语言。
编译器用墨语言自己写成，并能编译自身（自举）。

---

## 1. 程序结构

一个程序由若干声明组成，顺序不限：

```mo
import "io.mo";          # 引入其它文件

var counter: i64 = 0;    # 全局变量

struct Point {           # 结构体
    x: i64;
    y: i64;
}

fn add(a: i64, b: i64) -> i64 {    # 函数
    return a + b;
}

fn main() -> i64 {       # 入口
    return add(1, 2);
}
```

- 注释以 `#` 开头，到行尾结束
- 入口是 `fn main() -> i64`，返回值即进程退出码（只取低 8 位）
- 定义顺序无关：可以先调用后定义，跨文件也行

---

## 2. 类型

| 类型 | 说明 |
|---|---|
| `i64` | 64 位整数，唯一的基础数值类型 |
| `byte` | 1 字节无符号；存储时截断，读取时零扩展 |
| `ptr` | 指向字节的指针，用于字符串与缓冲区 |
| `[N] T` | 定长数组，N 必须是正整数常量 |
| 结构体 | `struct` 定义的复合类型 |

没有浮点、没有布尔类型（用 `i64` 的 0/1 表示）。

---

## 3. 变量

```mo
var g: i64 = 0;          # 全局，程序运行期一直存在，初值必须是常量
let x: i64 = 10;         # 局部，在函数内
let a: [8] i64;          # 局部数组（不初始化）
var b: [8] byte = 0;     # 全局 byte 数组
```

赋值与复合赋值：

```mo
x = x + 1;
x += 1;  x -= 1;  x *= 2;  x /= 2;  x %= 3;
x &= 0xf;  x |= 1;  x ^= 1;
```

数组与结构体不能被整体赋值（`a = b` 会报错），只能逐元素。

---

## 4. 函数

```mo
fn fib(n: i64) -> i64 {
    if n < 2 { return n; }
    return fib(n - 1) + fib(n - 2);
}
```

- 参数与返回值目前都按 `i64` 传递；`ptr`、`byte` 也可作参数
- 支持递归和互递归
- 前 6 个参数走寄存器，第 7 个起走栈
- 函数末尾必须出现 `return`（编译器做保守检查：完全没写会报错，
  但某个分支漏写不会报）

---

## 5. 运算符

按优先级从低到高：

| 类别 | 运算符 |
|---|---|
| 逻辑或 | `\|\|` |
| 逻辑与 | `&&` |
| 位或 | `\|` |
| 位异或 | `^` |
| 位与 | `&` |
| 相等 | `==` `!=` |
| 关系 | `<` `>` `<=` `>=` |
| 移位 | `<<` `>>` |
| 加减 | `+` `-` |
| 乘除取余 | `*` `/` `%` |
| 一元 | `-` `!` `&`（取地址） |

- `/` 与 `%` 是带符号除法，向零取整
- `!` 返回 0 或 1
- `&` 作一元是取地址，作二元是按位与，靠语法位置区分

---

## 6. 控制流

```mo
if x > 0 {
    return 1;
} else if x == 0 {
    return 0;
} else {
    return -1;
}

while i < 10 {
    if i == 5 { i += 1; continue; }
    if i == 8 { break; }
    i += 1;
}
```

- `break` / `continue` 只作用于最内层循环，在循环外使用会报错
- 花括号不能省略

---

## 7. 数组、指针与字符串

```mo
let a: [4] i64;
a[0] = 1;
let i: i64 = 2;
a[i] = a[i - 1] + 1;
```

- 下标越界会被拦住并终止程序（退出码 1，打印 `index out of bounds`）
- 编译期常量下标越界直接编译报错
- `ptr` 用于逐字节访问：

```mo
let s: ptr = "hello";
let c: i64 = s[1];       # 101
let n: i64 = strlen(s);  # 5
```

- 字符串字面量可以直接下标：`"hello"[1]`
- 字符串以 0 结尾，字面量存储在只读数据区
- 字符字面量：`'a'`、`'\n'`，值就是字符编码

---

## 8. 结构体

```mo
struct Inner { v: i64; }
struct Outer {
    a: i64;
    in: Inner;
    b: i64;
}

let o: Outer;
o.a = 1;
o.in.v = 2;
let x: i64 = o.in.v;

let arr: [3] Outer;      # 结构体数组
arr[0].a = 5;
```

字段按声明顺序连续布局，嵌套结构体内联展开。

## 9. 内建函数

| 函数 | 说明 |
|---|---|
| `load8(p)` / `load64(p)` | 从地址读 1 / 8 字节 |
| `store8(p, v)` / `store64(p, v)` | 向地址写 1 / 8 字节 |
| `syscall(n, a1..a6)` | 系统调用，返回rax |
| `argc()` | 命令行参数个数 |
| `argv(i)` | 第 i 个命令行参数（0 是程序名） |

标准库提供 `print` / `print_i64` / `strlen` / `streq` / `strcpy` /
`strcmp` / `memset` / `memcpy` / 文件读写 / 简易分配器 / 断言框架。

## 10. 模块

```mo
import "io.mo";
import "lib/str.mo";
```

- 所有文件共享同一张符号表，靠回填实现跨文件调用，顺序无关
- 重复 import 同一路径只编译一次，循环 import 合法
- 搜索顺序：相对当前文件 → `lib/<basename>` → `../lib/<basename>`

## 11. 编译与运行

```bash
moc prog.mo prog.elf        # 编译
moc prog.mo -g prog.elf     # 带调试信息（gdb 可按源码行下断点）
./prog.elf                  # 运行

bash tools/mobuild.sh main.mo -o app.elf   # 递归解析 import 并构建
bash tools/fmt.mo 的用法见下
```

格式化工具（`tools/fmt.mo` 编译后）：

```bash
fmt file.mo          # 输出到 stdout
fmt -w file.mo       # 就地写回
```

它只调整空白（缩进、行尾空格、末尾换行），不改 token 流。

## 12. 已知限制

| 项 | 说明 |
|---|---|
| 只有整数类型 | 没有浮点、没有真正的布尔 |
| ~~没有动态数组~~ | ✅ 1.1.0 起有 `lib/vec.mo` |
| 没有完整寄存器分配 | 1.0 只做了栈顶缓存；完整版需先有 IR，见 `docs/regalloc_design.md` |
| `ptr` 不带长度 | `p[i]` 不做越界检查 |
| 结构体不能整体赋值或按值传参 | 只能逐字段 |
| 没有 `<<=` `>>=` | 需要三字符 token 支持 |
| 调试信息只有行号 | gdb 能下断点，但不能 `print 变量名` |
| 只支持 x86-64 Linux | 直接产出 ELF64，不接 LLVM |

## 13. 代码生成

编译器边解析边发射代码，没有中间表示（AST/IR）。
1.0 起加入了**栈顶缓存**：二元运算的左操作数放进 `rbx` 而不是压栈，
省掉一对内存访问。`rbx` 在 SysV ABI 里是 callee-saved，
且生成的代码本身不使用它，因此安全。

维持不变式「`rbx` 里是最后一次 push 的值」，任何新的 push 之前
都会先把旧值落栈，所以嵌套表达式与函数调用都正确。

实测收益（相对优化前）：数组密集程序约 -15%，字符串处理约 -33%，
纯函数调用递归无变化。

完整的寄存器分配需要中间表示，属于 1.x 的议题。

## 陷阱与反直觉约定

这一节的每一条都对应一个**实际踩过**的 bug，不是理论提醒。

### 0. 数组名在表达式里退化为指针

与 C 一致：`let p: ptr = buf;` 得到的就是 `buf` 的首地址。

```mo
let buf: [8] byte = 0;
let p: ptr = buf;      # 等价于 &buf
p[0] = 65;             # 写的是 buf[0]
```

**曾长期缺失**（1.13.0 修复）。缺失时的表现极具迷惑性：

```mo
let p: ptr = buf;      # 实际把 buf 的前 8 个字节当成地址
p[0] = 65;             # 于是 p 是垃圾值（通常 0）→ 段错误
```

编译期不报错、运行期才崩。它一度被误判为"指针下标不支持写入"，
但真正缺的是**数组到指针的退化**——`&buf` 一直是好的。

### 1. `strchr` / `strstr` 返回相对下标

返回的是**相对传入起点**的下标，不是绝对地址。没找到返回 `-1`。

```mo
let e: i64 = strchr(s + i + 1, 96);
if e >= 0 {
    # 内容是 s+i+1 开始的 e 个字节
}
```

**最危险的一点**：返回 `0` 表示"就在开头找到"，**不是**"没找到"。
把 `== 0` 当失败判断，会在一匹配成功时反而走失败分支。
`grep.mo` 和 `site.mo` 各栽过一次。

### 2. `dir_next` 返回 1 表示取到

`1 = 取到一个条目，0 = 遍历结束`。与"0 表示成功"的直觉相反。

写反的后果很隐蔽——目录里明明有文件，却静默得到空列表。

### 3. 函数返回类型不支持 `ptr`

形参可以是 `ptr`，但**返回值不行**。返回地址时用 `i64`：

```mo
fn str_dup(s: ptr) -> i64 { ... }
```

### 4. 局部数组不要声明在循环体内

墨语言在栈帧里给每个 `let` 分配空间，循环内声明等于每次迭代
多占一份。`let buf: [512] byte = 0;` 放在 `while` 里，
循环几百次就是几百 KB，很容易爆栈。

**做法**：在函数开头声明一次，循环里复用。

### 5. `==` 比 `&` 结合更紧

```mo
if (m / 4096) & 15 == 8 {   # 错：被解析成 (m/4096) & (15 == 8)
```

不报错不崩溃，只是判断永远不成立。加括号。

### 6. 大数组要注意容量

`lib/archive.mo` 单文件 64KB、`lib/dir.mo` 目录缓冲 64KB，
超了会静默截断。`strcat` 不检查目标缓冲区容量，`atoi` 不查溢出。

## 字符串插值 f"..."

```mo
let n: i64 = 7;
print(f"共 {n} 篇\n");
# 等价于：print("共 "); print_i64(n); print(" 篇\n");
```

`{...}` 里可以是任意表达式：`f"a*b = {a * b}"`。

**必须 `import "io.mo"`** —— 展开后的就是 `print` / `print_i64`，
没有它会报 `undefined symbol` 并提示补 import。

### 为什么用 `f` 前缀

普通字符串里的花括号**保持原义** —— `site.mo` 生成的 CSS/HTML 全是
`{`，截断它们会是破坏性变更。只有 `f"` 开头的才插值。
名为 `f` 的函数不受影响（只有紧跟引号的 `f` 才触发）。

### 当前限制

- **只在 `print(...)` 里支持**。墨语言边解析边发射，要把插值结果
  作为"值"返回需要目标缓冲区 + 生命周期管理，改动大得多。
- 插值项按**表达式类型**自动分派：`i64` → `print_i64`，
  字符串（`ptr`）→ `print`。字符串字面量也可直接插值：`f"lit {"x"}"`。
- 不支持 byte 数组（只认 `ptr to byte`）与结构体

### sfmt：插值写入目标缓冲

```mo
let b: [128] byte = 0;
sfmt(&b, f"共 {n} 篇");
# → strcat(&b, "共 "); strcat_i64(&b, n); strcat(&b, " 篇");
```

需要 `import "str.mo"`。可多次调用追加到同一缓冲。

### ptr(v)：把整数当地址

很多库函数（`str_trim`、`str_dup`、`dir_next` …）返回 i64 ——
因为**返回类型不支持 ptr**。于是插值时被判成数字，打印出地址数值。

```mo
let L: i64 = str_trim(&LINE);
sfmt(dst, f"<h2>{ptr(L + 3)}</h2>");     # 不加 ptr() 会打印出数字
```

`examples/site.mo` 的标题渲染已经用上这个组合。

验证：`tools/fstrtest.sh` 把 f-string 的输出与手写 `print`+`print_i64`
**逐字节 diff**，并检查花括号原义与 `f` 标识符不受影响。

## f64（浮点）

```mo
fn area(r: f64) -> f64 { return r * r * 3.14159; }
let x: f64 = 1.5;
print_f64(x);              # 1.500000
fint(x);  f64(3);  fbits(x);   # 转换与取位模式
```

### 设计：值仍在 rax 里，只是装的是位模式

f64 **不放在 xmm 寄存器**。它像整数一样在 rax 里传，只是 rax 里装的是
IEEE754 位模式；运算时才 `movq` 进 xmm，算完再搬回来。

代价是每步浮点运算多两次 movq。换来的是**不与整数通路互相污染** ——
编译器所有值的通路（push/pop、栈顶缓存 rbx、返回值、参数）都是按
"一个 i64"写的，改成 xmm 要动的地方太多，且一旦交错出错极难排查。

### 字面量：编译期用整数算位模式

编译器自身没有浮点（它是墨语言写的，只有 i64），所以 `"3.14159"`
必须在编译期用**纯整数**算出位模式。

🔴 **不能写 `num << k / den`**：3.14159 按 314159/100000 算，分子要左移
到 2^52 量级 —— 早就溢出 i64，结果全是垃圾，而且**看起来"差不多对"**。

正确做法是**模拟长除法逐位生成尾数**：每次只把余数乘 2，
余数始终 < den ≤ 10^8，乘 2 后仍远小于 i64 上限。

### 三个真坑

**1. xmm → GP 寄存器必须用 `66 0F 7E`，不是 `66 0F D6`。**
`0F D6` 是 MOVQ xmm→xmm/m64，目标是 GP 寄存器时行为不对
（objdump 显示成 `rex.W movq %xmm0,%xmm0`），rax 根本没被写入。

**2. modrm 写错比指令写错更隐蔽。**
`movq xmm1, rax` 是 `11 001 000` = **C8**，第一版写成 C9（= rcx），
于是 `3.0 - 0.5` 变成 `3.0 - 3.0`。

**3. 🔴 `ucomisd` 只设 ZF/PF/CF，不设 SF/OF。**
所以 `setl`/`setg`（依赖 SF≠OF）**完全无效**，读的是上一条整数指令
残留的标志位。必须换成只看 CF/ZF 的那一族：

| 运算 | 整数 | 浮点（正确） |
|---|---|---|
| `<` | setl (9c) | **setb (92)** |
| `<=` | setle (9e) | **setbe (96)** |
| `>` | setg (9f) | **seta (97)** |
| `>=` | setge (9d) | **setae (93)** |
| `==` / `!=` | sete/setne | 不变 |

症状极隐蔽：`v < 0.0` 对某些值碰巧对、某些值恒假，
于是 `print_f64(-2.5)` 打出 `-2.-500000` 这种莫名其妙的东西。

### 已知限制

- `print_f64` 固定 6 位小数，不做科学计数法
- 不支持 NaN/Inf 的打印
- 字面量最多 8 位小数，整数部分 < 10^10（超出会溢出，宁可拒绝）
- 没有 `sqrt`/`sin` 等数学函数（`lib/math.mo` 里可用定点近似）

# bool 与 enum

## bool —— i64 的具名别名

```mo
let t: bool = true;
let f: bool = false;
fn is_pos(x: i64) -> bool { return x > 0; }
```

**bool 不做独立类型检查**，它和 i64 一样占 8 字节栈槽、一样在 rax 里传。

### 🔴 为什么不是"真布尔类型"

把比较结果的类型从 `ty_int()` 改成 `ty_bool()` 后，`print_i64(1 && 1)` 生成了
错误代码（反汇编：标签 b 落在 `call` 指令中间）。**`R_ETY` 不是纯标签，
它参与"值怎么传递"的决策**。所以 bool 只能是 i64 的具名别名。

## enum —— 具名整型常量

```mo
enum Color { RED = 1; GREEN = 2; BLUE = 3; }
enum Mode  { FAST; SLOW; TURBO; }     # 自动 0, 1, 2 ...
let c: i64 = Color.BLUE;
if m == Mode.FAST { ... }
```

存量代码里满地是 `1`/`2`/`3` 当状态码（lib/json.mo 的 J_TYPE、wavobj.mo 的
错误码），只能翻注释才知道 3 是什么。enum 让它们有名字。

### 三个踩过的坑

1. **地址踩踏**：enum 表第一版放在 `O_SCAL` 之后的"空档"，其实 O_SCAL 是
   一个约 1MB 的大区域，数组落在它内部，冲掉了 scratch → 段错误。
2. **`name_at(i)` 是"取符号 i 的名字"**，不是"取名字表偏移 i 处的字符串"。
   误用后 enum 永远匹配不上。
3. **`intern()` 不查重**，同一个名字 intern 两次得到两个不同偏移 ——
   所以表里存偏移、比较时必须比字符串内容。
4. **计数不要用 gv/sv 槽**：槽区是裸偏移、没有分配器，混着 scratch1/2/3
   和各种名字缓冲区，选哪个都可能踩到别人。全局标量用独立地址最稳。

## 已知限制

- 裸字面量/裸变量直接做 `&&` / `||`（`1 && 1`、`t && true`）会生成错误代码，
  这是**既有缺陷**；真实写法 `(a == b) && (c == d)` 正常。
- enum 不做类型检查，`Color.RED` 与 `Mode.FAST` 都是 i64，可以互相赋值。


### Leaky ReLU（1.71）

```mo
let h: i64 = ad_lrelu(z);        # 标量
let H: i64 = ad_vlrelu(A, n);    # 块级
ad_slope(4096);                  # 负半轴斜率，默认 4096 = 1/16；设 0 即退化为 relu
```

定点下 relu 的死区比浮点宽得多：某个单元的输入一旦恒为负，它就**永远**
收不到梯度。`examples/lrelu_ab.mo` 的 A/B 对照实测死权重 34 → 8。

> 数值梯度自检请配合 `ad_mse` 使用，不要用 `ad_mse_half` —— 后者 loss
> 与梯度差系数 2（1.36 为对齐 nn.mo 约定有意为之），自检必然差 2 倍。
