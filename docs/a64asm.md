# a64asm —— 用墨语言自举的 aarch64 汇编器

## 它和 `cfs-aarch64` 不是一回事

| | 路径 | 产物由谁决定 |
|---|---|---|
| `cfs-aarch64` | 墨语言 → C 源码 → **外部 clang/ld.lld** → ELF | 外部工具链 |
| **本工具** | 墨语言 → **墨语言写的编码器** → aarch64 机器码 → ELF | 墨语言自己 |

第二条路上没有任何 C 编译器、`as`、`ld`。ELF 头的每一个字节，
包括 `e_machine=183`、`e_entry`、程序头的 `p_paddr/p_filesz`，
都是 `examples/a64as.mo` 用 `store8` 写出来的。

汇编器自身由自举编译器 `moc` 编译成 x86-64 ELF，在宿主机上跑：
**读 `.s` → 写 aarch64 ELF**。

## 端到端结果

在 `tools/kern64run.py` 里执行。该模拟器模拟的是**硬件**（一块 CPU +
一个 MMIO UART），下面没有 Linux、没有 libc、没有安卓：

```
MO-A64 BOOT
SUM=5050 OK      ← 循环 + 条件分支
FIB=55 OK        ← bl/ret 递归 + 栈帧
MEM OK           ← str/ldr 写后读回
IMM OK           ← movz 的 imm16 字段位置
```

## 两遍汇编

pass1 完整编码一遍定出 label 地址（其 fixup 丢弃），pass2 再编一遍并回填。

**为什么不采用「pass1 只数指令条数」**：`mov rd, #imm` 这类伪指令按立即数
大小变长，两遍必须走**同一条编码路径**，否则条数算错会让所有 label 偏移
整体错位，而且完全静默。

**所有 label 引用一律登记 fixup，最后统一回填。** 早先 pass2 内联算偏移，
用的是「当时的 `NC`」；而数据段地址要用「最终 `NC`」——两处算法不一致，
`ldaddr` 拿到 `0x40000008` 这种指向代码区的地址，读到的字节是机器码而非
字符串，症状是**程序跑起来但一个字都不输出**。

## 支持的范围

指令：`movz movk mov add sub cmp mul and orr eor lsl ldr str ldrb strb
b bl b.<cond> br ret svc wfi nop`
伪指令：`.text .data .byte .zero .ascii .asciz` 与 `ldaddr`（加载 label 绝对地址）

## 三个真缺陷（都不报错）

### 一、imm12 静默截断

`cmp x0, #5050` 编出 `cmp x0, #954`（5050 & 0xFFF = 954）。
指令完全合法、程序照跑、退出码正常 —— 只是判据永远不成立。

现在越界立即数**响亮报错**；`ld`/`st` 的偏移还额外校验必须是 8 的倍数
（否则会被 `/8` 静默抹成错的字节数）。

### 二、`.ascii` 不加终止 0

GNU `as` 的语义就是不加。五个消息在数据段连成一片，一次 `puts(BOOT)`
把后面的 SUM/FIB/MEM/FAIL 全打印了出来，看起来像"四条自检都通过了"。

已补 `.asciz`（写字符串 + 终止 0），`.ascii` 保持 GNU 语义不变。

### 三、`fib` 的中间结果放在寄存器里

```
mov  x9, x0      ← 内层 fib 会把 x9 改掉
bl   fib
add  x0, x0, x9  ← 拿到的是被覆盖后的值
```

改存栈上（`str x0, [sp, #16]`）。这是源码的调用约定问题，不是汇编器的。

## 变异验证里的一个真发现

M1（把 `movz` 的 imm16 移位从 `*32` 改成 `*16`）**一开始没被捕获**：

源码里 `movz` 只装过 `0` 和 `1`，移位写错后 `mov x1, #1` 变成
`mov x17, #0`；求和循环从 `x1=0` 起步，最终仍然算出 5050 ——
**错误被循环抹平了**。

补了自检四（让立即数值本身参与判据：`movz x28, #0x1234` 与 4660 比较）后
才变红。又是一例「改了代码 ≠ 改到了那条因果链」。

## 判据的四层

| 层 | 抓什么 |
|---|---|
| ELF 头 | 产物根本不是 aarch64 |
| 解码对拍（`tools/a64dis.py`，**独立实现**） | 字段错位、移位写错 |
| 引用完整性 | 分支目标 / `ldaddr` 地址落在镜像内 |
| 端到端执行 | 语义错 |

解码器独立实现是关键：用编码器自己验证自己等于没验证。

## 已知限制

- 指令子集约 20 条；无浮点 / SIMD / 原子操作；无 `adrp`+`lo12` 相对寻址
- 单 `PT_LOAD`（RWX），无重定位、无符号表、无 `.bss`（`.zero` 实写字节）
- 只在 CPU 模拟器里跑过，未经真实硬件
- **`var A: [131072] i64` 会让 `import` 的符号静默消失**：报
  `undefined symbol 'print'`，指向用户代码而非真正原因。阈值在 65536 与
  131072 元素之间，**根因未定位**，本轮靠缩小数组规避
