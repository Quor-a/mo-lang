# seg —— 线段树（Segment Tree）+ 懒标记

`lib/seg.mo` · 测试 `tests/151_seg.mo`（150 项断言）· 变异 `tools/segmut.sh`（6 变异全捕获）

## 概念来源

线段树 + lazy propagation。**没有任何主流语言的标准库收录它** —— C++ 只有非标准的
`__gnu_pbds` / `boost::icl` 旁支，Python / Java / Go / Rust 一律靠第三方或手写。

## 与 Fenwick（v1.148）的分工 —— 本库真正的定位

| | Fenwick | 线段树 |
|---|---|---|
| 运算前提 | **可逆**（有逆元） | 只需**可结合**（半群） |
| 能做 | 加法类 | max / min / gcd 也能 |
| 区间赋值 | 做不到 | 能（覆盖而非叠加） |
| 空间 | O(n) | O(4n) |

Fenwick 靠差分 + 前缀和把区间操作化成两次单点，所以**必须**有逆元。
线段树的每个节点只存"这一段聚合起来的结果"，查询时把若干段合并 —— 只需结合律。

本库同时维护 **sum 与 max** 两个聚合量，就是为了让这条界线可测：
同一棵树、同样的区间更新，sum 走加法、max 走半群。

⇒ 因此判据一律是 `==`，不是"接近"（与四个概率性草图相反）。

## 标记优先级：赋值 > 加法

一个节点上同时挂"赋成 x"和"加上 y"时，两者**不能交换**：

```
set(x) 后 add(y)  ⟹ x+y   （赋值标记跟着 +y）
add(y) 后 set(x)  ⟹ x     （加法标记被清掉）
```

所以 `sg_apply_add` 必须先判 `HS`（是否有赋值标记）再决定往哪儿累加。

## 🔴 M1 变异第一版未被捕获 —— 以及为什么

M1 = `apply_set` 不清掉 `ADD` 标记。**第一版 151 全绿**。

原因不是断言太松，是**完全覆盖的查询根本不触发下推**：

```
radd(1, 8, 5)   → 根挂 ADD=5
rset(1, 8, 7)   → 根挂 SET=7, HS=1（M1 下 ADD=5 被保留）
qsum(1, 8)      → 完全命中根，直接返回 SUM[root] = 56  ✓ 看起来对
qsum(1, 4)      → 部分命中 → push(根) → set(7) 然后 add(5) → 12  ✗
```

只有查**严格子区间**才会 push，push 才会把那个残留的 ADD 叠上去。

修法不是放宽断言，是**补确定性场景**（`tests/151_seg.mo` 第 ③ 段）：
整树 radd → 整树 rset → 查子区间。补上后 M1 立刻 4 项红。

> 教训：随机 200 轮一次都没撞上这个序列 —— **随机样本多 ≠ 覆盖到了**。
> 这与 v1.141（SAM：`SA_NCL=0`，克隆分支从未进入）是同一类问题。

## 实测（`make segtest`）

```
cmps=3128 fails=0 nset=150 maxnode=13 push=8 total=448 max=7
```

- **3128 次**与暴力算法对照，0 处不一致（分阶段：初始化 128、区间加 450、
  区间赋值 450、混合 600，另加收尾全量单点 128）
- `nset=150`：区间赋值确实执行了（非空转守卫）
- `maxnode=13`：n=64 时单次操作最多访问 13 个节点（结构性，O(log n)）
- `push=8`：懒标记确实下推过

## 变异验证（6/6 捕获）

| 变异 | 效果 | 红 |
|---|---|---|
| M1 `apply_set` 不清 ADD | add 后 set 语义错 | 4 |
| M2 `push` 直接返回 | 懒标记永不下推 | 5 |
| M3 `rset` 退化成 `radd` | 区间赋值变区间加 | 11 |
| M4 `qmax` 返回 sum | max 变 sum 别名 | 5 |
| M5 `apply_set` 不改 MAX | max 停在旧值 | 72 |
| M6 pull 时 max 取 sum | max 聚合错 | 1 |

M6 只挂 1 项，冗余度薄 —— 改 `sg_radd` 的 pull 之前应先补断言。

## 断言设计（为什么这么写）

1. **精确性**：`==` 暴力，不是"接近"
2. **半群性**：`max != sum`（否则"维护两个量"是空转）
3. **标记优先级**：确定性场景（见上）
4. **非空转守卫**：`nset > 100`、`SGPUSH > 0`、值有正有负
5. **结构性**：`SGNODES` 上界 40（O(log n)）且下界 4（不是空转）
6. **越界**：一律返回 -1 并置 `SGBAD`，不静默夹紧

## 已知限制

- `n ≤ 256`（`SEG_MAXN`），超出返回 -1 并置 `SGOV`
- 池最多约 8 棵树，超出置 `SGOV`
- 只维护 sum 与 max 两个聚合量，没有 min / gcd
- 不支持删除、不支持合并（`merge`）
- 递归实现，深度 O(log n)（墨语言 `let` 局部变量每帧独立，已实测确认）
- 下标 1-based 闭区间
