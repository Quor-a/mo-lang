# 错误处理：`?` 传播

```mo
fn deep(x: i64) -> i64 {
    if x < 0 { return -7; }
    return x * 3;
}

fn mid(x: i64) -> i64 {
    let v: i64 = deep(x)?;      # deep 返回负数 → 带着 -7 立即返回
    return v + 1;
}

fn top(x: i64) -> i64 {
    let v: i64 = mid(x)?;       # 继续往上抛
    return v + 100;
}
```

`f()?` 等价于手写：

```mo
let t = f();
if t < 0 { return t; }
```

区别是**编译器保证不会忘**。约定：负数表示错误。

一个函数里可以有多个 `?`，它们共用同一个错误出口。

## 为什么这样设计

墨语言没有 AST / IR，边解析边发射。所以没有做 Rust 那种
`Result<T,E>` + 类型驱动的强制检查 —— 那需要类型系统配合泛型。

`?` 是**纯语法展开**，不需要任何类型信息：

```
call f
cmp rax, 0          # 48 83 f8 00
jl  L_err           # 0f 8c rel32
```

函数末尾放 `L_err:` + 标准尾声。所有 `?` 的跳转都指向它。

## 关键细节

**1. 错误标签必须放在 `g_epilogue()` 之前。**

放在之后就成了"跳到 ret 后面"。rax 此时已是错误码，直接走标准尾声即可，
与正常 `return` 共用同一份尾声代码。

**2. `cmp` 不改 rax。**

"检查"和"把值传下去"两件事天然不冲突 —— 这是选 `cmp` 而不是
`test`/`or` 的原因（后者虽然更短，但语义要靠标志位推断，容易出错）。

**3. 函数里用了 `?` 就自动视为有返回值。**

否则 `missing return statement` 会误报（错误路径本身就是一条 return）。

**4. 🔴 新函数不能放在 part2。**

`emit_err_propagate` 要写 `R_ETY`，而 `R_ETY` 声明在 part4。
moc 是两遍（先收集符号），先使用后定义没问题；但 **seed 是单遍的**，
要求变量先声明 —— 第一版放在 part2，seed 直接报
`undefined symbol: R_ETY`，整条自举链断掉。

> 给 compiler.mo 加代码时，凡是引用后面分片才声明的变量，
> 必须把新函数放在**那个变量之后**，否则 seed 过不去。

## 验证：`tests/91_errprop.mo`

7 条断言，其中**错误路径 4 条**：

```
✓ top(10)      = 131      （成功路径，三层穿透）
✓ top(-1)      = -7       （错误从最深层抛出）
✓ multi(2)     = 15       （同一函数多个 ?）
✓ with_local(4) = 1011    （错误出口的栈恢复）
✓ with_local(-2) = -7     （有局部变量时的错误路径）
```

**错误路径必须单独测** —— 只测成功路径的话，`?` 展开成什么都不影响结果。

## 已知限制

- 只在**函数调用**后可用（`f()?`）。`a + b?` 这类不识别
- 约定"负数 = 错误"，不做类型检查 —— 返回 0 或正数一律视为成功
- 没有 `try`/`catch`，没有错误类型，错误信息只能靠约定或全局变量传递
- 语句位置的 `f()?;` 可用，方法调用 `obj.m()?` 未测
