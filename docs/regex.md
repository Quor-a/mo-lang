# lib/regex.mo —— Thompson NFA + Pike VM

## 概念来源

- Ken Thompson 1968：正则 → NFA 的构造
- Rob Pike 1998，《Regular Expression Matching Can Be Simple And Fast》
  （<https://swtch.com/~rsc/regexp/regexp1.html>）

**为什么不用回溯**：Perl / PCRE / Python / Java / JavaScript 的正则都是回溯
实现，最坏情况是指数的 —— 这就是 ReDoS 的成因。Thompson 模拟之所以是
O(n·m)，本质在于**同一轮里每个状态只访问一次**（visited 去重）；回溯没有
这一步，同一状态会被反复访问。

本库同时提供 `rx_bt()`：一个**无记忆化**的回溯匹配器，专门用来做对照。

## 实测：线性 vs 指数

模式 `(a+)+b`，输入是 n 个 `a`（结尾没有 `b`，所以必然不匹配 —— 这正是
回溯最坏情况）：

| n | 4 | 6 | 8 | 10 | 12 | 14 | 16 | 18 | 20 |
|---|---|---|---|---|---|---|---|---|---|
| Thompson | 45 | 65 | 85 | 105 | 125 | 145 | 165 | 185 | 205 |
| 回溯 | 62 | 254 | 1022 | 4094 | 16382 | 65534 | 262142 | 1048574 | >4000000 |

- Thompson：每多 1 个 `a` 增加 10 步 —— **严格线性**
- 回溯：每多 1 个 `a` 乘 2 —— **严格 2^n**

n=18 时相差 5665 倍；n=20 时回溯超出 400 万步预算。

## 支持语法

字面字符、`.`、`*`、`+`、`?`、`|`、`()`、`[]`（含 `a-z` 范围与 `^` 取反）、
`^`、`$`、`\` 转义，以及捕获组。

```
re_exec(pat, txt) -> i64      # 匹配起始，-1 = 不匹配，-2 = 模式编译失败
re_endpos()       -> i64      # 整体匹配结束位置
re_gs(n) / re_ge(n)           # 第 n 个捕获组的起止
re_steps()                    # 本轮 VM 步数（用于复杂度对照）
rx_bt(pat, txt, budget)       # 回溯对照：1 = 匹配 / 0 = 不匹配 / -2 = 超预算
rx_bt_steps()                 # 回溯步数
```

## 设计：为什么不是递归下降

mo **没有前向声明**（符号必须先定义后使用），而正则的文法天然递归
（`alt → concat → atom → alt`）。所以这里用 Thompson 原本的 fragment 栈 +
顺序生成：所有 frag 的出口都是"自然落到下一条指令"，只有两处需要回填：

- `AL`：分支末尾 `jmp` 到本组出口
- `PN`：`split` 的第二分支（下一个分支的入口）

回填位置按分组栈分段存放（后进先出 ⇒ 每层占一段连续区间），不需要链表。

## 静默缺陷（本轮修掉的，都不报错）

1. **分支出口 `jmp` 跳到 `save` 之后** —— 跳过了捕获结束位置的写入。
   症状：起始位置正确、`re_endpos()` 恒为 -1。
2. **组入口 `save` 排在 frag 之前** —— `a*` 这类带后缀的 frag 入口被跳过，
   于是 `a*` 无法空匹配，只能在有 `a` 的位置起步。
   修法：入口改成 `save` 在前、`jmp` 在后，`jmp` 目标回填为 body 的 frag 起点。
3. **`rx_bt_open` 从 `)` 自身开始扫描** —— 括号匹配 off-by-one，
   嵌套组重复 `(a+)+` 找不到对应的 `(`。
4. **坏模式被静默接受** —— `(a` 少了 `)` 也"编译成功"，只是永不匹配。
   现在 `re_compile` 末尾检查 `ST_SP != 0`，返回 -1 并置 `RX_ERR = 8`。

## 验证

`tests/131_regex.mo`（33 项）。最关键的一条是 **`same-verdict`**：

> 对同一输入，Thompson 与回溯必须给出**一致结论**。

没有它，"回溯步数暴涨"完全可能只是"回溯引擎根本是坏的"。

`make remut`：5 个变异全部被捕获 ——

| 变异 | 红了几项 |
|---|---|
| M1 去掉 visited 去重 | 1 |
| M2 `*` 退化成 `+` | 1 |
| M3 `split` 目标互换（贪婪反转） | 6 |
| M4 字符类取反失效 | 2 |
| M5 坏模式不报错 | 1 |

全部是断言变红，不是崩溃或超时 —— 说明断言真的在参与决策。

## 已知限制

- `rx_bt` 只支持 `.` `* + ?` `|` `()` 与单字符原子（无字符类、无转义），
  只用于步数对照。
- 状态数上限 1024、并发线程 128、捕获组 8 个；超出置 `RX_ERR` 响出来。
- 无 `{m,n}`、无非贪婪 `*?`、无前后向断言。
