# sketch —— Bloom filter 与 Count-Min Sketch

`lib/bloom.mo` 与 `lib/cms.mo`。两者是一组：**同是"用哈希碰撞换空间"，误差方向恰好相反**。
测试 `tests/145_sketch.mo`（27 项断言）。
`tools/sketchtest.sh` 打印实测数字，`tools/sketchmut.sh` 做变异验证。

---

## 一、概念来源

| 成果 | 内容 |
|---|---|
| Bloom 1970 | k 个哈希映射 m 位；查询全 1 则判存在。**只会假阳，永不假阴** |
| Kirsch–Mitzenmacher 2006 | double hashing `h_i = h1 + i·h₂` 与 k 个独立哈希假阳率**渐近相同** |
| Bose et al. 2008 | 理论下界：m/n 固定时假阳率不可能优于 `(1/2)^(m/n·ln2)` |
| Cormode–Muthukrishnan 2005 | d×w 计数器矩阵 + 取 **min**；`â ≥ a`（确定性）且 `â ≤ a + εN`（概率 1−δ） |

**主流语言标准库一个都没有**：
Python→`pybloom`/`pyahocorasick` 旁系、Java→Guava、Go→`bits-and-blooms`、
Redis→`BF.*`/`CMS.*`（Redis 是存储，不是语言标准库）。C/C++ 各家自研。

---

## 二、为什么它和 HLL / LSH 放在一起看

项目里已有四个"随机性换空间"的库，它们**丢的东西不同，因此可验证的性质也不同**：

| 库 | 保留 | 误差性质 |
|---|---|---|
| HDC | 代数结构 | 无（可逆） |
| SDM | 内容寻址 | 概率召回 |
| LSH | 相似度序 | **会漏**（S 曲线） |
| HLL | 只一个基数 \|A\| | 1.04/√m 标准误差 |
| **Bloom** | 成员判定 | **永不假阴**（确定性） |
| **CMS** | 频次 | **永不低估**（确定性） |

Bloom 与 CMS 是这条线上**唯一有确定性断言**的一档 —— 假阴次数 / 低估次数必须
**恰好为 0**，不是"接近 0"。这决定了本测试的判据形状。

## 三、实测（`make sketchtest`）

### Bloom（m=1024，n=200，20000 次查询）

| k | 实测假阳 | 闭式解 `(1−e^(−kn/m))^k` |
|---|---|---|
| 1 | 3504 | 3548 |
| 3 | 1612 | 1743 |
| 4（≈最优） | 1548 | — |

`k* = (m/n)·ln2 ≈ 3.55`。置位数实测 545，理论 `m(1−e^(−kn/m))` = 555。

空 filter 查 2000 次：**假阳 0**（位数组全 0，这是必然不是概率）。
插入 200 个元素后回查：**假阴 0**。

### CMS（w=20，d=4，50 个 key，N=500）

```
keys_overestimated = 39/50   avg_err = 9   max_err = 25   ε·N = 67
```

`w = ⌈e/ε⌉ ⇒ ε = e/20 = 0.1359 ⇒ ε·N = 67`。低估次数 **0**。

## 四、🔴 一个"全绿但一条没验到"的设计错误（本轮最重要）

CMS 的 query 取 **min over d 行**。第一版测试用 `w=200`，结果：

```
avg err 0   max err 0   ← 25 项全绿
```

**因为 min 把碰撞消掉了**：50 个 key 在 200 列里，某行碰撞的 key 在其它行
未必碰撞，取 min 就得到精确值。于是
`under == 0`、`maxerr ≤ ε·N` 全部**平凡成立** —— 断言全过但一条都没验到。

修法不是放宽断言，而是**把 w 取小以逼出碰撞**：`w=20 < 50 个 key` ⟹
每行必然碰撞。现在 39/50 个 key 被高估，上界断言才有意义。

并加了一条**非空转守卫**：
```mo
assert_true("cms collisions actually happen (non-vacuous)", nerr > 0);
```

> 这与 v1.141 SAM 发现的「`SA_NCL=0`，克隆分支从未进入」是同一类问题：
> **样本看着很充分（120 个子串/50 个 key 全枚举），覆盖却是空的。**

## 五、变异验证（`make sketchmut`）

| 变异 | 结果 |
|---|---|
| M1 `bloom_has` 永不判否 | ✅ 4 项红 |
| **M2 去掉 `h₂ \|= 1`** | ❌ **未被捕获**（有充分理由，见下） |
| M3 CMS 取 max 而非 min | ✅ 5 项红 |
| M4 `bloom_new` 不校验 2 的幂 | ✅ 2 项红 |
| M5 `cms_add` 赋 c 而非累加 | ✅ 7 项红 |
| M6 去掉 CMS 退化保护 | ✅ 1 项红 |

### M2 为什么未被捕获（实测推翻了我原先的注释）

原注释写的是"h₂ 偶数 ⟹ k 个位置只落在 m/gcd 个位置 ⟹ 只用了一小部分位数组 ⟹
假阳率远高于公式"。**实测把它改回来了**（m=1024, n=200, k=4，逐样本检查）：

```
h₂ 为偶数的样本       101 / 200
k=4 个位置出现重复      0
h₂ ≡ 0 (mod 1024)     0 / 200
```

**k ≪ m/gcd 时，h₂ 偶不偶数根本不影响位置互异性。** `|1` 唯一的作用是排除
`h₂ ≡ 0 (mod m)`（m=2^p 的非零倍数都是偶数，0 也是偶数），概率仅 1/m。
所以它是**廉价的保险，不是性能关键**。注释已从"前提"降级为实测版本。

> 「改了代码却测不出变化」本身是信息 —— 保留 M2 是为了把这件事钉住，
> 而不是为了让脚本看起来 6/6。

### M6 第一版也没被捕获 —— 因为该路径**从未执行**

`cm_h2` 已 `|1` ⟹ h₂ 恒为奇数，而 `h₂ ≡ 0 (mod w)` 要求 h₂ 是 w 的倍数，
**偶数 w 的倍数必为偶数** ⟹ w 为偶数时保护是**死代码**。

实测（key 0..49）：`w=20/22/24` 命中 **0** 次；`w=15` 命中 **4** 次、`w=23` 命中 **4** 次。

修法是挑一个**奇数** w 让路径真被执行，并断言 `CMSDEG > 0`。加上之后 M6 立刻被捕获。

## 六、已知限制（都没静默）

- **Bloom**：m 必须是 2 的幂（否则 `bloom_new` 返回 −1 并置 `BLBAD`，不静默取模）；k ≤ 16；池 8192 字。
- **CMS**：池 16384 字（`cms_new(2048,2)` 一次占 4099）；`cms_w_for` 用 e≈2.71828 的整数近似。
- 两者**都不支持删除**：Bloom 需要 counting variant，CMS 的减法是 Conservative Update 之外的另一套。
- Bloom 的 `|1` 与 CMS 的退化保护，作用范围都比第一版注释声称的小（见上）。
- 哈希是 splitmix64 + 逻辑右移。**不要**换成 `lib/lsh.mo` 的 `lsh_mix` ——
  它用 `a ^ (a >> k)`，算术右移下 bit63 恒为 0（HLL v1.138 已栽过）。
