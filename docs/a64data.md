# 数据段重定位：`.quad` + `.rela.data`（v1.168）

## 补的是什么

v1.166/1.167 的自举工具链只会给**指令**做重定位（`.rela.text`）。
于是 `.data` 里只能放字节和字符串，**放不了地址** —— 也就是说：

- 跨模块的函数指针表（分派表 / 系统调用表 / 驱动表）做不出来；
- 一旦某个模块想引用别的模块里的数据，只能把地址算死在一条指令里。

这一版补上另一半：`.quad sym` 在数据段写 8 个占位字节，并登记一条
`.rela.data`，类型是 AArch64 ELF 的 **`R_AARCH64_ABS64 = 257`**；
链接器按规范把绝对地址写回这 8 个字节。

```
main.s ─┐  a64as -r ─→ *.o ── a64ld ─→ sys.elf ── 裸机模拟器
handlers.s ┘        .rela.data(257)    填 8 字节绝对地址
```

`examples/a64data/main.s` 演示的就是一张**系统调用分派表**：
`jt: .quad h0, h1` —— `h0` 在本模块、`h1` 在另一个模块，
`_start` 用 `ldr x2, [x1]` 取出表项再 `blr x2` 间接调用。

## 顺带补的一个能力缺口

`blr` 指令此前**根本不存在**。数据段里存了地址、却没有间接调用指令，
这个能力等于用不上 —— 这是"特性拼图缺一块"，不是 bug，但不补就演示不出来。

## 实测

裸机（模拟 UART，下面没有 Linux/libc/安卓）：

```
MO-SYS
A
B
SYS OK
```

`SUM = h0() + h1() = 1 + 2`，与预期 3 逐位一致。

### 判据分五层（缺一层就漏掉一整类缺陷）

| 层 | 判据 | 抓的是 |
|---|---|---|
| ① | `.o` 里有 `.rela.data`、类型是规范的 **257** | 用了私有编号 / 根本没产出 |
| ② | **链接前**跳转表那 16 字节必须是 0 | 汇编器自己把地址算死了、压根没走重定位 |
| ③ | **链接后** 8 字节 == 外部独立算出的地址 | 算错但程序照样跑 |
| ④ | 端到端执行 | 地址写进去了但 `blr` 到了别处 |
| ⑤ | 只补 `puts`、仍缺 `h1` 时必须报未定义 | 数据段重定位没参与符号解析 |

③ 的期望值由 Python **独立**按 `BASE + st_value` 算出，不读链接器日志 ——
"链接器说对就对"等于没验证。

## 验证脚本自己先错了两次（都记下来）

**一、类型判据把"元组集合"当成了"类型集合"。**
`set(rd)` 里的元素是整个 `(offset, type)` 元组，两个不同偏移的同类型重定位
是两个元素，于是拼出 `TYPES=257,257`，断言 `== 257` 误报失败。
它只是**让检查变红**，还算诚实；真正危险的是反过来的写法。

**二、负例没隔离。**
直接省掉 `handlers.o`，链接器报的是 `undefined symbol: puts` ——
那是 `.rela.text` 里的未定义符号，**先被撞上，`h1` 根本没机会被检查**。
我一度以为"数据段重定位没参与解析"，其实是判据选错了场景。
改成"只补 `puts`、仍缺 `h1`"之后，`h1` 成了**唯一**的未定义符号，
这条才真正验到数据段重定位确实参加了符号解析。

## 变异 4/4 被捕获

| 变异 | 改坏方式 | 结果 |
|---|---|---|
| M1 | `.quad` 不登记重定位（`NDF` 不增） | 失败 8 项 |
| M2 | ABS64 写偏 8 字节 | 失败 8 项 |
| M3 | 只写 4 字节（低 32 位） | 失败 8 项 |
| M4 | `.quad` 只占 4 字节 | 失败 3 项 |

M4 只红 3 项，冗余度比其它三个薄，如实记录。

改段布局时最静默的坑：段数从 7 增到 8 之后，`e_shnum`、`e_shstrndx`、
符号表的 `sh_link`(4→5)、两条 `.rela.*` 的 `sh_link`(4→5) 与 `sh_info`
**必须一起改**；漏掉任何一处，产物仍然编得出来、链得起来，只是读错段。

## 已知限制

- **没有 `.bss`**：零初始化数据仍得用 `.zero` 占文件字节；
- 没有弱符号、没有 `.a` 归档、没有 GOT/PLT（裸机静态镜像用不上）；
- `.quad` 只接受符号，不接受表达式；
- 最多 8 个输入、每条 `.rela.data` 只支持 `ABS64`；
- 只在 CPU 模拟器里跑过，未经真实硬件。

- `tools/a64datamut.sh`：4 个变异，4/4 被捕获
