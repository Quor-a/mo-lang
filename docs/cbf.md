# cbf / cms-cu —— Counting Bloom Filter 与 Conservative Update

补齐 v1.144 明确记下的两条已知限制：

| v1.144 的限制 | 本版 |
|---|---|
| "Bloom 不支持删除" | `lib/cbf.mo`：4-bit 计数器版，支持 `cbf_remove` |
| "CMS 只做了普通 add" | `lib/cms.mo` 追加 `cms_cu_add`（Conservative Update） |
| "CBF 不支持计数器的合并" | `cbf_merge`：**逐格 max**（见第五节） |

测试：`tests/147_cbfcu.mo`（34 项断言）；`tests/148_cbfmerge.mo`（21 项断言）
变异：`tools/cbfcumut.sh`（5 个捕获 / 1 个预期未捕获）；`tools/cbfmergemut.sh`（6 个全捕获）

## 一、概念来源

- **Counting Bloom Filter** — Fan, Cao, Almeida & Broder 2000
  《Summary Cache: A Scalable Wide-Area Web Cache Sharing Protocol》。
  把 Bloom 的 1 bit 换成 4-bit 计数器，于是支持删除。
- **Conservative Update** — Cormode & Muthukrishnan 2005 §3 的同名变体。
  add 时先取 d 行最小值 v，只把低于 `v+c` 的行拉到 `v+c`。

两者都**没有进任何主流语言标准库**：Guava 只有 BloomFilter 没有 counting 版；
Redis 有 `BF.ADD` 没有 counting 版；CU 更是只在论文与少数流处理系统里出现。

## 二、CBF 的代价：两条必须做对、否则假阴的事

Bloom 家族唯一的硬保证是**永不假阴**。CBF 为了换取删除，把这条保证变成了
"需要维护"而不是"结构性成立"：

**① 计数器必须饱和在 15。**
不做饱和，第 16 次插入让 4-bit 回绕成 0（还会向相邻计数器进位）→ query 变假
→ **假阴**。实测：同一元素插入 20 次，做饱和后 `query=1`、`est=15`、
`CBFSAT=15`（20 次插入中后 5 次 × 3 个位置 = 15，完全吻合）。
变异 M1（去掉饱和）→ 2 项断言变红。

**② 只能删确实插入过的元素。**
删一个没插入过的 x，会把 x 那 k 个位置的计数器减 1；若某位置与已插入元素 y
共享且计数为 1，y 就此变成假阴。

这是**受控场景**实测出来的（m=64 小表强制碰撞，不是撞运气）：

```
插入 S={1..8}，回查 fn=0
对 100 个**从未插入**的元素执行 cbf_remove
回查 S → fn = 8        ← 8 个已插入元素**全部**变成假阴
CBFNEG > 0             ← 库自己报告"减到了已经是 0 的计数器"
```

`CBFNEG` 是刻意保留的诊断：这类误删**阻止不住**（即使 x 插入过，它的位也可能
与别人共享），所以只能**显式响出来**，不能悄悄跳过。

`cbf_remove_safe` 只挡得住"完全没插入过"这一种 —— 挡不住假阳导致的误删，
因为 query 为真只说明 k 个位置都 >0，也可能是别人撞出来的。

## 三、实测

| 量 | 实测 | 参照 |
|---|---|---|
| CBF 假阳（m=1024,k=3,n=200, 查 20000） | **1740** | 理论 1743 |
| Bloom 假阳（同参数同集合，对照） | **1740** | 理论 1743 |
| 插入后回查假阴 | **0** | 必须恰好 0 |
| 插 20 次后 `est` | **15** | 饱和上限 |
| 删未插入元素后假阴 | **8 / 8** | 受控场景 |

CBF 的"计数器 > 0"与 Bloom 的"bit = 1"等价 ⟹ 假阳率同量级，
实测 1740 vs 1740 与理论 1743 三方吻合。

### CU 对照（w=20, d=4, 50 key, N=500，同一条插入序列）

| | 误差总和 | 最大误差 | 低估次数 |
|---|---|---|---|
| 普通 CMS | **492** | 26 | **0** |
| CU | **171** | 11 | **0** |

CU 把误差降到约 1/3，且**无低估仍然成立**（不变式"每行 ≥ 真实值"未被破坏 ——
CU 换来的只是更小的高估，不是放宽保证）。

同一批哈希、同一条插入序列，所以差异只可能来自更新策略。

## 四、🔴 同一次 merge，两种策略结论相反

| | merge 后与"直接构造"比对 |
|---|---|
| 普通 CMS | **0 处不同**（加法交换律，确定性） |
| CU | **19 / 50 处不同** |

CU 的"拉到 v+c"依赖**当前状态**，于是
`merge(CU(A), CU(B)) ≠ CU(A ∪ B)` —— **线性性被破坏**。

这是 CU 换误差付出的真金白银：CMS 能分布式聚合的根本原因就是线性，
CU 用掉了它。这不是 bug，是取舍，但必须写明。

## 五、三个实现细节

- **4-bit 字段的读写不需要位取反。** 读用 `(w >> sh) & 15`（算术右移的符号扩展
  被 `& 15` 清掉，对正负数都成立）；写用 `w + (v - old)·2^sh`，一次减法即可，
  绕开墨语言里容易写错的掩码构造。
- **m 必须是 2 的幂且 ≥ 16**，非法参数返回 −1 并置 `CBFBAD`，不静默接受。
- **专用循环变量** `CFI/CFJ/CFW/CFS/CFV/CFB/CFM`，调用方不得占用
  （本项目在 HDC/SDM/LSH/HLL/Bloom 上栽过同一类跟头）。

## 五、三种草图结构、三种合并运算（`tests/148_cbfmerge.mo`）

| 结构 | 状态 | 合并运算 | 代数性质 |
|---|---|---|---|
| Bloom | 位 | **OR** | 幂等（格 join） |
| CBF | 4-bit 计数器 | **max** | 幂等（格 join） |
| CMS | 计数器 | **相加** | **不幂等**（线性） |

幂等与否是**可测的结构性差异**，不是文档声明：

```
cbf_count(merge(A,A)) == cbf_count(A)      # 相等
cms_total(merge(C,C)) == 2 × cms_total(C)  # 翻倍
```

### 🔴 最反直觉的一条：整字 max 抓不到，律抓不到

4-bit 计数器打包在 i64 里（一格 4 bit），"逐格 max"与"对整字取 max"
是两种实现。**整字 max 照样满足交换律、结合律、幂等律** —— 格的三条律
对"错误的运算"一样成立。

M1 变异（改回整字 max）实测红了 4 项，**没有一项是那三条律**：

```
FAIL merge == 独立算出的逐格 max: got 168, want 0
FAIL 合并后对 S_A∪S_B 无假阴: got 128, want 0
FAIL fp(merge) == fp(direct): got 213, want 545
FAIL est(merge) >= max(estA, estB): got 131, want 0
```

**只有"与独立算出的逐格 max 逐格比对"和"无假阴"能抓到它。**
只测代数律的测试套件，会把一个引入假阴的 bug 判成全绿。

### 假阳的确定性单调

不是概率，而是逐格蕴含推出的必然：

```
Z(A) ⊆ Z(merge)       ⟹ fp(A) ≤ fp(merge)
Z(merge) ⊆ Z(direct)  （max ≤ sum 逐格）⟹ fp(merge) ≤ fp(direct)
```

实测 `fpA=176 fpB=157 fpM=545 fpD=545`。任何一次运行都必须满足，
所以断言写成 `fpM >= fpA && fpM >= fpB && fpD >= fpM`，而不是"接近"。

参数不一致（m 或 k 不同）时 `cbf_merge` 返回 −1 并置 `CBFBAD`，
**不静默给出半合并的结果**。

## 六、变异验证（`tools/cbfcumut.sh`）

| 变异 | 结果 |
|---|---|
| M1 去掉饱和 | 捕获（rc=2） |
| M2 remove 不检查 v==0（4-bit 回绕成 15） | 捕获（rc=1） |
| M3 query 只看第一个位置 | 捕获（rc=1） |
| M4 CU 退化成普通 add | 捕获（rc=2） |
| M5 位偏移 `*4` 改 `*2` | 捕获（rc=1） |
| M6 CU 的 max 形式改"只更新 == v" | **未捕获（预期）** |

M6 未捕获不是"这条检查没必要"：**c=1 时 `max(T, v+c)` 与"只更新 == v 的行"
数学等价**（值 ≥ v+1 的行本来就不动）。改了代码却没变红，说明那两种写法
不是两条因果链 —— 如实保留在脚本里，不挑掉、不假装通过。

## 七、已知限制

- 计数器 4 bit，上限 15；超过即饱和（`CBFSAT` 计数），不再精确。
- **删除只能"尽力"**：可能引入假阴，库用 `CBFNEG` 响出来但不阻止。
- 计数器 4 bit，上限 15；超过即饱和（`CBFSAT` 计数），不再精确。
- **CBF 的合并是逐格 max**（已实现），但**不支持拆分**（没有 `cbf_split`）。
- CU **破坏线性性**，不能分布式聚合（见第四节）。
- 池固定：`CBFP` 8192 字，最多约 122 个 m=1024 的 filter。
