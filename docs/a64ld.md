# a64ld —— 用墨语言写的 AArch64 链接器

`examples/a64ld.mo`，测试 `tools/a64ldtest.sh`，变异 `tools/a64ldmut.sh`。

## 一、它补的是 a64as -r 的另一半

`a64as -r` 产出 `.o`（ET_REL：机器码 + 符号表 + 重定位表），但里面所有地址**还是占位 0** ——
因为单看一个文件根本不知道它会被放在哪里。a64ld 负责：

1. 把各文件的 `.text` / `.data` 依次拼起来（布局）
2. 把符号名解析成最终地址（一个文件的 UNDEF 在另一个文件里找到定义）
3. 按 AArch64 ELF 规范把每条重定位算出来、写回指令字
4. 写出可执行 ELF（单 PT_LOAD，与 `a64as` 单文件模式同一布局）

于是完整链路是：

```
main.s ┐
lib.s  ├─ a64as -r ─→ *.o ── a64ld ─→ sys.elf ── 裸机模拟器 ─→ 输出
calc.s ┘
```

**全程没有 C 编译器、没有 `as`、没有 `ld`。**

## 二、重定位类型是真规范值，不是私有编号

| 值 | 名称 | 作用于 |
|---|---|---|
| 283 | `R_AARCH64_CALL26` | `bl` |
| 282 | `R_AARCH64_JUMP26` | `b` |
| 280 | `R_AARCH64_CONDBR19` | `b.eq` / `b.le` / … |
| 275 | `R_AARCH64_ADR_PREL_PG_HI21` | `adrp` |
| 277 | `R_AARCH64_ADD_ABS_LO12_NC` | `add rd, rn, #:lo12:` |
| 264–267 | `R_AARCH64_MOVW_UABS_G0..G3` | `movz` / `movk` 四段 |

类型不是汇编时另存的私有编号，而是**按指令字反推**的（`reltype()`）：
编码和类型只有一处真相，改了编码类型自动跟着变，不会出现「编码已改、reloc 还写着旧值」。

代价是：只有真正跑起来才算验证。所以端到端执行是最硬的判据 —— 跨文件 `bl`、
跨段取地址只要有一个算错，程序立刻跑不出预期输出。

## 三、实测

```
a64as -r lib.s   →  9 insns,    0 data bytes
a64as -r calc.s  → 11 insns,    6 data bytes
a64as -r main.s  → 20 insns, 4127 data bytes
a64ld            → 3 inputs, 40 insns, 4133 data bytes, 20 relocs, 14 syms
```

裸机模拟器输出：

```
MO-LD BOOT      ← main 的 adrp/addlo + bl puts（跨模块 CALL26 + 275 + 277）
SUM=5050 OK     ← bl addnum（跨模块）+ cmp + b.ne（同模块 CONDBR19）
CALC            ← bl getmsg，由 calc 模块自己引用**它自己**的 .data
```

## 四、三个真缺陷，都不报错

### ① 共享输入缓冲覆盖了重定位保存的符号名指针

`a64ld` 用一个 `INB` 缓冲依次读每个 `.o`。第一版把重定位里的符号名**存成 INB 内的指针**，
于是读第二个文件时整个缓冲被覆盖，先登记的重定位拿到的成了别的文件的内容。

症状是 `a64ld: undefined symbol: ` 后面跟一个空名字 —— 看不出是缓冲问题。

修法是名字必须复制进 `POOL`。**本项目已在共享临时缓冲上栽过多次，这里是同一模式换了个载体。**

### ② adrp 页偏移恒为 0：测试全绿，却一条都没验到

第一版镜像只有 40 条指令 + 37 字节数据，text 与 data **落在同一页内**，
`adrp` 算出的页偏移恒为 0。于是「页对齐写错」这类变异根本走不到被测路径：
M2（P 不做页对齐）改完代码，测试**照样全绿**。

修法不是放宽判据，而是**造出真场景**：在 `.data` 开头放 `.zero 4096`，
让数据跨到下一页。同时新增一条断言 —— 链接产物里必须存在页偏移非 0 的 `adrp`
（`ADRP_NONZERO >= 1`），把「跨页场景真的进入了」本身钉住。

这与 v1.141 SAM（`SA_NCL=0`，克隆分支一次没走）、v1.144 CMS（`w=200` 太大，
碰撞被 min 抹掉）是同一类问题：**样本充分 ≠ 覆盖充分**。这是本项目第三例。

### ③ 一个"数学恒等"的变异：改了代码，但测不出它是对的

M7（S 不做页对齐）**如预期未被捕获**。原因不是判据瞎，而是两者在数学上等价：

```
S = page*4096 + lo    (lo < 4096)
正确值   ((S & ~0xFFF) - pgp) / 4096 = page_diff
变异值   (S - pgp) / 4096            = page_diff + lo/4096 = page_diff
```

低 12 位被整除抹掉了。所以「改了代码」不等于「改到了那条因果链」——
M7 保留在脚本里并注明，提醒别拿它当有效变异用。

（附带一条：这只在 `S > pgp` 时成立。若符号在指令所在页**之前**，两者会差 1 页；
当前链接器布局是 text 全在前、data 全在后，所以触发不到。）

## 五、变异验证：7 / 7

| 变异 | 结果 |
|---|---|
| M1 不应用 CALL26 | 捕获，2 项红 |
| M2 adrp 的 P 不做页对齐 | 捕获，2 项红 |
| M3 UNDEF 覆盖已定义（破坏顺序无关） | 捕获，2 项红 |
| M4 data 基址误用 text 基址 | 捕获，2 项红 |
| M5 addlo 用 0 代替低 12 位 | 捕获，2 项红 |
| M6 `-r` 模式仍回填 fixup（地址算两次） | 捕获，2 项红 |
| M7 adrp 的 S 不做页对齐 | **数学恒等，如预期未捕获**（见 ③） |

M3 和 M6 各对应一条设计约束：符号解析必须与输入次序无关；
`-r` 模式下 `apply_fixups` **不能**回填（否则链接器再算一遍 = 算两次）。

## 六、已知限制

- 只处理 `.rela.text`（当前汇编器不产生 `.rela.data`），无 `.quad` / 数据段重定位
- 最多 8 个输入、4096 条指令、16 KB data、1024 条重定位、256 个符号
- 不支持 `SHF_TLS` / 动态链接 / 弱符号 / 归档（`.a`）
- 入口固定取 `_start`，没有 `-e`
- 不做符号版本化与 `-z` 类选项

## 七、本轮踩的一个坑（与链接器无关，但症状一样）

改 `a64as.mo` 时用行范围替换，把 `addfix(li, 0);` 一起吞掉了。
症状是 `bl` 的 imm26 全 0 —— **第一条 `bl` 跳到自己**，程序死循环、无任何输出。

这跟「链接器没应用重定位」的表现一模一样，但根因完全不同。
判别方法是直接看产物里有没有 imm26 为 0 的 `bl`（判据「无未回填的 bl」）。
