# a64mmu —— 自举 aarch64 的 **MMU**：隔离由页表说了算

## 为什么必须有这一层

`a64svc`（v1.172）做出了特权级分离，但它的已知限制第一条就写着：

> **没有 MMU**：EL0/EL1 的隔离靠模拟器的约定，不是页表。EL0 仍能读写
> 内核的**内存**（只有 UART 被拦）。

也就是说 "用户碰不到内核" 是**模拟器说不允许**，不是**页表说不允许**。
这一层补上之后，能不能碰由页表描述符的 `AP[2:1]` / `UXN` 决定：用户越界
会真的触发 **data abort**（EC=0x24），内核从 `esr_el1` / `far_el1` 读出
原因和地址。

页表格式是 AArch64 的**规范格式**（4KB granule、T0SZ=25 → 39 位 VA、
L1 → L2 的 2MB block），模拟器的判权限逻辑按 ARM ARM 遍历**同一张表**，
不是"内核和模拟器约好的私有结构"。

```bash
make a64mmutest    # 33 项断言（七层判据）
make a64mmumut     # 6 个变异，6/6 被捕获
```

## 布局（每块 2MB）

| VA | AP | 用途 |
|---|---|---|
| 0x40000000 | 01 | 内核代码/数据 + 用户栈（EL0 可读可写可执行） |
| 0x40200000 | 11 | 只读数据（EL0 可读，写则 abort） |
| 0x40400000 | 00 | 内核私有：内核栈、秘密值、页表（EL0 一律 abort） |
| 0x40600000 | — | **未映射**：EL0 访问是**转换错误**，与权限错误同类不同码 |

内核栈和页表都放在内核私有块里 —— 连内核自己用的东西也只有 EL1 能碰。

## 实测输出

```
MO-MMU
U OK        ← 用户写自己的页并读回
R OK        ← 读只读页，成功
PF1         ← 写只读页被拦（权限错误，块 1）
PF2         ← 读内核私有页被拦
PF2         ← 写内核私有页被拦
TR3         ← 读未映射页（**转换**错误，块 3）
UDONE
DONE
V OK        ← 退出前校验：秘密值 / 只读值 / 用户变量都没被改掉
N4          ← 4 次 abort
```

## 判据的七层

| 层 | 抓的是 |
|---|---|
| ① 汇编+链接产出 | 根本没产出 / 新助记符没被识别 |
| ② 编码真的在产物里 | 助记符静默落到别的分支 |
| ③ capstone 第三方反汇编 | 编码自洽但不符合规范 |
| ④ 逐行输出 | 编码合法但语义错 |
| ⑤ 诊断计数（svc=4 / eret=8） | 走的是别的路径、碰巧也对 |
| ⑥ 退出前校验三处内存 | **拦了但值还是被改掉** |
| ⑦ 反向：关掉 MMU 必须 V BAD | 这些性质其实是程序自己碰巧做到的 |

⑥和⑦是分开的两条，缺一条就漏一整类缺陷：**"被拦了"和"拦了但值还是被
写进去"是两回事**。所以用户故意往只读页写 `0xBAD`、往秘密值写 `0xDEAD`
（不是写原值）—— 写原值的话，"没拦住"和"拦住了"长得一模一样。

⑦同样重要：关掉 `--mmu` 后输出变成 `U OK / R OK / UDONE / DONE / V BAD`，
**没有一行 PF**。若没有这条反向验证，"隔离生效"可能只是程序自己的功劳。

## 挖出来的六个坑

**一、页表遍历顺序（最有价值）。** 第一版 `mmu_apply` 边走边保护：走到
内核私有块时，把页表所在的页也设成了 `PROT_NONE`，下一次 `rd64` 直接
`UC_ERR_NOMEM`。症状是**用户第一条指令就取不到**，看着像页表建错，其实
是遍历顺序的错。修法：先把整张表走完，再统一施加保护。

**二、在内存钩子里改保护会把模拟器搞崩（段错误）。** 触发越权后必须恢复
内核视图，但在 `UC_HOOK_MEM_*_PROT` 回调里调 `mem_protect` 实测会让
Unicorn 段错误。改成置标志，由**下一条指令执行前的代码钩子**统一恢复 ——
内核第一条指令是 `sub sp, sp, #256`，而内核栈就在被保护的块里，晚一步
就来不及。

**三、`orr` / `and` 只支持寄存器形式。** `orr x9, x13, #3` 报 `bad register`
（不是"立即数越界"，方向完全不对）。改用 `add` 与 `lsl/lsr` 取低位。

**四、`add` 的立即数上限是 4095。** `add x10, x10, #4096` 报
`immediate out of range`。用 2048 累加代替。

**五、`mmu["on"]` 一度不看 `--mmu`。** 内核写 `sctlr_el1` 就把隔离打开了，
于是"关掉 MMU 该看到什么"这条反向验证**无从做起**。

**六、验证脚本自己的假失败。** capstone 核对用 `awk '{print $2}'` 取结果，
而助记符 `dsb sy` 自带空格，字段错位后取到的是助记符本身 —— 明明核对
通过了却报"没核对出"。改用 `$NF`。

## 变异验证 6/6

| | 改坏什么 | 红 |
|---|---|---|
| M1 | 用户自己的块也设成 AP=00 | 10 |
| M2 | 只读块改成可写 | 5 |
| M3 | 内核私有块改成用户可访问 | 5 |
| M4 | 未映射块补上映射 | **1** |
| M5 | 模拟器一律给全权限 | 7 |
| M6 | 不区分转换错误与权限错误 | **1** |

M4 只红 1 项（`TR3` 那一行）：映射补上后其余输出**完全不变**，只有故障
类别从"转换"变成"权限"。M6 同理。改这两处之前应先补断言。

## 已知限制

- **只实现了数据中止**：指令中止（EC=0x20）没做，用户跳进内核代码会直接
  让模拟器报取指错误，而不是陷入内核。
- 模拟器用 `mem_protect` 按页收紧，**不是真 TLB**；页表格式与权限位是
  规范真值，但"翻译"这件事本身没有硬件参与。
- 只支持 4KB granule + L2 的 2MB block；L3 的 4KB 页未测。
- MMIO（UART/GIC/virtio）不参与翻译：内核访问它们是模拟器直接响应。
- 无 ASID、无 TLB 失效指令（`tlbi` 没实现），也无权限升级/降级。
- 用户块与内核块共用 TTBR0，没有 TTBR1 的高半区划分。
- 只在 CPU 模拟器里跑过，**未经真实硬件**。
