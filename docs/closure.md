# 嵌套函数与变量捕获（闭包）

```mo
fn counter(x: i64) -> i64 {
    let n: i64 = 0;
    fn bump() -> i64 {
        n = n + 1;          # n 捕获自外层
        return n + x;       # x 也捕获自外层
    }
    bump();
    bump();
    return bump();          # 13（x=10 时）
}
```

嵌套函数定义在函数体内，可以**读写**外层的局部变量与参数，
多次调用之间状态保持在同一外层栈帧上。

## 实现：就地发射 + 静态链

- **就地发射**：嵌套函数的代码直接发射在外层函数体中间，外层用一条
  `jmp` 跳过去。于是它的入口地址就是外层代码里的某个位置，
  调用它和调用普通函数没有区别。
- **静态链**：被调用时 `[rbp]` 就是调用者的帧指针。v1.130 起支持**任意层**，
  沿静态链走 n 步到达目标外层帧，捕获变量按 `[目标帧rbp + off]` 访问
  （用 r11 做中转）。

## 🔴 三个坑

**1. 槽位冲突 —— `gv(K_FNBASE)` 读出来是垃圾。**

K_ 槽和 `O_SCAL + <字面量>` **共用同一块内存**（`sv/gv` 就是
`store64(heap + O_SCAL + k)`），而 `O_SCAL+700` 已被方法名缓冲占用，
一次 8 字节写会跨到 707。第一版把 K_FNBASE/K_ENCBASE 放在 696/704，
正好被覆盖 —— 读出来是 8216206389 这种值，捕获判定全错。

> 表现：编译正常、运行不崩，只是捕获到的变量被当成"自己的局部变量"
> 去读，值完全不对。这与 1.59.0 的 profiler 槽冲突是同一类错，
> 本项目已经第三次栽在「槽位被别的用途占掉」。

**2. 嵌套的 `parse_func` 会重置函数级状态。**

`parse_func` 会重置 `K_CUROFF`（局部偏移）和 `K_FPATCH`（`sub rsp,N`
的回填位置）。嵌套函数解析完，外层的这两个槽已被改成嵌套函数的 ——
于是外层的 `sub rsp,N` 永远停在占位值 0，**栈帧一个字节都没预留**，
后面的 `push` / `call` 直接把返回地址写到局部变量的槽上。

症状极难归因：外层函数**看起来完全正常**（局部变量偏移是对的），
只是被捕获的变量读出来是返回地址那个数量级的巨大数值。
修法是逐个保存并恢复 K_CUROFF / K_FPATCH / K_HASRET / K_DEPTH /
K_LTOP / K_CRBX / K_CURFN / K_NDF / O_ERRLAB。

**3. 捕获区间必须两端都判。**

只判 `s < K_FNBASE` 不够：全局变量和 `predeclare` 登记的函数下标更小，
会被误判成捕获，生成 `[外层rbp+off]` 去读全局变量 —— 编译不报错、
运行静默出错。必须同时判 `s >= K_ENCBASE`（外层的基线）。

## 深层捕获（v1.130）

一层时 `[rbp]` 就是外层帧；n 层要做 n 次解引用：

```
第 1 步：mov r11, [rbp+0]    = 4C 8B 5D 00
之后每步：mov r11, [r11+0]    = 4D 8B 5B 00
```

`g_walk_static(n)` 发射这 n 条，结果留在 r11。层数由 `cap_depth(s)`
给出：查当前嵌套深度 `O_NEST`，再看符号落在哪一层基线之上。

### 🔴 基线必须存在独立地址，不能放槽里

各层基线存 `O_EBS[depth]`（独立地址，`O_NEST` 紧跟其后 128 字节）。
**第一版读的是 `K_FNBASE` 槽，那是错的**：

`K_` 槽与名字缓冲区共用同一块内存（`sv/gv` 就是 `store64(heap + O_SCAL + k)`），
**槽区没有分配器**。实测两个结构完全相同的程序，只因一个函数叫 `wm`、
另一个叫 `writemid`，后者的 `K_FNBASE` 就被函数名写穿成外层基线 ——
于是中间层的局部变量被误判成捕获，读到外层的值。

> 症状：**值错但不报错**，而且依赖程序里其它名字的长度。
> 本项目已第四次栽在「槽位被别的用途占掉」（1.59 profiler、
> 一次 K_ 槽冲突、以及这次）。相邻的另一处同类数据已一并挪走。

### 🔴 `cap_depth` 的判据要跟着一起改

1.129 的判据是"只可能是一层"，而深层返回的层数是 2 —— 于是深层捕获
**根本没走捕获分支**，被当成普通局部变量读。这也是值错、不报错。

另有一条守卫：`n < 1` 时 `g_walk_static` 不发射任何指令会让 r11 保留
上一次的垃圾值（最难查的一类），所以显式按 1 处理并把错误计数置上。

## 已知限制

- **支持到 8 层**（`O_EBS` 数组长度）。更深会明确报错，不会静默
  按错误的层数解引用
- **不能当回调传出去**：`&bump` 交给 C 的 `qsort` 之类时，调用者不是
  外层函数，静态链就是错的。捕获型嵌套函数只能从直接外层调用
- 不能捕获数组（明确报错）

## 验证

- `tests/95_closure.mo`：一层捕获。读捕获、写捕获、多次调用状态保持、
  嵌套函数内调用普通函数。故意改错期望值会打印
  `FAIL capture local: got 16, want 99`。
- `tests/130_deepclosure.mo`：3~5 层。跨层读写、跨层调用普通函数、
  多次调用状态保持，9 项断言。
- `make deepclosmut`：四个变异（层数封顶为 1、静态链少走一步、
  不做 EBS 入栈、层数从 0 起算）必须全部被捕获。
