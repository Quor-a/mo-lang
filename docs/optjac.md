# 最优 Jacobian 累积（1.86）：顶点消去序

## 概念来源

Griewank & Walther《Evaluating Derivatives》第 8 章；
Naumann, U. (2008) "Optimal Jacobian accumulation is NP-complete"
—— 与稀疏 Cholesky 的 fill-in 最小化等价，**NP-hard**。

两种极端策略：

| 序 | 模式 | 代价 |
|---|---|---|
| 拓扑序（正向消去） | 前向 | ∝ 输入维数 × 运算数 |
| 逆拓扑序（逆向消去） | 反向 | ∝ 输出维数 × 运算数 |
| 其余 | 混合 | 落在两者之间 |

**实践现状**：所有主流框架只实现了两个极端（forward / reverse），
没有任何一个提供混合序。求最优序是 NP-hard，已有实现只有
ADOL-C / ColPack 里的启发式实验代码。

## 模型：顶点消去

计算图 G：顶点 = 块，边 j→i 表示 i 依赖 j。

```
消去顶点 v：
    P = pred(v)，S = succ(v)
    代价 += Σ|P 大小| · Σ|S 大小|
    连边：对每对 (p, s) ∈ P×S 连 p→s；原本不存在的边 = fill-in
    删除 v
总代价 = Σ 各步代价
```

`fill-in` 总数衡量 Jacobian 被稠密化的程度。

## 实测：等宽链（输入维度 ≈ 输出维度）

链结构 `x(大小 m) → a1 → … → ak → y(大小 n)`，只有端点大小可变。

| m | n | k | 前向 | 反向 | 贪心 | 穷举最优 |
|---|---|---|---|---|---|---|
| **8** | **8** | 6 | 104 | 104 | **76** | 76 |
| 4 | 4 | 6 | 36 | 36 | **24** | 24 |
| 8 | 8 | 3 | 80 | 80 | **73** | 73 |
| 8 | 8 | 7 | 112 | 112 | **77** | 77 |
| 16 | 1 | 6 | 96 | **21** | 21 | 21 |
| 1 | 16 | 6 | **21** | 96 | 21 | 21 |

**核心结论**：

- 输入 >> 输出 → 反向最优（21 vs 96）—— 与常识一致
- 输入 << 输出 → 前向最优（21 vs 96）—— 与常识一致
- **输入 ≈ 输出 → 混合序显著优于两端**：104 → **76**（−27%），
  112 → **77**（−31%）

推导（m=n=8，k=6）：

```
拓扑序 = (k-1)·m + m·n = 5·8 + 64 = 104
逆序   = (k-1)·n + m·n = 5·8 + 64 = 104
混合   = 先消 a2..a5（各 1）+ a1（8）+ a6（64）= 4 + 8 + 64 = 76
```

这三个数字在测试里是**硬断言**，不是打印出来看看。

## 贪心 == 穷举最优

小图（可消去顶点 ≤ 7）用字典序排列枚举求精确解。6 个测试图上
**贪心最小代价都恰好等于穷举最优** —— 说明在这个图族上贪心没有损失。

测试里有硬断言 `g < b ⇒ 失败`（贪心不可能优于穷举最优），用来抓
"穷举实现写错"的情况。

## 真实 tape 的验证

6 层 MLP、标量 loss：

```
块数 16    前向 138    反向 48    贪心 58
```

**标量 loss 意味着输出维度 = 1 << 输入维度，反向必须最优** ——
实测确实如此（48 < 138）。这条既是模型自洽性验证，也是一条有用的工程结论：

> 墨语言目前的 AD 只用于标量 loss 的训练，这时反向就是最优策略，
> 混合序没有收益。**混合序的价值出现在求完整 Jacobian（多输出）时。**

## 三个实现细节（都踩过）

**一：一元算子的 `b` 是占位 0，不是槽 0。**

`ad_vsig(a, n)` 内部发 `ad_emit2(OP_VSIG, a, 0, o, n, 0)`。若不加区分，
建图时会把「槽 0」当成操作数，凭空长出一条假边。

修法：在 `ad_emit2` 里集中判定并写入 `AD_TFB[t]`，新增一元算子只改这一处。
**集中在一处**是关键 —— 分散到建图逻辑里迟早会漏。

**二：`ad_wblock` / `ad_newslot` 也要登记块表。**

第一版只改了 `ad_block`，于是权重块的 `AD_BID` 是 -1，所有来自权重的边
都建不起来 —— 表现为「权重顶点没有任何出边」，图看起来是断的。
`ad_newslot`（标量，如 loss）同理，否则识别不出输出块。

**三：连续调用 `oa_run` 必须恢复初始图。**

第一次 `oa_run` 把顶点消完，之后每次调用都没有活跃顶点，
**代价恒为 0**。第一版就是这样 —— 五种序里后四种全打印 0，
差点被读成"混合序零代价"。现在每次 `oa_run` 都从 `OA_ADJ0` 副本恢复。

## 验证

1. **手工验算的绝对值**：104 / 104 / 76，程序输出必须逐位相等
2. **枚举数**：720（6!），确认真的穷举了
3. **三种形态**：输入宽→反向最优；输出宽→前向最优；等宽→混合严格最优
4. **不变量**：最优 ≤ 贪心，且两者都不劣于 min(前向, 反向)
5. **真实 tape**：标量 loss 时反向最优；梯度仍正确（改动不得破坏已有反向）
6. **变异测试**：贪心改成选最大代价 → fail 从 0 变 5

## 限制

- **只做了序搜索与代价评估，没有实现按任意序实际执行累积的引擎** ——
  执行仍走 1.79（反向）/ 1.78（前向）已有路径。顶点消去序理论上对应
  bracketed 累积策略，但那需要矩阵乘法与中间 Jacobian 存储，未实现
- 穷举限制可消去顶点 ≤ 7（7! = 5040）；更多顶点退回启发式
- 顶点数 ≤ 128；块数 ≤ 512
- 块级粒度（顶点 = 块），块内稀疏性不参与计算
