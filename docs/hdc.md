# HDC / VSA —— 超维计算（Binary Spatter Codes）

`lib/hdc.mo` · `tests/123_hdc.mo`（27 项）· `examples/hdcnet.mo` · `tools/hdcmut.sh`

## 一、它为什么算"概念"

不是工程惯例（像有限差分、点积检验那样已被 PyTorch gradcheck 采用），
而是**有完整数学、却躺在论文里没人做进主流工具**的能力。

> "the lack of dedicated general-purpose frameworks for vector-symbolic
>  computing makes it difficult for researchers and developers to experiment
>  with and deploy HDC-based solutions efficiently"
> —— Cumbo & Chicco, *Hyperdimensional computing in biomedical sciences:
> a brief review*, PeerJ Comput. Sci. 2025

同一篇综述还指出该领域**普遍不公开代码**，违反 FAIR 原则——
所以"能复现"本身就是稀缺品。现有的只有 torchhd / pyhdc / hdlib 这类研究库，
**没有主流框架内建**。

谱系：Kanerva 2009（命名 HDC）、Plate 1995（HRR）、Gayler 2003（VSA）、
Kleyko et al. 2022（综述）。

## 二、三条代数要求

| 运算 | 要求 |
|---|---|
| bundling `⊕` | `sim(a⊕b, a) ≫ 0`；交换；`sim(a⊕b, c) ≈ 0` |
| binding `⊗` | `sim(a⊗b, a) ≈ 0`；可逆；`⊗` 对 `⊕` 分配 |

n 个等权分量 bundle 后，对每个分量的相似度约按 `1/√n` 衰减——
这是 bundling 必然有损的原因，也是容量有上界的原因。

## 三、选 BSC，以及相似度口径

向量空间 `{0,1}^D`，binding = **XOR**。

BSC 的独门性质是 **binding 精确自逆**：

```
bind(bind(a, b), b) == a      逐位相等，零误差
```

HRR / FHRR / MAP 都只是**近似**可逆。代价是二值化损失；
好处是 XOR 一条指令 64 位、Hamming = XOR + popcount，
与墨语言的位并行天然契合。

**相似度口径**（极易搞错）：

```
sim = 1 − 2·ham/D ∈ [−1, 1]      ← 本库用这个
cos = 1 − ham/D                  ← {0,1} 向量的真余弦
```

若用余弦，随机向量的相似度是 **0.5** 而不是 0，
所有正交判据全部失效。本库用前者（等价把 `{0,1}` 映到 `{−1,+1}`
后的余弦，也是 HDC 文献通行的"归一化汉明相似度"）。
变异 M3 专门盯着这条。

## 四、bundling：位平面计数器

每个维度一个 CW 位计数器，按**位平面**打包：

```
cnt[b·HDW + j] = 第 b 位平面
```

加一个 `{0,1}` 向量就是行波进位加法器，64 lane 全并行：

```
plane ^= carry ;  carry = old_plane & carry
```

### 实测：宽度 vs 容量（D = 4096）

判据：bundle n 个正交向量后，**每一个**分量与结果的相似度
都仍高于 `3/√D` 才算 n 可行。

| CW | 容量 n | 受什么限制 |
|---|---|---|
| 2 | 0（加 4 个就溢出） | 计数器上限 3 |
| 3 | **7** | `2^3 − 1` |
| 4 | **15** | `2^4 − 1` |
| 5 | 40 | 过渡 |
| 6 | 91 | 接近维度上限 |
| 7 | 95（= golden，也是测试向量数上限） | **维度** |

**两段式非常清楚**：CW ≤ 4 时容量严格等于 `2^CW − 1`（受计数器上限），
CW 足够大之后不再增长，转为受维度限制。

arXiv:1807.08583 图 18a 在 D=10000 下报"5 bit 足以追平 golden"；
本测试 D=4096 实测 6 bit 才追平。**差异来自维度与判据**
（该文用"最大归一化汉明距离"曲线，本测试用"所有分量都过阈值"），
趋势完全一致。数值不同不是矛盾，是口径不同——所以两者都写出来。

## 五、item memory 怎么初始化，决定能表达什么

NeurIPS 2022 (*Understanding HDC for Parallel Single-Pass Learning*) 的核心论点：

> 二值 HDC 的能力上界由**可表达的相似度矩阵**决定，**与维度 D 无关**；
> 而能表达哪些相似度矩阵，取决于超向量怎么初始化。

| 初始化 | `sim(L_i, L_j)` | 能表达的核 |
|---|---|---|
| i.i.d. 随机 | ≈ 0（i≠j） | 只有"相等/不等" |
| CIM 保序 | 随 `\|i−j\|` 下降 | 还有"相近" |

论文处方是随机傅里叶特征（RFF）；本库用 HDC 文献里的等价做法
**CIM**：level 0 随机，此后每级翻转 `D/(2(m−1))` 个不同的位。

实测 `sim(L_0, L_j)`，D=1024、m=16：

```
i.i.d. :  1.000  -0.014  -0.014  -0.014  ...   全是噪声
CIM    :  1.000   0.934   0.875   0.816 ...  0.348   严格单调
```

### A/B：让两种编码彻底分道扬镳

3 类，类心 level = 1 / 7 / 13。训练用 `类心 ± 1`，
测试用 `类心`——**训练与测试的 level 完全不重叠**。

| | 同分布对照（测试 ±1） | 泛化（测试 = 类心） |
|---|---|---|
| i.i.d. | 24 / 24 | **15 / 24** |
| CIM | 24 / 24 | **24 / 24** |

**同分布对照两组都满分**是关键：没有它，就无法区分
"泛化失败"和"压根没学会"。

i.i.d. 的 15/24 高于随机基线 8/24，说明仍有残余泄漏
（部分来自 `hdc_maj` 平局位随机打破引入的偏差）——
未彻底查明，如实记录。

### 抗噪

原型翻转 pct% 位后的泛化准确率（CIM）：

```
10% → 24/24    20% → 24/24    30% → 24/24    40% → 24/24
```

综述 (*Classification using HDC: a review*, 2025) 报的是
"40% 位翻转后性能才急剧下降"。本例任务简单、类间距大，
所以 40% 仍满分——**不能据此说本实现更鲁棒**，只能说没测崩。

## 六、🔴 本轮最大的坑：库内全局临时被嵌套调用抹掉

`_h0.._h8` 是共享临时，被调函数会随手改。凡是**跨调用要保持**的值
（循环变量、跨调用的中间结果）都不能放这里。

```
hdc_im_cim:
    _h0 = HDD / (2*(m-1));        # 每个 level 翻多少位
    while _h1 < m {
        hdc_copy(...)             # ← 内部也用 _h0
        hdc_flip_n(v, _h0);       # ← _h0 已经被抹了
    }
```

症状：**不报错、不崩溃**，只是 CIM 退化成
"只有 level 1 与 level 0 相关，其余全正交"。
实测 `sim(L_0, L_2) = -0.014`（应为 0.87）——
如果只测相邻两级，这个 bug 完全看不见。

修法：新增专用全局 `HDI / HDJ / HDK / HDNF / HDBI / HDBS`，
凡跨调用存活的值一律放这里。受影响的还有
`hdc_im_iid`、`hdc_enc_rec`、`hdc_enc_seq`、`hdc_am`、`hdc_accn`——
它们的循环变量都跨调用存活。

## 七、其它两个坑

**算术右移**：`hdc_perm` 取高 bs 位时 `x >> (64-bs)` 会做符号扩展，
必须与低 bs 位掩码相与；`bs == 0` 时更没有"高 0 位"，
必须单独分支（`1 << 64` 未定义）。

**翻转位数必须去重**：`hdc_flip_n` 用位图保证恰好 k 个**不同**位。
随机取模会重复，实际翻转数少于 k，而抗噪结论依赖"恰好 k 位"。

## 九、限制

- **只做矩阵-向量式的编码与检索**，没有实现 HDC 的 retrain 迭代
  （`hdc_accn` 只是重复累加，未接反馈回路）
- bundling 计数器**非饱和**：超出 `2^CW − 1` 置 `HDOVF` 并显式暴露，
  不静默截断（静默截断会让容量报告看起来正常）
- `HDP` 池 24576 字；`D` 上限受池限制，当前测到 4096
- 只实现 BSC 一族；HRR / FHRR / MAP 均未做
- CIM 的 `sim` 衰减因随机翻转有重叠，实测比理论 `1 − 2|i−j|/(m−1)` 慢，
  单调性成立即可用于序结构

## retrain：整数累加原型（1.109）

### 概念来源

- **OnlineHD**（Hernandez-Cane / Kim / Simic / Nowick / Imani，arXiv:2110.03662）
  首次把 HDC 做成**单遍在线学习**，并给出 retrain 回路：错分样本上
  `A_true += x̃`，`A_pred −= x̃`。
- **AdaptHD**（Imani / Kim / Rosing，DAC 2019）学习率**逐样本自适应**。

两者至今只在 torchhd / hdlib 这类研究库里，没有主流框架内建。

### 与 bundling 的根本区别（不是实现细节）

bundling 的原型是**二值**的（多数投票），±1 的修正会被多数投票直接吞掉。
retrain 的原型必须是**整数累加器** `Σ ±x̃`，所以不能复用 `hdc_maj`。

累加器存成位平面，每个 lane 独立 ±1，行波进位/借位，64 lane 并行：

```
加: new = old ^ ca ;  ca' = old & ca
减: new = old ^ cs ;  cs' = (~old) & cs
```

两个掩码初始互补（x 与 ~x），且 `ca'` 要求 `old=1`、`cs'` 要求 `old=0`，
传播中始终不交 —— 合并成一趟：`new = old ^ (ca|cs)`。

score 的闭式只用 popcount，不需要逐 lane 展开：

```
u_b     = 2·popc(P_b & x) − popc(P_b)
score   = Σ_{b<RCW−1} 2^b·u_b − 2^(RCW−1)·u_{RCW−1}
```

最后一项取负权即补码。`hdc_rt_score_ref` 是逐 lane 展开的慢速参照，
测试要求两者**逐位相等**（含补码负数路径：`+=x` → `D`，再两次 `-=x` → `−D`）。

### 实测（D=1024，NF=4，MM=8，NC=3，噪声 0%）

| 模式 | 在线错误数 | 留出准确率 | 测试最小间隔 | 更新次数 |
|---|---|---|---|---|
| 固定 α=1（OnlineHD） | 16 | 9 / 24 | **−3422** | 63 |
| 固定 α=4 | **6** | 8 / 24 | **−7682** | 83 |
| 不纠正（对照） | 29 | **24 / 24** | **+276** | 48 |

### 三个结论

**一、批式 retrain 在 HDC 上是空转的。**
单遍原型对每个训练样本都含一个自项 `x̃ᵢ·x̃ᵢ = D`，必然压过交叉项，
于是训练集**恒被拟合到 100%**（实测 48/48），没有错分样本可供更新 ——
`HDRU == 样本数`，一个纠正都没发生。retrain 真正有作用的是**在线**场景。

**二、在线纠正换来了在线错误数下降，代价是留出泛化。**
29 → 16 → 6 的同时，留出准确率 24 → 9 → 8，最小间隔 **+276 → −3422 → −7682**。
这三类数字单调对应，不是巧合：错误驱动更新等价于**普通感知机**，
而单遍累加等价于**平均感知机** —— 后者的泛化优势是经典结果。

**三、自适应步长在本任务上退化成 α=1。**
实测更新次数与固定 α=1 完全相同。原因是**在线误判里有相当一部分是平局**：
尚未见过样本的类原型全零、score 恰好为 0，与另一类打平 → `hinge = 0`
→ 自适应给不出更大步长。这是实测到的性质，不是预设；
"按 hinge 缩放步长"在 HDC 的空原型阶段会失效，列为已知限制。

### 已知限制

- 计数按 `mod 2^HDRCW` 回绕，回绕**不报错**、只会让分数悄悄变错。
  已加显式检测：进/借位"入最高位"与"出最高位"不同即置 `HDRVO`。
- 自适应步长的归一化尺度依赖任务，尚无通用处方。
- 只做了矩阵-向量式的逐样本更新，没有 batch 小批量。
