# 实战：用静态站点生成器倒逼完善

版本 1.11.0（2026-10-09）

## 做法

不凭空加功能。写一个**真能用的应用**（`examples/site.mo`，
静态站点生成器），缺什么补什么，撞到什么 bug 修什么。

site.mo 压到六条链路：目录遍历 → front-matter 解析 → Markdown 渲染
→ 按日期排序 → HTML 转义 → RSS 生成。这些用单元测试覆盖不到，
只有真生成一次站点才知道对不对。

## 实战补出来的标准库能力

写之前 `str.mo` 只有 14 个函数。写的过程中缺什么补什么：

| 新增 | 为什么需要 |
|---|---|
| `str_dup` | 往 vec 里存字符串必须拷一份，否则调用方复用缓冲区后内容全变 |
| `str_trim` | front-matter 的 `key: value` 要去首尾空格 |
| `str_starts_with` / `str_ends_with` | 判 `.md` 后缀、判 `---` 分隔 |
| `str_split` | 按行/按分隔符切分 |
| `path_join` | 拼路径，自动处理末尾斜杠 |
| `is_space` | 词法判断 |

## 实战抓出的 bug

**1. 索引顺序根本没排序。**
目录遍历顺序不等于日期顺序，倒着遍历也不等于排序。
实测把 `10-05` 排到了 `10-09` 后面。补了真的插入排序（四个平行 vec 一起换）。

**2. 行内代码渲染丢字。**
`` `a = b` `` 被渲染成 `` `a = ` ``。根因：`strchr` 返回的是
**相对传入起点的下标**，我按绝对位置取字符。

**3. `dir_next` 的 `ty` 形参声明了却从不写入。**
调用方拿不到条目类型，只能靠名字猜。已修。

**4. 导入文件数上限只有 8。**
给 `str.mo` 加两个 import 后，`pty` 用例直接撞上
"too many imported files"。单文件缓冲 1MB→512KB、`O_STRS` 后移腾出
16MB，上限提到 **32**。

**5. 命名冲突。**
`str.mo` 新增的 `is_space` 与 `wc.mo` 自定义的重复定义。
标准库扩张时必然遇到，已让示例改用标准库版本。

## 实战暴露的语言限制（已记入 language.md）

1. 函数**返回类型不支持** `ptr`（形参可以）→ 返回地址用 `i64`
2. 局部数组**不要声明在循环体内**：每个 `let` 占一份栈帧空间，
   512 字节 × 迭代数很容易爆栈
3. `strchr`/`strstr` 返回相对下标，`0` 表示"开头就匹配到"，
   **不是**"没找到"
4. `dir_next` 返回 `1` 表示取到、`0` 表示结束，与常规直觉相反

## 顺带修掉的真实缺陷

`tests/run.sh` 硬编码了绝对路径 `/data/workspace/mo/` ——
项目换个位置（比如拷到手机上跑）就整批失败。
改成从脚本自身位置推导。
