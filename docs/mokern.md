# mokern —— 自举内核：内核由墨语言程序直接构造

`examples/mokern.mo` 不是汇编器，是**内核生成器**：内核的每条机器码都由
墨语言程序 emit 出来，ELF 头逐字节写出。中间没有 `.s`、没有 C、没有
`as` / `ld` / `zig` / libc。

## 与既有 a64 系列的差别

| | 源码 | 产物 |
|---|---|---|
| `a64as` | 手写 `.s` | ARM64 ELF（汇编器） |
| `a64mmu` / `a64pkg` | 手写 `.s` 内核 | 裸机系统镜像 |
| **`mokern`** | **墨语言程序** | **裸机内核镜像** |

a64 系列证明了"墨语言写的工具能产出 ARM64 代码"，但那些内核的**源码是
手写汇编**。这一版补上的是：内核本身也是墨语言写出来的。

## 内核做了什么

- `msr sp_el1` / `msr sp_el0`：内核栈与用户栈分开（实测 `ksp=0x40401000`、
  `usp=0x40010000`，都是内核自己设的值，不是模拟器默认值）
- `msr vbar_el1`：装异常向量表（2048 对齐，`VBAR+0x400` = 来自 lower EL
  的同步异常）
- 二级页表 + `ttbr0/tcr/mair/sctlr`：开 MMU
- `eret` 降到 EL0 跑用户任务
- 用户只能 `svc` 陷入；直接读内核私有页 → data abort（EC=0x24）
- data abort 的返回地址 **+4**，否则出错指令原地重来 → 死循环

期望输出：`MO-KERN / U OK / PF2 / DONE`

页表布局（每块 2MB，与 `docs/a64mmu.md` 一致）：

```
0x40000000  AP=01  内核代码/数据/用户栈
0x40200000  AP=01  备用块
0x40400000  AP=00  内核私有：栈、页表（EL0 一律 abort）
```

## 🔴 三个真缺陷，全都不报错

**一、负分支偏移用加法而不是补码。** `b` 的 imm26 是有符号的，
`0x14000000 + (-5)` 会借位把操作码 `000101` 变成 `000100` —— 变成一条
非法指令。真编码是 `0x14000000 | (imm26 & 0x3FFFFFF) = 0x17FFFFFB`。

症状极难归因：**报错说"停机指令"，PC 指向那条 `b`，而 `b` 的目标地址、
目标处的指令全都正确**。看起来像目标页不可执行，实际是跳转指令本身非法。

**二、`adr` 的代码标签与数据标签算法不同，混用会跳到镜像之外。**
代码标签存的是"指令索引+1"，数据标签存的是"数据段字节偏移+1"。混用的
实测结果是 `eret` 后 `PC=0x40000d1c`——**已经超出整个镜像**（代码 3268
字节 + 数据 26 字节）。报错同样只说"停机指令"。

用编号区分（数据标签 ≥ 20）而不是另加一张表，是因为两张表不同步的代价
更高。

**三、`msr` 的底字是 `0xD5000000` 而不是 `0xD5100000`。** 系统寄存器字段
横跨 bit20..5，`L` 在 **bit21**。按 `0xD5100000` 算时 `msr sp_el1, x0`
编成 `0xd5284120`（多出 bit20），真值是 `0xd5184120`。

## 判据六层（`tools/mokerntest.sh`，13 项）

1. 生成器编译并成功产出镜像
2. `e_machine=183`、`e_entry=0x40000000`、`e_phnum=1`
3. 页表 block 写回指令数 = 3
4. 正向执行：四行输出逐行比对
5. **反向**：`--mmu 0` 后 `PF2` 必须消失 —— 没有这条，"隔离生效"可能只是
   程序自己的功劳
6. `ksp` / `usp` / `svc=2` / `eret=3`

## 变异验证（`tools/mokernmut.sh`，5/5 被捕获）

| | 红了几项 |
|---|---|
| M1 data abort 返回地址不 +4 | 3 |
| M2 内核私有块 AP=00→01 | 2 |
| M3 不设 `elr_el1` | 6 |
| M4 UART 地址装错半字 | 6 |
| M5 不建内核私有块描述符 | **1** |

M5 只红 1 项，冗余度薄：它唯一的盯梢就是"正向必须有 PF2"。改 `gen()` 里
页表相关代码前应先补判据。

## 已知限制

- 只在 CPU 模拟器（`tools/kern64run.py`）里跑过，**未经真实硬件**
- 没有中断、没有多任务：`a64irq` 那套是手写 `.s`，这一版还没搬过来
- 模拟器用 `mem_protect` 收紧页权限，**不是真 TLB**
- 内核私有块在 EL1 视图下也受同一套页级保护（模拟器局限），真硬件按
  异常级分别判权，没有这个限制
- 用户只有一个任务，没有 `fork` / 调度
