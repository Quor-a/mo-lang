# SDM 序列存储（Kanerva 1988, Ch.8）

## 概念

**是什么**：把序列存进稀疏分布式记忆——`address = a_i`，`content = a_{i+1}`；召回时把**读出直接当作下一个地址**，让链自己走下去。

**为什么算"概念"**：Kanerva 1988 年提出，是 SDM 的经典应用之一，也是它作为情景记忆模型的立身之本。至今只有 `sdmlib`、numpy 演示级实现，**无主流框架内建**。

**它检验什么**：SDM 的读出是**叠加态**（多个模式的加权和），不是精确复制。把它喂回自己当地址，误差会不会累积？这是序列存储能不能用的根本问题。

---

## 实测（D=256，M=512 硬位置，r=112，n=40 项，走 120 步）

| 模式 | 正确步数 | 首次出错 |
|---|---|---|
| mode 0 无清洗（读出直接当下一地址） | 13 / 120 | 第 11 步 |
| mode 1 SDM 自联想清洗（独立 bank） | 9 / 120 | 第 8 步 |
| mode 2 最近邻清洗（显式项表） | **120 / 120** | — |

低负载对照（n=10，100 步）：三种模式**全部 100/100**。没有这个对照，分不清"清洗有效"和"这个负载下本来就崩不了"。

---

## 三个定量结论

### ① 单步准 ≠ 链可用

单步读出与真后继的平均汉明距离只有 **1 / 256**（几乎无损），但连走 10 步就崩。误差轨迹：

```
1  4  4  11  16  49  61  80  77  88  97 ← 第 11 步认错项
```

**"每一步都几乎完美"和"链能用"是两件事。** 只测单步读出质量会得出完全乐观的结论。

### ② SDM 自联想清洗反而加速崩溃

这是本轮最反直觉的结果：**加了清洗，从第 11 步提前到第 8 步崩**。

原因是清洗记忆有自己的吸引域，实测：

| 输入误差 | SDM 清洗后 |
|---|---|
| 0 | 1 |
| 2 | 3 |
| 5 | 2 |
| 8 | 13 |
| 18 | 31 |
| 32 | 30 |
| 54 | 50 |

**输入误差 ≤5 时能吸附，≥8 时反而放大。** 链的误差一旦越过 8 位，清洗就从"纠错"变成"加噪"。

对比最近邻清洗：输入误差 **62 位仍吸附正确**。两者相差一个数量级以上，不是调参问题。

> **激活半径 r 与吸引域是两个不同的量**，本例 r=112 而吸引域仅约 5 位，差 20 倍。r 决定"能不能读到东西"，吸引域决定"读到的是不是精确的项"。混用这两个概念会直接推错结论。

### ③ 分支歧义可用平局位数检测

两条序列共享前缀 `x0→x1`，在 `x1` 后分叉：

| | 平局位 | 到各后继距离 |
|---|---|---|
| 非分支点 x0 | **0** | 0（精确） |
| 分支点 x1 | **108 / 256** | 到 x2 = 55，到 y2 = 53 |

x2 与 y2 在约一半位上不同，那些位的贡献相互抵消 → 平局。

**平局位数从 0 跳到 108，是最干净的检测信号**——它不需要知道正确答案，读一次就知道这个点是歧义的。而"到两个后继几乎等距（55 vs 53）"只能说明都不可信，不能区分"歧义"和"压根没存过"。

## 转移记忆与清洗记忆必须分 bank

把 `a_i→a_{i+1}` 和 `a_i→a_i` 写进**同一组**内容计数器，读 `a_i` 得到两者的叠加，既不是后继也不是自身：

```
单 bank 混合：正确 1 / 40    （对照：分开两组计数器时 13 / 120，且是 120 步）
```

SDM 的"读出"是激活位置计数器的逐维求和，同一位置上的所有写入**无条件叠加**。想让两种记忆共存，只能给它们各自的计数器——硬位置可以共用（地址译码相同），计数器不行。

## 本轮踩到的坑（第一条最值）

### 🔴 循环变量被嵌套调用抹掉 → 死循环，且不报错

`sq_recall` 的 `SQI` 被它自己调用的 `sq_nearest` 当作循环变量用掉，于是 `SQI` 每次被重置到 `n`，`+1` 后仍小于 `steps`，**循环永远走不完**。

最迷惑的地方：**3 步的测试看起来是通过的**。因为 `SQI` 跳到 10 后 `+1 = 11 ≥ 3`，循环正常退出——只是实际只走了 1 步，返回的"正确步数"自然也"对"。

修法是每个函数独占计数器（`SQI` / `SQNI`），并加一条**专门针对它**的断言：

```mo
assert_eq("SQITER == steps（循环变量未被抹掉）", SQITER, STEPS);
```

`SQITER` 是独立于循环变量、逐步自增的计数器。只看"正确步数"永远抓不到这类错误。

> 本项目已第六次栽在"库内共享临时被嵌套调用抹掉"上（HDC 的 `_h0`、CaW、多轮调试器、SDM 第一版、W2C）。文件头写了注释警告，然后我自己又犯了一次——**注释不能替代隔离**。

### 变异脚本自己的还原 bug（1.102 记过，重写时又犯）

`restore()` 里顺手把备份文件删了，于是第二次还原是空操作，M3 变异留在源码里，而脚本照样打印全绿。备份**只在脚本末尾清一次**，并在收尾时核对"变异字符串确实不在源码里"。

### 顺序 if 的级联触发

测吸引域时用一串 `if E == 0 { E = 2; } if E == 2 { E = 5; } ...` 推进，前一个刚赋值后一个立刻命中，一轮跑完全部跳到末尾，只打印出第一行。改成显式传参的 `probe(e)` 才拿到完整曲线。

## 已知限制

- **最近邻清洗用了显式项表**，不是纯内容寻址。它正是 HDC 里 cleanup memory 的标准做法，吸引域由项间距离决定；若坚持"全程内容寻址"，则只能接受 SDM 自联想清洗那条窄吸引域。
- 硬位置全扫描（M=512），更大应换哈希寻址，但半径语义会变近似。
- 内容计数器为 int8 偏移表示，单位置同向写入 >127 次会饱和（显式置 `SDOVF`）。
- 未做"部分线索召回"（从序列中段任一项起步已支持，但从**噪声**中段线索起步未测）。
