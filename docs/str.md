# str —— 字符串成为一等类型

墨语言 v1.118.0。

在此之前字符串不是类型：`let s: ptr = "abc";` 拿到的是「指向字节的指针」，
`s == t` 比的是**地址**。于是两个内容相同、地址不同的字符串判等为假，
只有 `streq()` 能用 —— 一个连 `==` 都不能用的"字符串"，谈不上类型。

## 设计：只加类型标记，不改表示

```
kind 10 = str
值      = 一个指向 NUL 结尾字节的地址，占一个 8 字节槽（与 ptr 逐位相同）
```

改动面因此被压到最小：所有值通路（push/pop、栈顶缓存、参数传递、返回值）
一条都不用动。变的只有**类型标记**，而类型只影响三处决策：

| 决策 | ptr（旧） | str（新） |
|---|---|---|
| `==` / `!=` | 比地址 | **比内容** |
| `s[i]` | 按 1 字节步进 | 同（共用 `elem_size`） |
| 赋值/传参兼容性 | — | 与 i64、ptr 互通（不动旧代码） |

**为什么不做 `{len, ptr}` 胖值**：那样 `len(s)` 是 O(1)，但要动贯穿编译器的
"所有值都是一个 i64" 这条不变式 —— 栈槽、参数传递、返回值、调试信息全得改。
收益是 O(1) 求长，代价是动最核心的通路，性价比不成立。所以本版**没有** O(1) 求长，
求长仍是 `strlen()`（见"已知限制"）。

## `==` 怎么实现的

不走 `strcmp` —— 生成物默认不链 libc，`extern` 符号在裸产物里没有地址，
调用会跳到 0（这是本项目 1.112 记过的坑）。全程内联：

```
    mov dl, [rcx]          # rcx = 左串地址，rax = 右串地址
    cmp [rax], dl
    jne ldiff
    test dl, dl
    je  lsame              # 两端同时到 NUL → 相等
    inc rcx
    inc rax
    jmp lp
```

进入时的寄存器约定与 `g_cmp_set` **完全一致**（rcx=左、rax=右），
所以可以直接顶替它，不引入新的调用约定。

## 三条必须写清楚的边界规则

1. **两侧都是 `str` 才比内容。** 一侧是 `str`、一侧是整数（典型 `s == 0` 判空）
   仍按地址比 —— 那才是想要的语义。
2. **`ptr` 保持地址比较。** 语义变更不能悄悄波及旧代码，`tests/127` 里
   `ptr-addr-cmp` 专门盯着这条。
3. **`str` 是上下文关键字**，只在类型位置生效，不占用标识符空间。
   做成真关键字会破坏已有代码里名为 `str` 的变量。

## 🔴 本轮最值得记的两个坑

### 一、指向性与取址：`p[0]` 读到指针变量自己的字节

`index_addr` 里区分两种基址：

- 数组变量 → 变量的**地址**就是数组基址（`lea`）
- ptr 变量 → 变量的**值**才是地址（必须 `load`）

`str` 与 ptr 同类，但我第一版只在入口的合法性检查里放行了 kind 10，
**没有在"取基址"这一处放行** —— 于是它落到 `sym_kind == 1` 分支去 `lea` 变量自身。

症状：`p[0]` 期望 104、实得 **216**。不报错、不崩溃，只是值错。
216 正是指针变量槽里的最低字节。

> 判断依据只能是"读到的值是否与独立来源一致"，不能是"程序有没有崩"。

### 二、变异脚本自己会静默失效，而且一次犯了两遍

- **用"已还原"标志跳过还原**：一开始算基线时就把标志置了，
  于是末尾那次还原是空操作，M3 变异**留在源码里**，脚本照样打印 ✓ 全绿。
- **用 grep 变异串核对还原**：`g_cmp_set(0x94); }` 在源码里本来就有两处，
  于是"残留"永远为真 —— 这个检查既是假阳性，又掩盖了上面那条真失败。

改成：**还原每次都拷贝**（幂等），**核对用 `diff` 逐字节比对**。
这与 1.102 修过的是同一类错误，重写脚本时又犯了一次 ——
校验工具本身也必须被校验。

|---|---|
| M1 字面量类型改回 `ptr` | 4 项变红 |
| M2 `==` 退回地址比较 | 5 项变红 |

才说明断言在参与判断。

## 已知限制（都没静默）

- **`len` 不是 O(1)**：表示仍是 C 串，求长走 `strlen()`，O(n)。
- **`+` 拼接是 O(n²)**：1.121 起支持（`lib/scat.mo`，region 生命周期），
  但朴素拼接每次重抄前缀 —— 循环 n 次累计复制 n(n+1)/2 字节，见 `docs/scat.md`。
- **不校验 UTF-8**：`str` 是字节串；UTF-8 校验/解码在 `lib/utf8.mo`。
- **下标不做越界检查**：与 `ptr` 一致（没有长度信息，无从检查）。

## 有意为之的对照保留

`ptr` 的地址比较语义、`lib/str.mo` 里 `streq` / `strcmp` 全部原样保留 ——
它们现在是独立参照：两条实现路径给出一致结论，才都可信。

## 字典序比较（1.119）

`<` `<=` `>` `>=` 现在也按内容比，走**无符号字节**字典序。

### 为什么必须无符号

UTF-8 的多字节码与续接字节都 >= 0x80。当**有符号** char 比，0xE4 = -28，
于是"中" < "a" —— 整个 CJK 区间跑到 ASCII 前面，排序 / 二分查找 / 最值
全部静默错位。C 规定 `strcmp` 按 `unsigned char` 比较，正是这个原因。

### 一条可验证的性质：字节序 == 码点序

`tests/128_strcmp.mo` 用 `lib/utf8.mo` 解出码点再比一次。两条完全独立的通路
（位比较 / 解码）必须给出同样的顺序：

    U+0061 "a"  <  U+007A "z"  <  U+00E9 "é"  <  U+4E2D "中"  <  U+1F600 "😀"

### 变异验证

脚本：`tools/strcmpmut.sh`

| 变异 | 结果 |
|---|---|
| M1 `setb` → `setl`（退回有符号比较） | `cjk-gt-z` / `cjk-gt-a` 等变红 |
| M2 `<` 与 `>` 互换 | 变红 |
| M3 退回地址比较 | 变红 |

### 仍是地址比较的情形（刻意保留）

- 一侧不是 `str`（如 `s < 0`）
- `ptr`（语义不许悄悄波及旧代码）

## 转义序列（1.120）

字符串与字符字面量现在支持 `\xHH`（两位十六进制，大小写皆可）。

### 它是怎么被发现的

1.119 在用 `\x` 构造 UTF-8 用例时，测出来「中 > z」与「中 < a」
**同时为 0**。两个方向都假 —— 否则至少有一个方向会成立 ——
只可能是数据本身不对。顺着查到：`\x` 此前**完全不支持**。

而且它是**静默**的：`\x` 后面的 'x' 不匹配 n/t/r/0，于是落到
"原样输出"分支，输出字符 'x' 自己：

```
"\xe4\xb8\xad"   ->   "xe4xb8xad"   （9 字节，不是 3 字节）
```

不报错、不崩溃，字符串只是安静地变成了另一个。

### 位数不足必须报错

`\xZZ` / `\x4` 现在报 `error: bad \x escape` 并退出。
不能悄悄给个值 —— **静默是这个项目反复出现的最危险模式**：
1.105 字段偏移、1.106 栈上数组基址、1.108 HDC 共享临时、1.110 SWAR 进位，
全是同一个形状。

### 实现

`lex_esc(p)`（`src/compiler.mo`）集中处理，三处调用点共用：
`lex_string` / `lex_fstring` / `lex_char`。此前三处各有一份 14 行的
重复 if-else 链 —— 分散正是"改一处漏两处"的温床。
汇编 seed（`src/asm/lex.s`）同步加了 `.Lesc_x` 与 `.Lch_x`，
两套实现都要认，否则自举链会在其中一级断掉。

### 变异验证

脚本：`tools/escxmut.sh`

| 变异 | 结果 |
|---|---|
| M1 禁用 `\xHH`（落回原样分支） | 抓到 |
| M2 高低位互换 | 抓到 |
| M3 位数不足不报错（静默） | 抓到 |

🔴 M3 第一版**没被抓到**：只删了 `hi` 那一条检查，而 `\xZZ` 两位都非法，
`lo` 那条仍会把它拦住。必须两条都删才真的回到静默状态 ——
**"改了代码"不等于"改到了那条因果链"**。

判据也不止一条：`tests/129` 变红 + 非法用例退出码非 0 + 报错信息存在。
只看测试通过与否，M3 这类"不影响合法输入"的变异会溜过去。

## 拼接（1.121）

`+` 与 `+=` 现在都是**拼接**（此前根本不支持，1.118~1.120 的"已知限制"里记着）。
分配出来的串归 region（`lib/scat.mo`）所有：不单独 free，整批丢弃。

```mo
let a: str = "abc";
let c: str = a + "def";     # "abcdef"，a 不改动
c += "ghi";                 # += 同样是拼接，不是地址相加
```

细节、实测表与五个变异验证见 `docs/scat.md`。这里只记一条最要紧的：

🔴 `+=` 走通用复合赋值就是**地址相加** —— 实测段错误（exit 139）；
而相加结果若恰好落在已映射内存里，会**静默**给出一个偏移后的串，
不报错也不崩。后者才是必须挡住的那种。
