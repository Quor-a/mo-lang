# modb：墨语言自己写的调试器

```bash
./bin/moc prog.mo -g prog.elf
./bin/modb prog.elf -x cmds.txt      # 从文件读命令
./bin/modb prog.elf                  # 交互模式，从标准输入读命令
```

命令行：`b <行号|函数名>`、`r`、`c`、`s`、`bt`、`p <变量名>`、`regs`、`q`。

## 为什么必须自己写

编译器、链接器、包管理器、LSP 都已经是墨语言写的，唯独"调试器"这一环
还依赖外部工具。**`-g` 的调试信息是自家的，能读它的调试器却不是** ——
自包含生态在最后一环是断的。

modb 全程不借 gdb、不借 libc：

| 能力 | 实现 |
|---|---|
| 起停目标进程 | `fork` + `PTRACE_TRACEME` + `execve` |
| 断点 | 在目标地址写 `int3`(0xCC)，命中后恢复原字节、回退 rip、单步、重装 |
| 单步 / 继续 | `PTRACE_SINGLESTEP` / `PTRACE_CONT` |
| 寄存器 | `PTRACE_GETREGS` / `SETREGS` |
| 回溯 | rbp 链 + `.debug_info` 的函数 DIE 反查 |
| 变量 | DWARF 的 `fbreg` 偏移 + 当前 rbp 读内存 |

## 🔴 最大的坑：PEEKDATA 恒失败，而 POKEDATA 生效

实测（同一地址、同一进程）：

```
mem(text)     0x20ec8148e58948cc    ← /proc/<pid>/mem：对（低字节是 int3）
file(text)    0x20ec8148e5894855    ← 文件里的原始字节（push rbp）
ptrace(text)  0x-e                  ← PTRACE_PEEKDATA：-14 (EFAULT)
```

**这是本项目最阴的一类错：写通、读不通。** 断点能下（POKEDATA 生效）、
能命中、程序能继续、能退出 —— 表面上调试器的核心功能完全正常，
只有"读内存"拿到的全是无意义的负值。

第一版用 PEEKDATA 读变量，`p s` 打印出 `-14`，很容易被误读成
"变量没初始化"或"fbreg 偏移算错了"。是拿 `/proc/<pid>/mem` 做对照，
才确认**地址本身没问题、是通道坏了**。

> 判据不是"功能看起来能不能用"，而是"读到的值是否与独立来源一致"。
> 这里 `file(text)` 就是那个独立来源。

现在所有内存读写走 `/proc/<pid>/mem`（tracer 的等效通道，且没有 8 字节
对齐限制），ptrace 只保留控制类请求。`regs` 命令仍然同时打印两条通道，
把这个差异固化成可复现的对照。

## 🔴 行号不再唯一：必须按文件过滤

1.100 起行号表覆盖所有 `import` 进来的库文件。于是**同一个行号在多个文件
里都有意义**：`b 5` 在没有过滤时命中的是 `str.mo` 的第 5 行（`strlen`），
而不是主文件的第 5 行。

症状极具迷惑性：断点确实命中了、函数名也打印出来了（`strlen()`），
只是函数不对 —— 看起来像"DWARF 信息错了"。

修法是 `addr_of_line(ln, fid)` 按文件编号过滤（文件表里 1 = 主文件）。
**变异验证**：去掉过滤 → 3 项断言立即失败。

## 形参的 DWARF DIE（本次补齐）

此前只有 `let` 声明的局部变量有变量 DIE，**形参完全没有登记**。调试器在
被调用函数里 `p a` 会一无所获。

形参用的是**本帧**的槽（参数被复制进自己的栈帧，与局部变量同一套负数
偏移 -8, -16, ...），所以在 `parse_func` 的参数循环里补一次 `dbg_var` 即可。

现在 `b 5; r; p a; p b; p s` 给出 `a = 3 / b = 4 / s = 7`。

## 条件断点

```
b 22 if i == 5
b 22 if i > 7
b 22 if i + 1 == 6
b 22 if sum >= 15
```

条件在**每次到达断点时**求值（不是下断点时），不成立就自动继续，不打扰。
表达式支持：变量名、十进制字面量、负号、`+` `-`、`==` `!=` `<` `<=` `>` `>=`。
变量按 DWARF 查当前作用域（局部 fbreg → 全局绝对地址）。

`stat` 打印三个计数，其中**"条件放过"是核心**：只有它能区分
"断点没跑到"和"跑到了但条件拦住了"。

```
断点命中   1
条件放过   5      ← i=0..4 被放过，i=5 才停
```

### 🔴 坏表达式必须报出来，不能静默当"不成立"

条件写错（未知变量名、缺比较运算符）时 `eval_cond` 置 `EV_ERR`，
调试器打印"条件无法求值"并**停下**。

如果改成静默当不成立，断点看起来就是"没生效"，与"程序没跑到那里"
**完全无法区分** —— 这是本次最想避免的失败模式。

### 单步撞上 int3 不算命中

单步执行 int3 后 rip 指向下一条，`rip - 1` 正好是断点地址。不区分的话，
观察点单步时路过任何断点都会误报"命中"。用 `LASTSTEP` 标记来源。

## 观察点

```
watch sum     观察点: sum = 0
              观察点触发: sum  0 -> 1
```

**软件实现**：单步 + 每步读值，变了就停。代价 O(步数)，受 `MAXW = 200000` 限。

为什么不用硬件调试寄存器（DR0-DR7）：那要往 `user` 区写 debugreg，偏移
写错就是**静默失效** —— 断点照样下、程序照样跑，只是永不触发。软件单步
虽然慢，但必然正确，而且"步数 / 触发"能在测试里直接验证。

作用域外读不到变量时 `VL_OK = 0`，必须跳过而不是当成"值没变" ——
否则观察点永远触发不了。

## 🔴 LASTSTEP 残留：断点会静默跳过一次

`do_cont` 为走过 int3 会先 `step_once()`，而这次单步**不走 `after_stop`**，
`LASTSTEP` 就残留在下一次 `PTRACE_CONT` 上。于是真正的断点命中被误判成
"单步路过"：不打印命中、不检查条件，看起来像断点少生效了一次。

实测：无条件断点第 2 次经过时不报命中。修法是 `step_once()` 之后显式清零。

## 验证

`make modbtest`：12 项，含两项反向验证

`make modtypetest`：类型感知打印的验证（结构体/嵌套/数组/bool/byte/f64
的打印值必须与 DWARF 描述一致，一律按 8 字节整数打的话这些都"有值"、
静态看不出错；含作用域反向验证与变异验证）

- 断点落在 `addv()` 第 5 行；`s = 7`；回溯 `#1` 是 `main()` 第 11 行
- **作用域反向验证**：断点下在 main 的行再 `p s`，必须"找不到"
  —— 否则"找到"可能只是无条件通过
- 不存在的行号必须报错而不是静默
- 单步后 rip 必须变化
- 两条内存通道的差异被固化成断言

## 已知限制

- 只支持 x86-64；`MAXBP = 32` 个断点
- 回溯用 rbp 链，遇到 `-fomit-frame-pointer` 风格的代码会断（墨语言自己
  不会生成这种代码）
- 变量按 8 字节读取打印，byte/f64 暂不按类型格式化
- 观察点是软件单步实现，O(步数)，大程序上很慢；`MAXW` 到顶会报"未改变"
- 条件里不接受裸变量当布尔值（`b 22 if i` 报错，这是刻意的）；
  不支持位运算与函数求值
- `watch` 只在当前进程运行时有效；`c` 继续后不会自动继续观察
- 交互式与脚本模式都把标准输入留给被调试程序（脚本走 `-x`）

## 复合条件（&& || 括号）

文法（优先级靠层次表达，`&&` 比 `||` 紧）：

    or   := and ( "||" and )*
    and  := cmp ( "&&" cmp )*
    cmp  := add [ cmpop add ]
    add  := prim ( ('+'|'-') prim )*
    prim := '-'? ( 数字 | 名字 ) | '(' or ')'

两条不显然的设计：

**不做短路。** 两侧都求值。表达式里只有变量读取、没有副作用，多算一次
不花代价；而短路会把 `i == 0 || zzz == 1` 里的拼写错误吞掉 —— 左侧为真时
右侧根本不求值，断点表现为"条件成立就停"，和"程序没跑到"无法区分。

**"至少一次比较"放在顶层判。** 第一版让每个叶子必须是比较，结果
`(1 == 1)` 全部报"无法求值"：括号组是布尔值，外层再找不到比较运算符。
改成 `EV_NCMP` 计数后在顶层要求"整个条件至少有一次比较"，既保住了
`b 22 if i` 报错，又让 `i == (4 + 1)` 这类括号里的算术能存在。

## 条件断点 / 观察点的验证

`make modcondtest`：36 项

- 条件成立的那一次停住，且变量值真的是条件里的值（`i == 5` → `i = 5`）
- 计数逐位对上：命中 1 / 放过 5
- **反例**：`i == 999` 必须一次都不停，程序正常跑完（55 / 退出码 0）
- 六种运算符与算术各自验一遍
- 复合条件：`&&`、`||`（含 `c` 继续到第二次命中）、括号包裹、
  括号里的算术、多变量
- **优先级**：`i == 5 || i == 7 && sum == 100` 必须命中 1 次
  （若 `||` 更紧则为 0 —— 两个数字能区分开）
- **不做短路**：`i == 0 || zzz == 1` 必须报"条件无法求值"
- 括号不配对必须报错
- 坏表达式必须报"条件无法求值"
- 观察点在 main 与 addv 里都能触发，作用域外必须报找不到

`make modmut2`：变异验证

- M1 条件恒真（`cv = 1`）→ 反例必须失败，实测 25 项变红
- M2 观察点比较反号（`v == WV0`）→ 观察点必须失败，实测 3 项变红
- M3 `||` 忽略左操作数 → 复合条件必须失败，实测 5 项变红

期望值与**基线**比对，不写死项数：测试项数每次新增都会变，写死的话脚本
会一直"抓到变异"，而实际只是在比两个不同的数字。

只看 36 项全过证明不了什么 —— 条件判断压根没参与决策时也可能碰巧成立。


## 类型感知打印（1.103）

`p` 按 DWARF 类型成形，而不是一律按 8 字节整数：

    p p1        → {x = 3, y = 4, bv = 7, in = {v = 5}}
    p p1.in.v   → 5          # 嵌套成员路径
    p arr       → [10, 20, 30, 40]
    p arr[2]    → 30
    p flag      → true       # bool
    p bv        → 7          # byte 按 1 字节
    p fv        → 1.5000     # f64

判据是"打印值必须与 DWARF 描述一致"。此前一律按 8 字节整数打，
byte/bool/f64 全都**看起来有值**，静态看不出错。

### 顺带修掉的两个编译器缺陷

**一：类型 DIE 的递归发射顺序。** 原来写 `db_u32(dbg_ty_emit(x))`，
mo 会**先求值实参**，于是子类型的整个 DIE 被插进本 DIE 中间。只要程序里
有"结构体作参数"或"嵌套结构体"，`.debug_info` 就整体错位，readelf 报
`abbreviation number 101 which does not exist`。改成先发头部、给 ref4
留 4 字节占位、再递归、最后回填。

**二：结构体成员偏移。** byte/bool 字段在结构体里实际占**一个 8 字节槽**，
原来按 `ty_size` 累加（byte 是 1）会让后面所有成员偏移都偏小：`in` 被
算成 @17，实际在 @24，读出来是 `360287970189639680` 这种怪值。

### 三个必须记住的坑

- **全局数据区接近上限时编译器会静默损坏符号表**，报错落在完全无关的
  行（`undefined symbol 'BUF'`，而 BUF 就在上面 130 行）。本轮为类型信息
  新开三个 `[4096]` 数组即触发 —— 改为复用现有数组（byte_size 存 `D_LO`、
  元素数存 `D_MLOC`）。
- **DW_AT_type 的 ref4 基准是 .debug_info 节区起点**（含 11 字节 unit
  header），不是 CU 数据起点，差 11。匹配不上时所有类型都退化成整数。
- **DW_AT_count 是 55，不是 56** —— 56 是 `DW_AT_data_member_location`。

### 已知限制

- `f64` 在墨语言里是 **IEEE754 double**，不是 Q16.16（实测 1.5 的位模式是
  `0x3FF8000000000000`）。按定点解释会得到 `70334384439296.0000`。
- **struct 作为函数参数会段错误**（`fn work(o: S)` 直接 139）。这是既有
  缺陷，与本轮改动无关；DWARF 里这类参数被标成 pointer，与实际的按值
  拷贝也不一致。
- `dwmo -S` 在扫完 bin/moc 后会段错误退出；输出已完整，交叉验证仍成立。
