# 数组字面量与 byte 数组初始化

```mo
var GA: [4] i64 = [10, 20, 30, 40];     # 全局
var GC: [5] i64 = [1, -2, 3];           # 支持负数
var GD: [3] i64 = [7];                  # 元素少于长度 → 补 0
var GB: [8] byte = "hi!";               # byte 数组用字符串初始化

fn main() -> i64 {
    let la: [3] i64 = [7, 8, 9];        # 局部同理
    let lb: [8] byte = "abc";
    return la[0];
}
```

元素必须是**整型常量**（可带负号）。原因：数组初始化发生在声明处，
局部数组在栈上、全局数组在数据段 —— 两者都要在**编译期**把值写出来，
运行时表达式在这里没有可发射的位置。

## 两个真坑

**1. 🔴 读字符串池必须用 `load8`，不能用 `sbyte`。**

```
sbyte(i) = load8(heap + K_SRCBASE + i)    ← 它是"读源码第 i 字节"
```

`sbyte` 的参数是**源码偏移**，不是绝对地址。拿 `heap + O_STRS + off`
当参数传进去，会读到源码区之后几十 MB 处 —— 直接段错误。

这个错误的隐蔽性在于：`sbyte` 和 `load8` 名字都很"读字节"，
而且 `O_STRS` 确实是 `heap +` 开头的地址，看起来完全像能直接传。

**2. 🔴 列表分支下不能再 `next_token`。**

`parse_i64_list` 结束时就停在 `;` 上（它内部的 `expect("]")` 已吃掉 `]`）。
调用方再多走一步会跳过分号，于是 `expect(";")` 读到下一行开头 ——

```
3:1: error: syntax error
```

**报错位置指向下一行**，很容易误判成下一行写错了。

## 验证：`tests/92_arraylit.mo`（15 条断言）

覆盖：正负元素、不足补 0、byte 数组字符串初始化（含 NUL 之后补 0）、
全局与局部两条路径。

## 已知限制

- 元素只能是整型常量，不支持表达式、枚举名、字符字面量
- 不支持嵌套（`[[1,2],[3,4]]`）
- 不支持匿名数组当实参传（`foo([1,2,3])`）—— 需要栈上临时对象与生命周期管理
- 元素上限 512
