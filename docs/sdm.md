# Kanerva 稀疏分布式记忆（SDM）

## 概念来源

Pentti Kanerva, *Sparse Distributed Memory*, MIT Press 1988（NASA Ames 1984 起）。

结构：n 位地址空间（2^n，n=256 已远超宇宙原子数），但**只显式存 M 个随机硬位置**
（M ≪ 2^n）。写与读都作用于"与地址汉明距离 ≤ r"的那批位置：

- 写：激活位置的每维计数器按数据位 ±1
- 读：激活位置的计数器按维求和，符号即读出位

**为什么算"概念"**：1988 年至今只有 sdmlib 等 numpy 演示级实现，**没有主流框架
内建**；2022 年的 CS-SDM 综述指出"缺乏通用框架"，硬件实现集中在 FPGA/VLSI，
软件侧没有可参考的规范实现。

**与 HDC（1.108 的 BSC）的区别**——两者相邻但机制不同：

|  | HDC / BSC | SDM |
|---|---|---|
| 表示 | 向量**就是**符号 | 显式地址空间 + 邻接激活 |
| 运算 | 代数：⊕ bundling、⊗ binding | 读写分离 + 内容计数器 |
| 存储 | 一个原型向量 | M 个位置 × n 维计数器 |

## 内容计数器的表示（关键设计）

每维一个计数器，用 **SWAR** 把 8 个 int8 打包进一个 i64。

直接存补码 int8 会**跨字节借位**：

```
字节 0x00 减 1 → 0xFF 并向相邻字节借位
字节 0xFF 加 1 → 0x00 并向相邻字节进位
```

而 SDM 的计数器恰恰**常年在 0 附近摆动**——这个 bug 会静默发生。
所以本实现用**偏移表示**：存 `count + 128`，0 表现为字节值 `0x80`。
内容区初始化必须是 `0x8080...80`，**不是 0**。

即便如此，加/减仍必须**分开做**。第一版用一个 delta 字、用 `0xFF` 表示 −1：

```
0x80 + 0xFF = 0x17F → 字节结果 0x7F，且进位 1 到相邻字节
```

相邻维的计数器被凭空 +1。不报错、不崩溃，恢复率从 100% 掉到 87%。
分开后 `0x80 + 0x01 = 0x81`、`0x80 − 0x01 = 0x7F`，都不跨字节。

溢出（字节触及 `0x00`/`0xFF`）显式置 `SDOVF`，**绝不静默**。

## 实测

配置：n=256（SDW=4 字），M=512 硬位置，激活半径默认 `SDD/2 − SDD/16 = 112`。

### 激活半径：双向失败，两端原因不同

| r | 激活数 | 现象 |
|---|---|---|
| 64 | **0** | 一个硬位置都激活不了 → 读不出来 |
| 112 | 20 | 正常 |
| 200 | **512**（全部） | 所有模式叠加，不同查询返回**完全相同**的输出 |

r=200 时两次查询的读出结果汉明距离 = **0**，而两个正确答案之间距离 = 115。
这才是"失去区分度"的严格证据。

### 容量曲线

| K（存储模式数） | 平均恢复率 | 逐位完全恢复 |
|---|---|---|
| 4 | **100%** | 4 / 4 |
| 40 | 98% | 6 / 40 |
| 200 | 86% | 0 / 200 |

### 内容寻址（噪声容忍）

地址翻转 32/256 位（12.5%）后查询：平均恢复率 **99%**。

## 一处被实测推翻的预期

原以为 "r 过大 → 读出接近随机（50%）"，实测 **73%**。

正确模型：r 过大时读出 = 全部模式的多数投票，它与**单个**模式的匹配率是

```
0.5 · P(Bin(K−1) > K/2 − 1 | d=1) + 0.5 · P(Bin(K−1) ≤ K/2 − 1 | d=0)
```

K=4 → `0.5·0.5 + 0.5·0.875 = 0.6875`，与实测 73% 在样本波动内一致。
它**随 K 增大才趋向 50%**。

所以"无区分度"的证据必须是"查询间输出距离为 0"，而不是"读出随机"。
测试里这两条断言分开写，各管一件事——否则一条会掩盖另一条。

## 三个坑

1. **硬位置比错了数组**：`sdm_activate` 调 `sdm_ham(a, SDI*SDW)`，比的是向量池
   里同下标的无关向量（硬位置在 `SDLOC`，不在 `SDVP`）。激活数对 r 完全不敏感
   （r=64 与 r=112 都得 1），**不报错**。新增 `sdm_ham_loc`。
2. **SWAR 跨字节进位**：见上。
3. **测试自己的变量被覆盖**：`run_k` 内部复用了全局 `V1`，K=4 的结果被后两次
   调用悄悄覆盖，断言在比两个无意义的数。本项目已在 HDC、CaW、多轮调试器里
   栽过同一类跟头——**跨调用存活的值必须有专属名字**。

## 变异验证（`make sdmmut`）

只跑测试证明"没坏"不够，必须证明**改坏了测试会红**：

| 变异 | 失败项 |
|---|---|
| M1 硬位置比错数组 | 4 |
| M2 SWAR 加减合并（跨字节进位） | 5 |
| M3 内容区初始化为 0 而非 0x80 | 8 |

脚本开工前先验源码干净——上一轮的污染会一路传染：备份备份了污染版本，
于是三次"还原"全都还原成污染版本，脚本却照样打印全绿。

## 已知限制

- 硬位置用**全扫描**（M=512）。M 更大应换哈希/采样寻址，但那时半径语义变近似。
- 内容计数器是 int8（偏移 128），单位置同向写入 >127 次会饱和，已显式置 `SDOVF`。
- 未做序列存储（SDM 的经典应用之一）。
