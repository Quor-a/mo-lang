## 一、AD 正确性是语义问题，不是编译器技巧 —— 已落地

> "you cannot bolt an AD macro onto a standard call-by-value language and
>  call it a day" —— 对 arXiv:2007.05282v2 的解读
> "An op with no rule ... is treated as having zero derivative unless you
>  supply one" —— Tape / Trace / Source Transform 三路径对比

**直击本项目已踩过的坑**：1.39 那轮，`ad_set()` 不记 tape，用它拼装的
多通道池化让卷积层**收不到任何梯度**，而结果**照样 8/8，毫无异常**。

落地：`ad_audit()`（lib/autodiff.mo），检查四类问题：

| 检查 | 说明 |
|---|---|
| tape 中出现未知算子 | backward 无兜底分支，会静默跳过 → 梯度归零 |
| 权重从未进入计算图 | 不会被更新（1.39 正是这个形态） |
| 权重从未收到过非零梯度 | 结构性断裂 |
| 权重/梯度接近 i64 溢出界 | 见下条 |

### 🔴 关键设计：区分「结构性断裂」与「数值饱和」

第一版按"本轮梯度为 0"报，结果一个**已经正确解出 XOR** 的网络稳定报
6 个问题 —— 训练后期 sigmoid 单元饱和，导数≈0，那是**正常数学现象**。

真正的断裂特征是**从头到尾**都没收到过非零梯度。所以用 `AD_AUD_EVER`
记录历史，只有 EVER==0 才算高危；本轮为 0 但历史有过 → 只汇总不计数。

### 它抓到了什么（真实案例）

`examples/adcheck.mo` 用 ±1.5~6.0 量级初始化一个 2-4-1 网络：

```
[!!] 权重槽 4/5/8/9/11/13 从未收到过非零梯度
```

对应 4 个隐藏单元里的 **2 个从初始化起就是死的**，原因：定点 sigmoid 的
导数在 |z| 稍大时查表即为 0。网络靠另外 2 个单元把 XOR 解出来了，
**结果完全正常** —— 不审计根本看不出一半容量是废的。

改成 ±0.5 量级初始化后：`PASS`，XOR 同样解出。

> 这与 1.34 那轮「relu 在定点下死亡」是同一类问题：定点饱和区比浮点窄
> 得多，浮点里还能流动的梯度，在定点里已经归零。

## 二、整数/定点训练已被学界证明可行 —— 印证路线，并给出风险边界

**支撑**（arXiv:2207.08822, *Is Integer Arithmetic Enough for Deep Learning
Training?*）：int8 全整数训练 ResNet18/ImageNet 得 69.25%，浮点基线 69.75%，
差 0.5%；ViT 微调 98.8% vs 99.1%。无需调整超参、无需梯度裁剪。

→ 墨语言走**定点 autodiff** 是有依据的，不是权宜之计。且相对浮点有个被
低估的优势：**定点逐位确定**，梯度检查可用精确值而非容差（1.33 的发现）。

**风险边界**（PocketNN）：纯整数反传的溢出上界随层数**指数增长**
O(2^(e+kw))（e=误差位宽，w=权重位宽，k=距输出的层数）。墨语言用 i64 定点，
位宽大得多，但深层网络仍可能撞界 → `ad_audit()` 里加了 2^62 溢出检测。

另一点：整数没有 NaN/Inf 静默传播，一旦溢出是**可检测的** —— 这是相对
浮点的真实优势，值得写在明处。

## 三、可复现构建与多样双重编译 —— 部分印证，但别高估

> Diverse Double-Compiling：用两个**独立来源**的编译器编译同一源码，
> 产物字节一致则 trusting trust 攻击不成立。（LWN、bootstrappable 社区）

墨语言恰好有两个实现：`seed`（手写 x86-64 汇编）和 `moc`（墨语言写的），
`make boot` 三级一致看起来就是 DDC 的实例化。

**但必须说清楚**：seed 与 moc **同源**（同一作者、同一套设计），不满足
DDC 要求的"独立来源"。它能证明的是"两个实现在当前源码路径上吻合"，
**不能**提供供应链安全保证。真正要达到 DDC，需要第二个由他人独立写的
墨语言编译器 —— 本项目没有。

这条观念的实用收获是另一半：**自举只覆盖被测到的路径**。
1.68 已据此把 seed 补上复合赋值并让 compiler.mo 真的用上它。

## 四、小语言在 AI 时代的对策 —— 已落地（CLAUDE.md）

> "As of 2026, coding agents are strongest in Python and TypeScript...
>  In minor languages hallucinations are frequent... **a small language
>  permits a counter-move: you can hand the agent the entire language
>  specification as context. Keeping a cheat sheet in CLAUDE.md actually
>  works.**"

墨语言有 39 篇文档，让 AI 助手全读代价过高，而它在墨语言上的训练数据
几乎为零。落地：仓库根目录 `CLAUDE.md` —— 一页速查表，重点是**AI 最
容易写错的地方**（不是语法教程，是踩坑清单）。

## 六、把审计接进已有示例 —— 发现新东西，并发现工具自身的 bug

观念落地之后要**回头检验已有代码**，否则工具只在新写的 demo 上有效。
把 `ad_audit()` 接进 nnet2 / cnn_ad / cnn_shift 三个既有神经网络示例，
用 `tools/adaudit.sh` 统一跑。

### 结果

| 示例 | 权重数 | 从未收到非零梯度 | 本轮为 0 但历史有过（饱和） |
|---|---|---|---|
| nnet2（2-4-1 XOR） | 17 | **0** | 1 |
| cnn_ad（8×8 卷积） | 114 | **34** | 44 |
| cnn_shift · CNN | 50 | **16** | 26 |
| cnn_shift · FC | 520 | **104** | 376 |
| adcheck（小初始化） | 17 | **0** | 0 |

### 🔴 审计工具自身的 bug：EVER 采样偏差

第一版把 EVER 的更新放在 `ad_audit()` 里。跑到 cnn_ad 时报出
"卷积核几乎全部从未收到过非零梯度" —— 可它**明明更新了 23/36**。

原因：训练跑了 1600 步，而 audit 只在 epoch 0 / 199 调用两次，EVER 只
采样到那两个瞬间。某个权重在采样那一刻梯度为 0，就被永久判成"从未"。

修法：EVER 改由 `ad_backward()` **每步**维护（`ad_ever_mark()`）。问题数
从 78 降到 34，且分出 44 个"饱和"。

> 这是**验证工具出错**，且它表现为"被测代码有问题"。与 1.42 那轮 ppc64
> 脚本字节序错、把正确产物判成失败，是同一类。
> 教训：验证工具报错时，**先怀疑工具，再怀疑被测对象**。

### 它验证了自己，也发现了新东西

- **SKW 卷积核 13 个**从未收到梯度 —— 与 1.39 文档记载的"23/36 被更新，
  其余 13 个是恒空窗口（dK = gy·input = 0）"**完全吻合**。那是正确行为。
  审计没误判，说明它可信。
- **SFW 全连接 20 个**是真实死权重 —— **此前无人察觉**。成因是 relu 后
  flat 的某些位置恒为 0，于是 dSFW = gy·flat = 0。

### 为什么"问题数 > 0"不判失败

断裂分**合理**（输入恒空）与**不合理**（本该流动却断了）两类，机器分不清。
所以脚本只汇总数量、检查审计确实执行过，判定权留给人 —— 这与
"AD 正确性是语义问题"的立场一致。
