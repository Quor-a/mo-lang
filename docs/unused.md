# unused —— 「写了但从未读」的局部变量检查

```
python3 tools/unused.py --lib     扫 lib/
python3 tools/unused.py --all     扫 lib/ examples/ tests/
python3 tools/unused.py <文件>...  指定文件
```

命中时打印 `文件:行  fn 函数名  变量 'x' 写了 N 次、从未读过`，退出码 1。

## 为什么要查这个

一个变量被赋值却从没被读过，通常只有两种可能：

1. **死代码** —— 留着无害，删掉更清楚；
2. **本该用它却忘了用** —— 一条判断、一次校验、一次打印被漏掉。

第 2 种才是它真正的价值：那种缺陷不报错、不崩溃，只是结果悄悄不对。

v1.151 里它翻出的正是第 2 种。`lib/mopkg.mo` 的 `np = PKG_NN;` 存了递归前的
状态却从没人读 —— 而这半截修复指向的是一个真缺陷：

```
app -> {b, d}，b -> {c1, c2}
tree 修复前：b / c1 / c2 / c2      ← d 丢失、c2 出现两次
tree 修复后：b / c1 / c2 / d
```

文件第 50 行早有注释写着「pkg_closure 里就留着这个隐患」。作者知道、
写了注释，但因为没人读它，也就没人被它拦住 —— **注释没能阻止缺陷，只有
自动检查能**。这和 v1.137 `lib/sdm.mo` 第 335 行那条警告是同一件事第二次发生。

## 判据（刻意收紧，避免噪声淹没）

只报**局部**变量（`let` 声明），且 `写次数 > 0 且 读次数 == 0`。

不算：

- **全局变量** —— 本来就是给别的模块用的；
- **形参**；
- **数组下标写** `buf[0] = 7` —— 读的是 `buf` 的地址，算用过；
- **取址** `&p`；
- **成员名** —— `a.x` 里的 `x` 不是变量。

**声明处本身不算一次读**，必须显式跳过：否则 `let x: i64 = 0;` 中 `x`
后面是 `:`（不是 `=`），会被记成一次读，于是 `读次数 == 0` 永远不成立、
检查恒绿。**第一版就栽在这里 —— 在 lib/ 上跑出「0 命中」不是因为代码干净，
而是判据写错了。** 修完立刻在受控样例上确认：只报该报的那个。

注释与字符串会先被剥掉 —— 否则注释里提到变量名会被当成一次读。

## 豁免

声明行写 `# unused: ok` 即豁免。

⚠ **豁免必须在原始源码上判定**。`strip()` 会把注释整个剥掉，剥完之后再找
`unused: ok` 永远找不着 —— 这是实现时实际踩到的一次失效。

## 与 pkgclosuretest 的分工

| | 管什么 |
|---|---|
| `unused.py` | 静态：哪个变量写了没人读 |
| `pkgclosuretest.sh` | 端到端：依赖树里每个名字恰好出现一次 |

前者指路，后者证伪。v1.151 是前者翻出线索、后者确认并守住。

## 已知限制

- 只在**函数内**做，不做跨函数 / 跨文件分析
- 不区分「死代码」与「本该用却忘了用」—— 工具只负责指路，判断靠人看上下文
- `while` 内联 `let` 与外层同名时按同一函数体统计（可能漏报，不误报）
- 不做「写了但从未读」之外的检查（未使用的函数、未使用的形参都还没做）
